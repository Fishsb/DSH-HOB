# dsh-hob

一个 DeepSeek Harness（`dsh`）插件：在**你**和**另一个开发会话**之间加一层翻译。
它读项目文档、整理你的意图、把意图写成可执行的指令交给开发会话，并维护自己的记录。

它**不改代码、不跑命令**。需要动手的事，它写成步骤交出去。

---

## 1. 前置

| 要求 | 说明 |
|---|---|
| **DeepSeek Harness（`dsh`）** | 本插件对标的是上游的 **`next` 通道**，不是 npm `dist-tags` 里的 `latest`。⚠ 装之前请确认你的 `dsh` 走的是 `next` 通道 |
| **Node.js** | `>= 20` |
| **包管理器** | `pnpm`（`dsh plugin` 子命令把参数转发给 profile 目录下的 pnpm） |
| **一个工作区** | 一个你希望被协助的项目目录（插件把骨架铺进它，账本区建在它**之外**） |

⚠ ⚠ **上游是预发布版**：`next` 通道的相邻版本**可能删 API 且不给弃用窗口**。
本插件依赖的宿主接口在版本之间变过（本项目为此专门保留了一条"依赖同代机检"）。
⇒ 升级 `dsh` 之后**请先跑一次自检**（见 §6），别默认它还能用。

## 2. 安装

⚠ ⚠ **本仓的 `lib/`（编译产物）不入版本库**，所以**必须先构建再装**。跳过这一步装出来是个**空壳包**
（`lib/` 为空 ⇒ 载入时报 `ERR_MODULE_NOT_FOUND`）。

```bash
# ① 取源码
git clone <本仓地址> dsh-hob
cd dsh-hob

# ② 装依赖（含构建工具）
pnpm install          # 或 npm install

# ③ ⚠ 必须先构建：这一步产出 lib/，装的时候真正被加载的就是它
npm run build

# ④ 装进你的 profile（profile 名按你的实际情况换，如 web / headless）
dsh plugin --profile <你的 profile 名> add /绝对路径/到/dsh-hob
#   也可以用 link: 形式（开发时推荐，改完重新 build 即生效）
#   dsh plugin --profile <profile> add link:/绝对路径/到/dsh-hob

# ⑤ 确认装上了（这一步会打印组合后的配置树，能看到本插件的条目即是成功）
dsh --profile <profile> --dump-config | grep dsh-hob
```

⚠ **装插件 = 预设也一起就位**：本包自带两个 patch（插件本体 + 预设声明），
由 `package.json` 的 `dsh.bundle.patch` 统一列入。**不要再把 `preset/` 目录单独加进
`dsh.profile.bundles`** —— 那会让同一个 patch 挂载两次，宿主 loader 会因条目 id 重复而崩。

⚠ 装完**重启一次**（或重载 profile）。首次在某工作区干活时，插件会把骨架（`.hob/` 结构层）
铺进那个工作区；目标已存在则**一个字节都不动**。

## 3. 配置

配置项分两处，**用途不同，别混**：

- **A. 设置面板里的开关**：设置在宿主的插件设置页 → 本插件分区，落盘到 profile 的补丁文件。
- **B. 预设行里的参数**：写在 patch 文件里（`preset/dsh-hob/preset-dsh-hob.patch.yml`），
  ⚠ **改它只能在包内改**（见 §3.2 的注意）。

### 3.1 设置面板可见项（A 组）

| 键 | 默认值 | 一句后果 | 空值 / 取值语义 |
|---|---|---|---|
| `modules.tools` | `true` | 关掉 ⇒ 助手会话的读写记录工具**不存在**（其余模块照常） | 布尔，无空值 |
| `modules.bus` | `true` | 关掉 ⇒ 同实例内的投递能力消失（少两个工具），其余模块照常 | 布尔，无空值 |
| `modules.orch` | `false` | 打开 ⇒ 被派发的会话跑完会**自动唤醒派活方**，即**无人看管时也会继续推进**（会继续消耗 token）。⚠ 缺省关 | 布尔，无空值 |
| `modules.settings` | `true` | 关掉 ⇒ 本插件不再出现在设置页（配置面本身消失） | 布尔，无空值 |
| `modules.interconnect` | `false` | 打开 ⇒ 允许把任务投递给**另一个**实例（地址只能来自 §3.1 的白名单）。⚠ 缺省关 | 布尔，无空值 |
| `spawn.agentPreset` | `""` | 插件建出的新会话用哪个预设 | **空串 = 出厂默认**（标准模式）；⚠ 填成本插件自带的规划侧预设时不会套用它（它只规划、不施工），会退回出厂默认并说明 |
| `spawn.provider` | `""` | 建出会话用哪个模型路由 | **空串 = 用宿主默认模型** |
| `spawn.model` | `""` | 建出会话用哪个模型 | **空串 = 用宿主默认模型** |
| `spawn.reasoningEffort` | `""` | 建出会话的思考档位 | **空串 = 用该模型自身默认档** |
| `permission.level` | `ledger` | 「助手」会话**能读哪些文件**。三档：`ledger`（只读自己的记录与网络）· `project`（另可读工作区 `.md`）· `workspace`（另可读工作区任意文件与图片、可跨文件搜索） | 三选一，无空值。⚠ **任何一档都不能写、不能执行命令、不能组队**；档位只改「读」的范围，不改「写」的边界。改完即生效，不必重启 |
| `skeleton.enabled` | `true` | 首次在某工作区干活时，把骨架铺进那个工作区 | 布尔，无空值。⚠ **只补缺**：目标已存在 ⇒ 一个字节都不动，等于空操作 |
| `interconnectTargets.list` | `[]` | 跨实例投递的**对端白名单**：每行一个，格式 `名字` 或 `名字=<启动器路径>` | ⚠ **空 = 谁都不许投**（不是"不限制"）。拒的时候会**点名**说明不在白名单内，不会静默 |

⚠ 上面这批里 `modules.*` 是**拓扑型**：改了要**重启实例**才生效（宿主语义如此，不是本插件的选择）。
`spawn.*` / `permission.level` / `skeleton.enabled` / `interconnectTargets.list` 是**值型**：改完即生效。

⚠ 本插件的设置页里**每一项都有一句说明**；上面这张表是同一份口径的离线版。

### 3.2 预设行里的参数（B 组）

这些**不在设置页**，写在 patch 里：

| 键 | 默认值 | 一句后果 | 空值语义 |
|---|---|---|---|
| `workspaceRoot` | `""` | 强制指定工作区根（不填就按会话当前目录解析） | **空串 = 按会话 cwd 解析**（推荐留空） |
| `ledgerHome` | `""` | 记录区的父目录。其下每个工作区一个独立子目录 | **空串 = 派生**：`<工作区父目录>/.hob-ledgers/<工作区名>/`。⚠ 该缺省**不含任何本机绝对路径**，换机自动成立 ⇒ **除非你确知在做什么，否则留空** |
| `ledgerRoot` | `""` | 直接指定本工作区的记录目录（覆盖上面的派生） | **空串 = 走 `ledgerHome` 派生** |
| `maxFileBytes` | `65536` | 单个 `.md` 的读取上限；超了会截断并在尾部标注 | 数字，无空值；**调小**会让大文档读不全 |
| `maxWriteBytes` | `262144` | 单个文件的写入上限；超了拒绝写 | 数字，无空值；**调小**会让一次写不完的内容被拒 |
| `enableWrite` | `true` | 关掉 ⇒ 写工具**根本不存在**（退化为只读） | 布尔，无空值 |
| `debugLog` | `false` | 打开 ⇒ 诊断日志**落盘**（有字节上限） | 布尔。⚠ 缺省关：一个只读用途不该有写盘副作用 |
| `debugLogPath` | 未设 | 诊断日志写到哪 | 未设 = `/tmp/dsh-hob-preset-tools.log`。⚠ 只在 `debugLog: true` 时有意义 |

⚠ ⚠ **改 B 组有一个坑**：profile 层写 `- id: preset-dsh-hob` 是**整段替换**（不合并）——
你若只写一项，预设里另外九行工具声明会**一起消失**（助手的工具面会塌掉）。
⇒ 要改 B 组，**改包内的 `preset/dsh-hob/preset-dsh-hob.patch.yml`** 并重新构建，
**不要**在 profile 层覆盖它。

## 4. 已知限制

⚠ **宁可写多，不许写少。** 下面每一条都是"照实说"而不是"以后会好"。

| 限制 | 实况 |
|---|---|
| **跨实例投递当前不可用** | ⛔ **不要说本插件"支持跨实例投递"。** 投递能力**代码里已经有**，但：① 缺省关闭（要显式打开）；② 对端白名单**缺省为空**（空 = 谁都不许投）；③ 缺省启动器路径是**某台机器的实测取值**，换机基本不存在 ⇒ 要真用得**自己配 `名字=<启动器路径>`**，并确认那个路径在你机器上真的存在。否则你会拿到"启动器不存在"的明确拒绝，而不是它悄悄投到别处 |
| **改完代码是否立即生效** | 按 `dsh-hmr` 的实况：**运行中的产物在下次重算时被替换**（不是"改完即生效"）。⚠ **`package.json` 的变更不被检测** —— 改了 `package.json` 必须重启。⚠ **预设那半边替换时不做兼容性检查** —— 旧的会话可能带着新代码跑，出问题时先怀疑这一点 |
| **上游是预发布版** | 本插件对标上游 **`next` 通道**（⛔ 不是 npm 的 `latest`）。⚠ **相邻版本可能删 API 且无弃用窗口**。升级 `dsh` 后请先跑 §6 的自检 |
| **读的范围三档** | 三档显示名：**账本权限**（`ledger`）· **文档权限**（`project`）· **完全权限**（`workspace`）。**「完全权限」的边界句**：工作区里**任何文件都可读**（含代码与图片），但**仍然不能写、不能执行命令、不能组队** —— 三档里都不存在写类与命令类工具。⚠ 这一条最容易被误读：档位只改「读」的范围，**不改「写」的边界** |
| **记录区在工作区之外** | 插件把记录放在 `<记录区父目录>/<工作区名>/`，**不在你的项目目录里**。它不写 `~/.dsh/**`（有显式拒绝路径） |
| **订阅限制** | 只读工具走一条**单调拒**的守卫；写工具走独立的路径白名单。两者都是**机制**，不是"约定"——但上游哪天改了挂载点，机制会**静默失效**（见上面"改完代码是否立即生效"），所以**出问题时先怀疑这一点，别先怀疑文档** |

## 5. 卸载与残留清理

```bash
dsh plugin --profile <profile> remove dsh-hob
```

⚠ **卸载命令不会清掉下面这些**。逐条点名，按需自己删：

| # | 残留 | 位置 | 怎么清 |
|---|---|---|---|
| 1 | **骨架**（铺进每个被协助的工作区） | `<工作区>/.hob/` | `rm -rf <工作区>/.hob/`。⚠ 会连你自己加的模板一起删，先看一眼 |
| 2 | **记录区**（在工作区之外） | `<记录区父目录>/<工作区名>/`（父目录 = 你配的 `ledgerHome`，或派生出的兄弟目录 `.hob-ledgers/`） | ⛔ **别随手删** —— 那是你的项目资料（方案 / 决策 / 上下文 / 归档 / 改前备份）。要清就先搬走 |
| 3 | **profile 依赖** | `<profile>/package.json` 的 `dependencies` 与 `dsh.profile.bundles` | 由上面的 `remove` 处理；若它没清干净，手工删那两处 |
| 4 | **profile 的 id 定向覆盖条目** | `<profile>/cordis.patch.yml` 里 `- id: dsh-hob` 那一段 | **手工删**。⚠ `remove` **不清这一条**。不删的后果：每次启动 stderr 多一行 `patch: entry "dsh-hob" not found`，**不影响启动** |
| 5 | **`node_modules` 里的符号链接**（用 `link:` 装过才会有） | `<profile>/node_modules/dsh-hob` | 随 #3 一起消失；若没有，手工删 |
| 6 | **运行态** | `<记录区父目录>/<工作区名>/runtime/`（含一个自忽略的 `.gitignore`） | 随 #2 一起；它**不进 git**，留着也不污染 |

⚠ 插件**不写** `~/.dsh/**` 下除 profile 配置以外的任何东西（骨架铺装对被禁止的目录有显式拒绝）。

## 6. 判据 / 自检（一条命令）

```bash
npm run check          # 一条命令跑完全部判据，汇总退出码
```

退出码：`0` = 全部通过 · `1` = 至少一族有实际失败 · `2` = 至少一族**没能执行**（基准缺失）。
⚠ **`2` 不代表通过** —— 它表示"这条判据这次没跑起来"，可能缺 `node_modules` / 缺 `lib/` / 缺记录区。

逐族单跑也可以（每族都是 `npm run check:<名字>`）。⚠ 若某一族打的是"未执行"，
它**没有**替你检查任何东西 —— 别把它的输出当成绿灯。

想先知道**哪几族现在跑不了**，跑 `npm run check:preflight`：它只报告缺什么、怎么补，**不跑判据**。

## 7. 目录结构（给贡献者）

```
src/
  index.ts          入口：只做"模块登记"（加模块 = 加一个文件 + 这里加一行）
  config.ts         配置面唯一来源（设置页的字段与说明都从这里生成）
  modules/          宿主半边，一个模块一个文件，各自独立启停
  preset/           预设作用域那一半（工具在这里注册，权限面也在这里）
  server/           落地实现：读写、路径守卫、渲染
  client/           设置面板那半边（浏览器侧）
preset/             预设声明（patch）
scripts/            判据脚本
```

模块之间靠**依赖声明**解耦：依赖不在 ⇒ 该模块不激活，**插件整体照常加载、宿主不报错**。
所以"关掉一个模块只影响它自己"是**结构保证**，不是约定。

⚠ 改完 `src/` 必须 `npm run build`（`lib/` 是产物且不入库）。**改完不 build，跑的还是旧产物** ——
这一类漂移在 `git status` 里**看不见**，`npm run check` 里有一族专门盯它。
