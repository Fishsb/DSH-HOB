### E-174 · ⚠ ⚠ **判"某条判据漏了什么"之前，先确认那个对象在不在它的扫描面里** —— 「漏一个方向」与「从来不在范围内」是两种病，修法完全相反

**现象（实测，2026-10-25 · `archive/2026-10-25-gate-existence`）**：⚠ 作业书说收尾命令表那处漏洞是
「只判一个方向包含，**两侧同时删一行也过**」。我按这个假设去补，**先做了个内存模拟**，结果发现：

```
正本 §4.1 全部命令 = build check:archive … typecheck
模板 §4.1 全部命令 = build check:archive … typecheck
非 check:* 的命令（V/V2/N 三条都扫不到）= build typecheck
```

⇒ ⚠ ⚠ **真相不是"少一个方向"，而是 `build` / `typecheck` 这两条命令
从来就不在 `V` / `N` / `V2` 三条判据的扫描面里** ——
那三条的集合关系**全部建立在 `check:*` 前缀上**（族名从 `package.json` 的 `check:*` 脚本键派生），
⚠ 而 `build` / `typecheck` **不是 `check:*`**。
⇒ 实测（两侧同删 `build`+`typecheck` 之后）：

```
✓ N ✓ 模板镜像（结构行）：… 模板表行集 ⊇ 正本（0 缺行）…
✓ V ✓ 收尾表**不漏族**：`package.json` 的 `check:*` 族 19 个，正本 §4.1 里全部在列…
✓ V2 ✓ 正本 §4.1 没有多出来的族：抽到 19 个，全部都在 `package.json` 的 19 个里…
✓ V2 ✓ 模板 §4.1 没有多出来的族：…
✗ V3 **正本 §4.1 缺必跑命令 2/2 条**（← 仅新增的 V3 报）
```

⚠ ⚠ **两条命令已经从两侧彻底消失，而四条既有 `✓` 一个都没动。**

**根因**：⚠ ⚠ **"扫描面"与"判据逻辑"是两个不同的东西，而判据的输出只暴露后者。**
`V` / `N` / `V2` 的实现**本身没写错**（集合关系判得对），
错的是**它们取的集合里根本不含那两个命令** —— 而这个盲区**在判据全绿时完全看不出来**
（绿 = "我查的那些都对"，⛔ 不是"该查的都查了"）。
⚠ 同族：**`E-156`**（判据算出来是绿的 ≠ 判据真的在跑）·
**`E-160`**（判定行里的清单/数字必须从权威来源派生，手抄的会悄悄少一块覆盖面）·
**`E-142`**（机检的覆盖面会静默缩水）——
本条是同一族在**"我以为漏的是方向，其实漏的是对象"**这个形态上的落地。

⚠ **后果比"少一行表"重得多**：`check:host` / `check:build` 都是**必须在 `build` 之后跑**的
（前者 import 产物、后者拿产物与源比 mtime）⇒ §4.1 少了 `build`，
**照表跑收尾的人永远不会 build** ⇒ **整条收尾链从第一步就断，且没有任何一条判据会红**。

**正确做法**：
① ⚠ ⚠ **看到"某判据漏了一个方向/一条规则"这种描述时，先别信它 —— 先确认那个对象在不在取数面里**；
   ⚠ 手法：把该判据的**扫描正则 / 派生来源**取出来，拿**目标对象**去跑一遍（几行脚本即可），
   ⛔ 不要凭"它应该查过"下结论；
② ⚠ ⚠ **判据的"覆盖面"必须能被单独打印出来**（本仓既有做法：`✓ 覆盖面：` 那一段逐项列取了什么），
   ⚠ 这样"对象不在面内"是**可读的**，⛔ 不是靠人猜；
③ ⚠ ⚠ **补的断言要明确写出"它补的是哪条既有判据的盲区、为什么那几条结构上看不到"** ——
   ⛔ 否则下一个人会以为这是重复劳动，顺手删掉；
④ ⚠ **负向对拍要同时证明"新的会红"和"旧的仍绿"**：后者才是"盲区"的直接证据
   （本仓实测：删掉两行后 V/N/V2 四条 `✓` 一个没动，只有新增的 V3 报）；
⑤ ⚠ **不是 `check:*` 一类的东西，"必须在场"这件事只能人维护一张小表** ——
   那就要把这个代价写在明处（本仓：`V3_REQUIRED` 的注释里写明"加新非 check 命令时须同批加进来"）。
