### E-172 · ⚠ ⚠ **"没有找到 X"这句话本身可能就是假话** —— 取数为 0 时，先分清「真的没有」与「有、但不合格」

**现象（实测，2026-10-20）**：⚠ 重启宿主后，`npm run check:build` 面 ③ 印出
「⚠ 面 ③：**判不出** —— 这一侧也取不到：**没有找到跑着本 checkout 的 `dsh web` 宿主进程**」。
⚠ ⚠ **而宿主明明在跑**（`ps` 实测 pid 26110 / 30214，`curl 127.0.0.1:3080` 通、网页开着）
—— 真相是：那个 profile 的 `dsh.profile.bundles` 里**没有 `dsh-hob`**（06:24 一次写盘丢的，
`dependencies` 里还留着 `link:`），⇒ **插件压根没被装配**，所以"解析出来的不是本 checkout"。

**根因**：⚠ ⚠ **取数函数把"找到了但不合格"的进程 `continue` 掉了**（`runningInstances()` 里
`if (own.notThisPackage !== true) notes.push(...)` 之后直接 `continue`）⇒
⚠ 数组里只剩"合格的那些"，**长度 0 于是渲染成"没有找到"**。
⚠ ⚠ 这是**取数面把两种事实压成一个读数**：① 一个候选都没有；② 有候选、全被筛掉。
⚠ ⚠ 而两句话的**修法完全相反**：① 去查进程有没有起来；② 去查**装配**（bundles / 依赖）。
⚠ ⚠ 同族先例：**E-156**（判据算绿 ≠ 判据在跑）· **E-170**（零输出 + exit=0 是可疑信号）——
本条是同一族在**取数逻辑**里的形态：**"过滤掉的"与"本来就没有的"长得一模一样**。

**正确做法**：
① ⚠ ⚠ **凡"筛完为 0"的取数，必须把"被筛掉的那些"单独带出来**（本仓修法：新增 `others` 通道，
   每项带 `pid / profile / why`）—— ⛔ 不许让 `continue` 把证据一起丢掉；
② ⚠ ⚠ **渲染层按"有没有证据"分档**，⛔ 不许只用 `length === 0` 一个判据：
   有证据 ⇒ "**有 N 个在跑，但它们都不合格（为什么）**"；没证据 ⇒ 才是"没有找到"；
③ ⚠ ⚠ **新开的档必须明确归到哪一族**（本仓 `not-assembled` 归"判不出"、
   判据模下 exit 2）—— ⛔ 不许因为是新档就悄悄落 0（那等于把误报换成静默）；
④ ⚠ ⚠ **负向对照要一起立**：`others` 为空时**仍**落"判不出"（⛔ 不许把新档做成通配）；
⑤ ⚠ **判据模/报警模的口径照旧分开**：新档只影响判据模的退出码，报警模照旧只打印。

**出处**：⚠ **2026-10-20 实测** ——
读数：`ps` pid 26110（06:56:25 起）/ 30214（13:33:43 起）· `curl -o /dev/null -w %{http_code}` ⇒ `401`（服务在）·
`dsh --profile web --dump-config` ⇒ `patch: entry "dsh-hob" not found` +
`python3` 读 `package.json` 的 `dsh.profile.bundles` ⇒ **28 项、无 dsh-hob**（与 `package.json.bak-dsbot-20261020-000040` 对照，
那份**有**）；
修法落点 = `scripts/check-build-sync.mjs` 的 `runningInstances()`（新 `others`）+
`classifyInstance()` 第 4 参 / `not-assembled` 档 + 断言 **T-e**（断言 5 → 6）；
回放读数：`--probe` 注入同一份证据 ⇒ strict exit **2** 且文案改为"有 1 个宿主在跑，但没装配"；
空证据 ⇒ 仍 exit 2；装配回来之后 ⇒ strict exit **0**「同步 · 1 个进程核过」。
⚠ 同族：**E-156** · **E-170** · **E-148**（"我说派出去了"不是证据 —— 同属"读数≠事实"族）。
