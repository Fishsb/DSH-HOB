### E-176 · ⚠ ⚠ **⛔ 不许跨单对比「查了多少处」这个数** —— 那个分母会随"我自己新建/删除了几个文件"变化

**现象（实测，2026-10-25 · 两单连做）**：⚠ `check:all` 汇总里有一行
`处级口径：查了 N 处 · 过了 N 处`。⚠ 我连着做单，每次都拿它跟上一单的 N 比 ——
结果**两次都差点把自己的动作误读成"判据出错"**：

- ⚠ `archive/2026-10-25-module-log-mismatch` 收工时 N 从 `1420 → 1421`（**+1**），我一度以为漏了什么；
  ⇒ 查出真相 = **`check:archive` 对"盘上有、index 里 0 份"的派生目录每目录印一条 `ok()`**，
  ⚠ 而我**新建了本单的归档目录** ⇒ 多一个派生目录 ⇒ **+1**。
- ⚠ `archive/2026-10-25-gate-existence` 收工时 N 从 `1421 → 1429`（**+8**），
  ⇒ 逐族核过才敢下结论：`check:presets` **+4**（我加的存在性断言）+ `check:gitignore` **+3**（V3/W）+
  **`check:archive` +1**（又是本单新建目录）。⚠ **`4 + 3 + 1 = 8` 精确吻合之后**我才敢写"只增不减"。

⚠ ⚠ **两次的干扰项都不是判据缺陷，而是"我在写档案"这个动作本身**。

**根因**：⚠ ⚠ **这个"处数"不是常数，它是"被判定对象的规模"的函数**，而**我会自己改变那个规模**：
- `check:archive` 的处数 ∝ 账本里的派生目录数（**我每开一单就 +1**）；
- `check:gitignore` / `check:presets` 的处数 ∝ 我**新加的断言条数**（本单 +5 条就 +5）；
- ⚠ 于是**跨单相减 = 把"我的写入量"与"判据的覆盖量"混在同一个数里** ——
  而这正是本仓明令禁止的**混量纲**（`E-150` 是同族：`N/M` 里的 `M` 是"命令条数"、不是"`✗` 行数"，
  两个分母"都看起来合理"但不可相加）。
⚠ 更麻烦的是：**它会让"判据真的坏了一处"被"我自己多写了文件"掩盖**（或反过来误报）。

**正确做法**：
① ⚠ ⚠ **只在同一单内比改前/改后**，并**同时写明这一单新增/删除了哪些文件、新增了几条断言** ——
   ⛔ 不许把上一单的数当基线；
② ⚠ ⚠ **差值必须逐族分解到"来源可指认"**（本仓做法：把每族的 `查了 N 处` grep 出来逐条比，
   `+4 / +3 / +1` 每一笔都写清是哪一条断言、或哪一个新目录）；
   ⚠ **分解不平就不许写"只增不减"** —— 那说明有别的变化没查到；
③ ⚠ ⚠ **"我自己新建的目录"要单独列出来**（本仓：`✓ ② 盘上派生目录 archive/<本单>/ …` 那两行），
   ⚠ 这样"分母为什么变了"是**可读的**，⛔ 不是靠猜；
④ ⚠ **别用"总数变大"当"判据变强"的证据**：那是**两个命题**
   （"多了几条断言" vs "原有判据覆盖得更全"）—— 后者得逐族看，⛔ 总数字看不出来；
⑤ ⚠ **下界（`ASSERTION_FLOORS`）才是跨单可比的那个量**（它只准升不准降）；
   ⚠ 「查了 N 处」是**当前盘面的规模读数**，两者**不可互相替代**。

**出处**：⚠ **2026-10-25 实测**（两单连做）——
`archive/2026-10-25-module-log-mismatch/REPORT.md` §4（+1 查清 = `check:archive` 的派生目录，原文行 468-469）；
`archive/2026-10-25-gate-existence/REPORT.md` §3.3（+8 逐族分解：`4 + 3 + 1`，与实测精确吻合）；
⚠ 具体读数：`1420 → 1421 → 1429`；
⚠ 干扰项证据（不是判据缺陷）：`check:archive` 输出里 `✓ ② 盘上派生目录 archive/2026-10-25-<本单>/ —— 盘上有 N 份、但 index 里 0 份`；
⚠ 同族：**E-150**（`N/M` 的 `M` 是命令条数，不是 `✗` 行数）· **E-109**（回报里的数字必须带口径）·
**E-137**（自报读数天生没有执行器）。
