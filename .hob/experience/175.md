### E-175 · ⚠ ⚠ **「两边一致」不等于「东西还在」** —— 凡一致性判据必须配一条**存在性**判据，⛔ 不许拿前者代替后者

**现象（实测，2026-10-25 · `archive/2026-10-25-gate-existence`）**：⚠ 本仓有多条判据只判
"**两份载体逐字相同**"（人读版 ↔ 机读版、正本 ↔ 模板 …）。
⚠ ⚠ **"相等"这个关系在两边都没有时也成立** —— 所以**两份一起删掉，判据照样绿**。

实测（用脚本**自己的**抽取函数，未改任何文件）：

```
prefix 块行数 = 334
人读版 text 块数 = 1  各块行数 = [ 334 ]
改前：两份逐字相等 = true

正文含「这轮做了什么」= true
两侧同时删 ⇒ 两份仍逐字相等 = true
⇒ ⑤（只判一致）仍然 PASS —— 漏洞成立
```

⚠ 更严重的一格：`UD-152` §③ 已把三条硬规矩写进正文
（不再问已表态的 / 当轮落账 / 待决写已认领），⚠ 而**判据里 grep 一条都找不到**：

```
"Never ask again about something the user has already settled" 在脚本里出现 = false
"已认领 (claimed by the user)" 在脚本里出现 = false
"这轮不用你决定" 在脚本里出现 = false
正文含 "Never ask again about something the user has already settled" = true
```

⇒ ⚠ ⚠ **正文有、判据零覆盖** ⇒ 两份一起删掉这三条，**全族全绿**。

**根因**：⚠ ⚠ **一致性判据与存在性判据守的是两个不同的命题**，而它们**在"都正常"时输出完全相同**：
- 一致性：`A == B` —— 防的是"**改一边漏一边**"；
- 存在性：`内容 ∈ A`（且 `∈ B`） —— 防的是"**两边一起没有**"。

⚠ ⚠ 而**一致性判据会在存在性缺失时给绿**（`∅ == ∅` 为真）⇒
**"两份一致"这个绿灯，对"东西还在不在"零分辨力。**
⚠ 同族：**`E-83`**（断言只覆盖尾部 ⇒ 未覆盖部分是「缺席的 PASS」）·
**`E-126`**（豁免要成对：只补"不该被咬的"、不验"该咬的还咬不咬" = 把判据改哑）·
**`E-131`**（两侧各写一套 ⇒ 两边一致地错，而"一致"看着像"正确"）——
本条是同一族在**"两份载体互相校验"**这个形态上的落地。

**正确做法**：
① ⚠ ⚠ **凡"一致性"判据，必须同批配一条存在性判据** ——
   ⛔ 不许以"两份都改了所以是同步的"为由省掉它；
② ⚠ ⚠ **存在性判据要钉"足够具体的原文片段"，⛔ 不是关键词** ——
   关键词会误伤（正文别处合法提到它也算过），片段才能回答"那一条在不在"；
③ ⚠ ⚠ **片段必须对"折行"稳健**：正文若是 YAML `|-` 块，长句会被折行，
   ⚠ 把片段写成跨行原文（含缩进）⇒ 正文只是重新折行就**假红**。
   ⇒ **先做空白归一化再 `includes`**（连续空白压成单空格）——
   ⚠ 这**不放宽**：比对仍是逐字，改一个字仍会红；只是不把"换行/缩进"当字面值的一部分。
   ⚠ 本仓第一版就是这么错的（当场 FAIL），**那是判据口径不对、不是缺陷**；
④ ⚠ ⚠ **缺哪条要逐条点名**（⛔ 不 first-fail 就 return）—— 否则补一条再跑一次才发现还缺一条；
   ⚠ 每条最好同时印出"**缺它会退回哪种病**"（只说缺哪条不够，还得让人知道代价）；
⑤ ⚠ **新条目的片段取自正文现状时，要在注释里写明"正文有意改写须同批改这里"** ——
   ⚠ 否则会出现"改对了反而红"，而这个代价必须写在明处。
