### E-155 · **登记表单元格是个"机械面"** —— 两支写法写法相似会照抄错，裸竖线会打断单元格

**现象**：`.hob/README.md` §5.1 的**第 3 列**（机检归属）**有两支合法写法**，⚠ 而它们在视觉上**几乎一样**：
- `` `check:<存在的名>` `` —— **带反引号**；
- **裸** `未机器化` —— ⛔ **不带**反引号（⚠ 带反引号反而落进上面那一支的正则分支 ⇒ `F` 组判"不是合法值"）。

⚠ **两次实测各踩一支**：**第 156 轮**加五行时，**顺着上一批的行的形状复制**（上一批加的多是 `check:` 那支）
⇒ 第 3 列写成了带反引号的 `` `未机器化` `` ⇒ `F` 组**当场报 3 条 `✗ …不是合法值`**；
**第 160 轮**加一行时，第 3 列**填对了**（依据 = **作业书把它写成了明确值**），
⚠ 但**同一行里**又踩了**另一种**：单元格正文里写了 `` git show <修订> | grep -c … ``
—— ⚠ **那个裸竖线 `|` 打断了 Markdown 表格的单元格** ⇒ `F` 组把**后半句整段**当成了第 3 列，
报 `✗ F 第 590 行的「机检归属」不是合法值：\`grep -c '<该条的字样>'\`；…`（⚠ **看不出根因**）。
⚠ **两轮的坑都不是语义错误**（内容都对），⚠ **全是"表格这个机械面"造成的** ⇒ 且**两次都在提交前修净**（⛔ 未进任何提交）。

**根因**：**§5.1 的判定器（`F` 组）解析的是"表格的形状"，而写它的人脑子里想的是"这句话的意思"** ——
⚠ 于是**同一张表里存在两个互不相干、却都能把行写坏的机械约束**：
① **第 3 列须逐字匹配两支正则之一**（⚠ 而两支的差别只是**一对反引号**）；
② **单元格须恰好被 `|` 切成 3 段**（⚠ 于是**任何正文里的裸竖线都会多切一段**）。
⚠ **写它的人按"上一行长什么样"复制**（同族 **E-131**："照抄是纪律，但它没有执行器"）——
⚠ 而**"上一行"恰好可能是另一支**（①）或**恰好不含竖线**（②）⇒ **复制就翻车**。
⚠ **更深一层**：`F` 组报的是"**不是合法值**"，它**不告诉你该改成什么**（⚠ 第 156 / 160 两轮
**都是靠"回头读 §5.1 的文档"或"自己看出竖线"才定因的**）⇒ **修法不在报错里**（同 **E-120**：规矩没有执行器）。
⚠ 与 **E-153** 的关系：E-153 的**主题**是"只写账本侧 ⇒ 换个工作区开箱拿不到"，
其"正确做法第 ③ 条"里**提到了两支写法这个配套**；⚠ 但**裸竖线那一支只在正本 §0.7 的配套句里**（⚠ **实测 0 处入库**）
⇒ 本条把**两个机械约束合起来**记（⚠ 第 163 轮已裁定"同一口径两处并存 = 正确"，判据 = 两处须能互相指认）。

**正确做法**：
① ⚠ ⚠ **加行前先看清这一行该填哪一支** —— ⛔ **不要按"上一行长什么样"复制**：
   **处置者是某个 `check:` ⇒ 写 `` `check:<名>` ``（带反引号）**；
   **处置者是人 / 无机器管制 ⇒ 写裸 `未机器化`（⛔ 不带反引号）**。
   ⚠ **派单方一侧**：**把每行该填哪个写成明确值**（⛔ 不要只说"第三列只许 A 或 B"—— 实测这句话挡不住照抄）；
② ⚠ ⚠ **单元格正文里 ⛔ 不写裸竖线 `|`** —— 需要示例时**改成叙述形态**
   （如"用法：先 `git show <修订>` 取该轮内容，再 `grep -c …`"，⛔ 不写 `git show <修订> | grep -c`）；
③ **自检（加完立刻跑）**：`npm run check:gitignore | grep 'F ✓'`
   —— ⚠ 判据 = **行数 +1**、且第 3 列**全部合法**；
   ⚠ 另可**手工切一刀**验单元格段数（`line.strip('|').split('|')` ⇒ **应恰好 3 段**）；
④ ⚠ **执行方一侧**：若 `F` 组报"不是合法值"而**那一列看起来很正常** ⇒ **先查单元格里有没有裸竖线**
   （⚠ 两轮实测中，这一支的报错**长得像"那一列写错了"，实际是"那一列被切成了两段"**）。

**代价与处置**：**两轮各踩一次**，⚠ **两次都在提交前修净**（⛔ 未进任何提交）——
第 156 轮：3 条 `✗` ⇒ 改成裸写 ⇒ 转绿；第 160 轮：1 条 `✗` ⇒ 改成叙述形态 ⇒ 转绿。
⚠ 第 160 轮那次**已登记**于 `REPORT-R158.md` 第 4 段第 1 条（⚠ 并在第 5 段把它列为待决问题）。
⚠ **诚实登记**：该坑**无机检**（`F` 组只判"第 3 列是否为合法值" ⇒ 它**报的是症状、不是病因**）
⇒ 登记表第 3 列如实标 `未机器化`。

第 156 轮 `REPORT-R156.md` §4 第 1 条（3 条 ✗ · 照抄翻车）· 第 160 轮 `REPORT-R158.md` §4 第 1 条 / §5 第 1 条
（裸竖线打断单元格）· `scripts/check-gitignore.mjs` 的 `F` 组（判"第 3 列是否合法"）。
