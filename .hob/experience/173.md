### E-173 · ⚠ ⚠ **脏工作树里做「还原」只能用 `cp` 回自己的备份，⛔ 绝不能用 `git checkout --`** —— 它还原的是索引，不问工作树里压着什么

**现象（实测，2026-10-25 · `archive/2026-10-25-gate-existence`）**：⚠ 负向对拍时我改过
`.hob/templates/CONTEXT.md`（删两行以证明判据会红），还原那一步图快写了
`git checkout -- .hob/templates/CONTEXT.md`。
⚠ ⚠ **它把那个文件里"别人未提交的改动"抹掉了** —— 该文件开工时是 **`MM`**
（索引里有一版、工作树里**还压着另一份未提交改动**），而 `checkout` 回退到**索引版** ⇒ 工作树那份没了。

⇒ ⚠ **发现方式不是"我看见了"，是"数不对了"**：下一轮跑 `check:gitignore` 时，
`没过` 从 `3` 变成 **`2`** —— 我疑惑"少了一条"，回去 `git status | diff` 开工快照，
才看到 `.hob/templates/CONTEXT.md` 状态从 **`MM` → `M `**。
⚠ ⚠ **如果那一步没让任何数字变化，这个损失会完全静默**（`E-24` / `E-25` 同族：
**"看起来还原了" ≠ "还原成开工那一刻"**）。

**根因**：⚠ ⚠ `git checkout -- <path>` 的语义是「**用索引里的那一版覆盖工作树**」——
它**只回答"索引里是什么"**，⛔ **不回答"工作树里原本压着什么"**。
⚠ 而在一个**脏工作树**里（本仓开工时 64 行未提交状态、其中多份是 `MM`），
"索引版"和"开工那一刻的工作树版"**是两回事**。
⇒ ⚠ 于是 **`checkout` 这个名字听起来像"撤销我的改动"，实际做的是"撤销所有人的改动到索引为止"**。
⚠ 同族：**`E-161`**（改了被派生清单收录的件必须同批重建，⛔ 别把"改既有"当成"免重建"）——
两者都是**"我以为我在动一个小范围，实际动的是更大的一片"**。

**正确做法**：
① ⚠ ⚠ **在脏工作树里，"还原"只认一种手法：改之前 `cp` 一份到工作区外，改完 `cp` 回来** ——
   ⛔ 永远不要用 `git checkout --` / `git restore` / `git stash` 去"还原一个我改过的文件"；
② ⚠ ⚠ **动任何文件之前，先拍一份"开工态快照"**（本仓做法：`git status --porcelain > /tmp/x-before.txt`），
   收工再拍一份 **`diff`** —— ⚠ 差异必须**逐行解释得清**，⛔ 不许"看起来差不多"就过；
③ ⚠ ⚠ **还原之后必须双重核对**：`md5sum`（或 `cmp`）对备份 **＋** `git status` 对开工快照，
   ⚠ 两者都过才算还原（单靠其中一个都会被"索引版恰好也是对的"骗过去）；
④ ⚠ **对拍前先看该文件的状态码**：若它是 `MM` / `AM` / `AD` 这类**带工作树改动**的码，
   ⚠ 那它**没有"干净的还原点"** ⇒ 只能靠自己的备份，⛔ 不能靠 git。

**出处**：⚠ **2026-10-25 实测** ——
`archive/2026-10-25-gate-existence/REPORT.md` §5.4 有完整记录：
失误命令 `git checkout -- .hob/templates/CONTEXT.md`；
发现读数 = `check:gitignore` 的 `没过 3 → 2`；
状态码证据 = `.hob/templates/CONTEXT.md` 从 `MM` 变 `M `；
找回手法 = `cp /tmp/gm/bk.TPL.md`（开工态工作树备份）覆盖回去；
核对 = `md5sum` 现为 `a087690196853fd06b0bf2292631d11a`（与备份一致），
被覆盖那份是 `32100de9f89ccd85d70256ace9b1b8e5`（= 索引版）；
最终 `git status | diff 开工快照` ⇒ 只剩本单应有的那一条改动，其余逐字相同。
