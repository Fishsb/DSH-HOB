### E-132 · **按行号机械切分单体脚本时，夹在两块之间的模块级声明会被"吞进"函数体** —— 作用域悄悄变了，而**基线 diff 当场抓住**

**现象**：把一个 1726 行的单体机检脚本（`check-gitignore.mjs`）按"族"拆成
「薄调度入口 + 三个模块」。做法是**按行号区间切片、原样搬运**（⛔ 不retype 任何判据 —— 那才谈得上"没改判据"）。
切片本身**逐段首尾核对过**，`node --check` **四份全过**，`✓` 计数与判定行也**对得上**……
⚠ 但**一跑就崩**：`ReferenceError: ZERO_WIDTH_RE is not defined`（`check-code-face.mjs` 的 G 组）。

**根因**：原文件里 `const ZERO_WIDTH_RE = /…/`（**模块作用域**）**夹在 F 段的文档注释与其代码块之间**——
它**在行号上落在 F 的区间内**，但**语义上不属于 F**（它是 G 的判据、也在 H/I 的注释里被提到）。
⇒ 把它连同 F 一起塞进 `export function runDiscipline(...) { … }` 之后，
它从**模块作用域**变成了**函数局部**：F 自己看不见它（也没用），**G 却从此看不见了**。
- ⚠ **`node --check` 查不出来**：这是**运行时**的 `ReferenceError`，语法**完全合法**。
- ⚠ **"逐段首尾核对"也查不出来**：切片边界**是对的**（F 确实从 `/**` 开始），
  错的是**"这段代码该放在什么作用域里"** —— 那是**行号区间表达不了的信息**。

**教训（本条的要点）**：**行号区间是"文本位置"，不是"作用域边界"**；两者在
"两块之间夹着一条共享声明"时**会分叉**。
⇒ 机械搬运**必须用一把会跑的尺子验收**，⛔ 不能只靠"切得准不准"的静态核对。

**正确做法**：
① **先存基线、再动手**（本轮 §3① 的硬要求）：同一条命令在**改前**跑一次、**逐字落盘**
   （本轮：82 行 / `✓ 69` / `EXIT=0` / md5 `09ddc4fe…`，**另存一份不可变副本**）。
   ⚠ 顺序**不可颠倒** —— 先改后存基线，等于"没弄坏"这句话**永远无法证明**。
② **主判据是"拆前拆后逐行一致"，不是 exit code**（**E-112 家族**）：
   搬丢一整组时**很可能照样 exit 0**（那一组的 ✗ 永远不出现）⇒
   本轮就是靠**逐行 diff** 在第一时间看到"整段输出被一段堆栈替换" ⇒ **当场定位到作用域问题**。
   ⚠ 去噪：`UNDICI` 告警行带 PID ⇒ 比对前先剔除，否则会把噪声当差异。
③ **按"语义块"切，不按"看起来整齐"切**：哪些声明是**共享的**（模块级常量）必须**留在模块顶层**，
   ⛔ 不能因为"它落在某个区间的行号里"就跟着进函数体。切完**逐个模块跑一次**，
   而不是只跑总入口（总入口会把"谁看不见谁"掩盖成一次通过或一次崩溃）。
④ **切分 = 纯搬运 ⇒ 任何非搬运的改动都要显式列出并单独解释**：
   本轮实际只有**两处**非搬运改动 —— ① 断言 K 的检查侧基准点**搬到新家**（不同步它 ⇒ K 会因
   "提取不到"而 FAIL —— ⚠ **这正是 K 自带的保护**，它把"你忘了改这里"变成**可读 FAIL**）；
   ② `SCRIPT_LANDING_EXEMPT` 白名单**从空表变成 3 条**（纯库不该单独跑 ⇒ 按纪律**逐条登记 + 写理由**）。
   ⚠ ②会**如实改变一行输出**（反向自检的计数从"10 个 .mjs"变成"13 个 .mjs，另有 3 个显式豁免"）
   ⇒ 这类**预期内的差异要事先说明**，⛔ 不能混进"没差异"里蒙过去。
⑤ **负向对拍要覆盖"搬过家的"每一组**，且**还原逐字节**（`cmp` exit 0）：
   本轮实测 D / D′ / J / G / K / 脚本落点自检**全部照旧咬人**；
   ⚠ 另加**"改哑"对照**（**E-126**）：把判据**故意改宽** ⇒ **自带样本当场报 ✗**
   （只验"该咬的会咬"会让**判据写对**与**判据过宽**输出相同）。
