### E-161 · **改了「被派生清单收录」的件 ⇒ 必须同批重建清单，⚠ 且**必然**引入待重启项** —— ⛔ 别把"改既有"当成"免重建"

**现象（同族两处探针，均为实测）**：
- ⚠ **改 `.hob/README.md` 一个字节**（第 266 轮 `TASK-R215` §3.2 探针 A）⇒ `check:gitignore` 当场红：
  `✗ R 同源漂了：.hob/README.md` —— 清单 sha256 `ae72a1c1…` vs 仓库 sha256 `49aa7c12…`。
- ⚠ **改 `.hob/templates/REPORT.md` 一个字节**（同轮探针 B）⇒ 同一断言红：
  清单 sha256 `79ea38aa…` vs 仓库 sha256 `b95f1d0f…`。

⚠ ⚠ **两次都**不是"新增 / 删除了件"** —— ⚠ ⚠ **只是**改了既有件的一个字节****，
⚠ 而判据照样红 ⇒ ⚠ ⚠ **"新增/删除 vs 改既有"这个二分**在机制上不成立****。

**根因**：`R`（`check:gitignore` 的骨架同源断言）**不是只比 `allowlist`** ——
⚠ 它还**逐件比 `sha256`**。⚠ 而 `allowlist` 是**从 `.gitignore` 的 `!` 例外派生**的
（⚠ 改文件**内容**不会动它）⇒ ⚠ ⚠ **"改既有件不影响 `allowlist`"这一点是真的，
但"因此不影响 `R`"是假的** —— ⚠ **两件事被混成了一件**。
⚠ ⚠ **真正的判据 = "**要不要重建派生清单**"**：⚠ **凡动**被清单逐件收录**的件**（不论新增 / 删除 / 改内容）
⇒ ⚠ ⚠ **清单**必然过时** ⇒ ⚠ **必须跑 `gen:skeleton` 重建**。
⚠ ⚠ **而重建物落在 `src/server/skeleton-manifest.ts`（`src/**`、入库）** ⇒
⚠ ⚠ **它要 `build` 才进 `lib/`、要**重启**才进运行实例** ⇒ ⚠ ⚠ **凡这类改动，**必然**是一个待重启项**。

**正确做法**：
① ⚠ ⚠ **落笔前先问一句**："**我要改的这个件，在不在这份逐件清单里？**"
   （⚠ 判据 = `grep "path: '…'" src/server/skeleton-manifest.ts`；⚠ **清单的条目数**也可先数一遍）。
② ⚠ **在清单里** ⇒ ⚠ 顺序**固定**：⚠ **① 改 `.hob`** ⇒ ⚠ **② `npm run gen:skeleton`** ⇒
   ⚠ **③ `npm run check:gitignore`（期望转绿）** ⇒ ⚠ **④ `npm run gen:skeleton --check`（期望"一致"）** ⇒
   ⚠ **⑤ 收尾套件** ⇒ ⚠ **⑥ 才提交**（⚠ ⛔ **不许在第 ③ 步之前提交**，⚠ ⛔ **也不许因为红就跳过它去提交**）。
③ ⚠ ⚠ **并**照实声明**"本单引入了待重启项"** —— ⛔ **不许写"不引入"**（⚠ 那是错的，⛔ 不是保守）。
④ ⚠ **不在清单里**（⚠ 如经验库 `.hob/experience/**` —— 生成器自己 `EXCLUDE`）⇒ ⚠ 改它**不**动清单、**不**引入待重启项。
