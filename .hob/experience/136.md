### E-136 · **目录形态的 MUST-TRACK 判据**：`git ls-files --error-unmatch <目录>` **恒 `exit 1`** ⇒ 判据要用 `git ls-files -- <目录>` 输出非空

**现象（第 81 轮，加 `mustTrack` 一条时实测）**：要把 `.hob/experience/`（**目录**）加进
`check-repo-rules.mjs` 的 `mustTrack` 时，直接套用既有的 `inIndex()`：
```
$ git ls-files --error-unmatch -- .hob/experience/
error: pathspec '.hob/experience/' did not match any file(s) known to git
$ echo $?
1
```
⇒ **恒 `false`**。照搬会**常红**，而"常红"的下场是被无视（E-117 同族：判据一旦自己不可信，就没人再看它）。
⚠ 前一轮（第 80 轮）正是因为这条走的"撤下该项"路线 —— 当时判断为"目录还不该进 git"，
但其实**还有另一半原因没被认出**：判据形态本身对目录不适用。

**根因**：**git 只跟踪文件，目录本身不在 index 里** ⇒ `--error-unmatch` 对目录路径**无对象可匹配**。
⇒ 这是**判据形态与被判对象的形态不匹配**：拿"单文件"的判据去判"集合"。

**正确做法**：**按形态分派，且新判据更严而不是更松**：
```
// 目录形态：该目录下**至少有一个文件真的进了 index**（`git ls-files -- <dir>` 输出非空）
function inIndexDir(dir) {
  const out = execFileSync('git', ['ls-files', '--', dir], { cwd: root, encoding: 'utf8' })
  return out.trim() !== ''
}
```
- ⛔ **不是放宽**：原判据对目录恒 false（等于"从不检查"），新判据要求"**目录下至少一个文件在库**" ——
  它拦的正是本项要拦的东西（**E-70** 的失效模式：文件静默不入库）。
- ⛔ **不要用 `--error-unmatch`** 去凑 —— 它对目录没有意义。
- ⚠ **旁证实测**：`!.hob/experience/**` 这条通配 `!` 例外对"一层文件"是**冗余**的 ——
  **承重的是目录行** `!.hob/experience/`（它本身就放行其下全部路径）。实测四种情形：
  两条都在 ⇒ 不忽略；**只删 `**` 那条 ⇒ 仍不忽略**（`check:gitignore` 仍 PASS）；
  只删父行 ⇒ 被忽略；两条都删 ⇒ 被忽略。
  ⇒ 作业书若把"删 `**` 那条"写成负向对拍，**它不会咬** —— 对拍的坏样本必须**真能翻判据**，
  否则那条"对拍"只是形式（与 E-112 同族：**通过判据要看不通过时长什么样**）。

**出处**：第 81 轮（骨架侧搬家轮）加 `mustTrack` 的 `.hob/experience/` 一条时实测；
`scripts/check-repo-rules.mjs` 的 `inIndexDir()` · 第 82 轮独立复核把它复验为
`✗ MUST-TRACK（目录）但其中没有任何文件加入 git index：.hob/experience/`（`git rm --cached` 后实测）；
`!.hob/experience/**` 冗余这条由第 81 轮实施方先报、第 82 轮复核方独立复验（四种情形）。
