### E-162 · **往索引 / 表格类文件**追加行到文件末尾** ⇒ 与上一张表之间隔空行 ⇒ **产生孤立表行**，⚠ 判据 `P2` 当场红**

**现象（本轮实测）**：⚠ 三条新加的用户决策行（`UD-122` / `UD-123` / `UD-124`）
⚠ **被追加到 `volumes/user-decisions/INDEX.md` 的**文件末尾****（⚠ 与上一张表之间**各隔一个空行**）⇒
```
✗ P2 表结构：volumes/user-decisions/INDEX.md:125 —— 孤立表行（前后被空行夹住 ⇒ 该块无分隔行）
✗ P2 表结构：volumes/user-decisions/INDEX.md:127 —— 孤立表行（前后被空行夹住 ⇒ 该块无分隔行）
✗ P2 表结构：volumes/user-decisions/INDEX.md:129 —— 孤立表行（前后被空行夹住 ⇒ 该块无分隔行）
```
⚠ ⚠ **`check:gitignore` 当场 `EXIT=1`** ⇒ ⚠ **它把"收尾全部 `EXIT=0`"这条提交前置条件直接挡死**
（⚠ 第 266 轮就是因此停手的 —— 而**成因在派单方那一侧**）。

**根因**：⚠ **"追加到文件末尾"与"加进它所属的那张表"是两件事**。
⚠ `P2` 的判据是「**连续以 `|` 开头的行 = 一个表块**，⚠ **一个表块的第 2 行必须是分隔行**」——
⚠ ⚠ **一条孤立的表格行自成一块**（⚠ 块内只有 1 行）⇒ ⚠ **它连"第 2 行"都没有**
⇒ ⚠ 判据判它**无分隔行**。⚠ ⚠ **而在 markdown 渲染里，这一行**根本不显示成表格**
⇒ ⚠ ⚠ **"内容还在"让人以为写成功了，⚠ 而形态已经静默失效**。

**正确做法**：
① ⚠ ⚠ **凡往"表 / 索引"类文件加行** ⇒ ⚠ **先找到那张它**所属**的表**（⚠ 现有表头 + 分隔行 + 同族行），
   ⚠ **把新行**插进表内**（⚠ 紧接同族的最后一行之后、⛔ **中间不加空行**）。
② ⚠ ⛔ **⛔ 不许"往文件末尾一贴就完事"** —— ⚠ 末尾是**下一节 / 文件边界**，⛔ 不是"表尾"。
③ ⚠ ⚠ **加完当场跑一次那条判据**（⚠ 本仓 = `npm run check:gitignore`；⚠ ⚠ **它在收尾套件里，⚠ 早跑一次成本几乎为零**）。
④ ⚠ ⚠ **别把它当"格式小事"** —— ⚠ 它的失效形态是"**东西都在、没人报错、⚠ 但它不显示**"，
   ⚠ ⚠ **而唯一会拦它的那条命令，恰好排在"提交前置条件"的位置上**。
