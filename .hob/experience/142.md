### E-142 · **机检的覆盖面会静默缩水** —— 一处措辞改动就让一条检查少核 34 对成员，而收尾命令仍逐条全绿

**现象**：第 120 轮把 `CONTEXT.md` §5.2 一行里**具名的归档目录**改成了**结构解**（按本仓既有纪律："列死成员会过期"）。
第 121 轮实测：`check:archive` ② 的**成员比对由 112 对降到 78 对**（−34：`duty-boundary` 33 + `rounds-105-106` 1），
而**收尾命令逐条 EXIT=0、✗=0、零提示** —— **判定行仍写「成员齐备」**。

**第 122 轮补一刀 —— 派生判据自己也会带洞**：第 121 轮把覆盖面改成"派生"时，**又立了一条收录判据**
（`archive/` 下"有 `README.md` **或** 含 `sources/`"的目录）⇒ **两者都不具备的目录整个不可见**
（`rounds-*` 系列 9 个，且**收尾仍全绿**）。
⇒ 口径升级为「**说"谁在盘上就核谁"，就要真的覆盖盘上全部**；⚠ **任何"收录判据"都要先问一句"谁被它排除在外"**」。
⇒ 扩到**全部子目录**后实测：目录形态 **15 → 95 处**、成员比对 **154 → 563 对**（**+409**）。

**根因**：那条检查的**扫描对象来自"正文里被点名的具体目录"** ⇒ **正文一改写法，覆盖面就变**；
而这个变化**不产生任何红灯**（"无对象可核"与"成员齐备"在判定行上几乎同形）。
⚠ **同族第二态**：改成"派生"之后，洞**从稿件搬进了判据本身** —— 只要写着"收 X 类目录"，
就**必然有一批 X 类之外的目录不被核**；而**判据越像"常识"（有 README 才叫归档）越不容易被当成排除面**。
⇒ 与 **E-133**（写死的成员清单 ⇒ 新成员逃出视野）**同族**：那条讲"清单写死"，这条讲"**覆盖面挂在别人的措辞上**"。

**正确做法**：
1. **机检的覆盖面必须派生**：扫**盘上实际存在的目录 / 成员**，⛔ 不许依赖"某处正文正好点名了它"。
   ⚠ ⚠ **且"派生"要派生到底**：⛔ 别在派生之上又加一层"收录判据"—— 那只是把洞从稿件搬进判据。
2. **覆盖面变化要能被看见**：判定行里**分别报**"正文点名"与"盘上派生"两个来源的贡献，⛔ 不报一个合计数
   （合计数会把"降了"藏起来）。
3. **每次改动若动了某机检的扫描对象 ⇒ 同批重测该机检的「覆盖面读数」**：⛔ 不许只看"全绿"；
   降了必须逐数归因（**单变量实验**胜过推理）。
4. **新增覆盖必须配负向对拍**，且**成对**（正例 + 反例）：本例是"夹具里放一个**没人点名**的目录，破坏其成员 ⇒ 必须 FAIL"；
   ⚠ **加宽覆盖面时还要补"用它新覆盖到的那一类"的对拍**（第 122 轮补的档 = **既无 README 又无 sources/** 的目录）。
5. ⚠ **加宽覆盖面会点亮"此前被排除面掩盖着的老 bug"** —— 第 122 轮实测：扩到全部子目录后立刻 **FAIL 105 处**，
   排查发现**不是数据坏了**，而是 `git ls-files` 默认 `core.quotePath=true` **把非 ASCII 路径引号化** ⇒
   `existsSync("…\350\264\237…")` 恒 false ⇒ **把存在的成员报成"缺成员"**（改用 `-z` 后 0 假报）。
   ⇒ **纪律**：扩覆盖面后出现大批 FAIL，**先判"是真坏还是判据自己的编码 bug"**
   （**单变量对照**：同一批对象换一种读法，假报应当消失）；⚠ 别把假报当"放宽断言"的理由去关掉检查。
6. ⚠ **同一类读法要全族扫**：`core.quotePath` 的引号化**不止一个子命令**（`ls-files` / `status --porcelain` /
   `diff --name-*` / `log --name-only` …）⇒ **第 123 轮把 `scripts/` 里"git 输出当路径用"的调用点逐点核过**
   （⚠ 只判"非空"或只取退出码的**不算**）。⇒ **纪律**：凡"git 的输出被当作路径用"⇒ **先问一句"它会不会被引号化"**；
   关掉它的办法是 `-z`（或 `-c core.quotePath=false`），⛔ **不是加白名单、⛔ 也不是放宽断言**。
