# UD-156 · 账本只给 Hob 用，⛔ 不为人读而写

**用户原话（逐字）**：

> 「还有我看账本里面有"人读版"的信息，当前项目的账本就是给HOB预设用来使用的账本信息，不需要人读和操作的，用户需要调整或者了解账本信息直接问就可以了，不需要人去看账本，不需要为了人读或者看去专门写一些文档信息」

## 决定

| 项 | 内容 |
|---|---|
| **账本的读者** | **只有 Hob（及其派出的实施会话）**。⛔ 不存在"人读"这个读者 |
| **用户的获取方式** | **直接问**。⛔ 不需要为"用户会去读账本"而写任何东西 |
| **⛔ 不许再写** | 为"人读"而存在的载体、栏目、版本、说明：<br>· 「人读版」与「机器读版」这类**双版本**；<br>· 「人话一页」「给不懂代码的人写」这类**面向人类读者的说明件**；<br>· 正文里为"让人类看懂"而加的**解释性铺垫、类比、背景故事** |
| **✅ 仍要保留的** | ① **事实本身**（结构 · 约束 · 边界 · 决策 · 证据）；<br>② **`简要说明` 那种"说给用户听"的内容** —— 它在**回复**里，⛔ 不在账本里；<br>③ **可被机检读的机器读版**（⚠ 它不是"人读版的对偶"，它是**判据的靶点**） |

## 为什么（用户给的理由，照录）

用户不看账本，需要什么直接问。⇒ **账本里为"人读"服务的那部分，是没有读者的成本**：
它占体量、会过期、还得有人维护，而它服务的那个读者**根本不会来读**。

## ⚠ 一条必须分清的技术边界（不是反驳，是防误删）

**「人读版」这三个字在本项目里指过两种完全不同的东西**，处置完全不同：

| 形态 | 它实际是什么 | 处置 |
|---|---|---|
| **预设契约的「人读版」** | ⚠ 它**是判据靶点** —— 有一条机检要求"人读版与机器读版**逐字一致**"。它的读者名义上叫"人"，实际是**机器在比对**它 | **⛔ 不许删**；⚠ 只许**改名**（去掉"人读"这个误导词），⛔ 且改名要同批改判据里的靶点 |
| **`PURPOSE-AND-FUNCTIONS.md` 一类"人话一页"** | **真的为人写的**，没有任何判据读它 | ✅ **可删**（⚠ 删前先证"没有任何机检读它" —— 既有铁律 `UD-144`） |
| **正文里的解释性铺垫** | 为让人看懂而加的类比、背景、"为什么这很重要" | ✅ 应删；⚠ 但**判据、约束、边界理由 ⛔ 不许当铺垫删掉** |

⇒ **判别法**：**删掉之后，有没有一条机检会红？** 会 ⇒ 它其实是机器读的，⛔ 不能删（只能改名）；不会 ⇒ 它才是"为人写"的，可以删。

## 边界

- ⛔ 本条**不解除**"给用户的回复要用常人语言写"（`UD-135`）—— 那条管的是**回复**，⛔ 不是账本；
- ⛔ 不解除任何判据、红线；
- ⚠ **落点与迁移**由 Hob 定，另记变更记录；⚠ **先只读盘点再动**。
