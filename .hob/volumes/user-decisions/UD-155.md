# UD-155 · 本项目是「管理项目的插件」⇒ 规则与骨架必须可复用，⛔ 不能只改本项目账本

**用户原话（逐字）**：

> 「还有注意当前项目本身就是一个用来管理项目的插件，所以很多的规则和框架骨架是需要在其他项目复用的，不能只调整当前项目的账本」

## 决定

| 项 | 内容 |
|---|---|
| **约束** | 本项目产出的**规则、判据口径、框架骨架**，凡属"任何被协助项目都该遵守"的那部分，**必须做成可复用层**并随插件分发；⛔ **不许只落在本项目的账本里** |
| **界线** | ⚠ **本项目专属**的东西（本项目的需求 / 方案 / 决策 / 验收件 / 专属判据）**照旧只属于本项目**，⛔ 不强行通用化 |
| **落地要求** | 每一项账本 / 规则改动，**同批回答一句**："这条要不要跟着走？走到哪一件载体上？"—— ⛔ 不许答"以后再说" |
| **判据** | 凡只改本项目账本、而可复用层没跟上的 ⇒ **视为未完成**（与 `UD-103` 同一条纪律） |

## 为什么（用户给的理由，照录）

本项目的产出物**本身就是给别的项目用的**：骨架、模板、契约、判断口径都是随插件分发的东西。
⇒ 只在自家账本上把毛病治好，等于**把经验锁在自己家里**；新建一个项目时，同样的毛病从头再来一遍。

## 与既有决定的关系

- `UD-103`：**改动不只改自己** —— 可复用层（骨架 / 模板 / 契约 / 判断口径）必须同批跟着走；
  ⚠ **本条是它在"账本规则"这个面上的再次确认与扩大**，⛔ 不是新口径；
- `CHG-047`：预设必须自带职责边界、改动连账本与可复用层一并照顾；
- `CHG-032`：账本与方案改「地图＋分卷、一事一文件」时，**骨架侧同批** —— 已有先例。
