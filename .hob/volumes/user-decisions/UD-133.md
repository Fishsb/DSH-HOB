### UD-133 · 2026-10-17 · 权限档位改名：功能名「可读权限控制」· 三档「账本权限 / 文档权限 / 完全权限」

- **决策内容**：把设置里那一组开关的**名字**改掉 ——
  **功能名**：`权限档位` → **可读权限控制**；
  **三档显示名**：`账本` → **账本权限** · `项目` → **文档权限** · `工作区` → **完全权限**。
  ⚠ **只改名，不改机制**：三档的**内部取值**仍是 `ledger` / `project` / `workspace`，
  **配置字段名**仍是 `permission.level`，volatile 形状（父不标 + 子标）一字不动 ⇒
  **已有用户档位设置继续有效**、**能读到哪里的范围也一字不变**。
- **用户原话（逐字）**：
  > 「权限档位 账本 项目 工作区，这三个档位名称改一下，账本权限，文档权限，完全权限，权限档位改成可读权限控制」
- **Hob 据原话裁定的四条（附依据）**：
  ① **「可读」是定性，不是扩权** —— 用户用「可读权限控制」四个字命名 ⇒
  ⛔ 不许借改名让它多出写 / 命令 / 组队；三档仍是**无写、无命令、无组队**（与 `UD-113` 一致）。
  ② **「完全权限」必须带限定句** —— 凡「完全权限」出现在**用户可见处**，**紧邻**必须有：
  **完全权限 = 工作区里任何文件都可读，仍然不能写、不能执行命令、不能组队。**
  依据 **R-26**（只写名字不写守的方式，读者会把「读得更多」误读成「权限更大」）。
  ③ **内部标识不改** —— 取值 / 字段名 / 白名单 / 哨兵 / 模块开关全不动。
  理由：改名是**界面与文档口径**的事；动内部取值会让已有设置失效，且要连带改 schema、白名单、机检三处。
  ④ **记录类文本不追改** —— 轮次记录、既有 `CHG` / `UD`、`archive/**`、经验库历史条目一律保留旧称。
  理由：那些写的是「当时是什么」，改它就是伪造历史 ⇒ 新名只进**现行正文** + 本条 + `CHG-059`。
- **落点**：落实为 **CHG-059**（代码显示文本 + 骨架可复用层 + 方案正文 + 两处索引，同批）。
- **状态**：active
