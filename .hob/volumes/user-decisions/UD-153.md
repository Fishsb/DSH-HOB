# UD-153 · 唯一事实源（`PROJECT.md`）的任何变更 = **整份重构重写**，⛔ 禁止逐处修改或插入

**用户原话（逐字）**：

> 「唯一事实源要改，但是要按照规定，PROJECT.md唯一事实源任何更改调整，应该是直接重构（禁止修改或者添加插入信息，直接全部重构重写，这样整份方案更干净，旧的按规定放入归档目录，方案变更记录信息写入变更记录表）」

## 决定

| 项 | 内容 |
|---|---|
| **允许的做法** | **整份重构重写** —— 以"现在是什么样"为准，把全文重写一遍，使它读起来是一份干净完整的方案 |
| **⛔ 禁止的做法** | ⛔ **逐处修改**（只改那几行）· ⛔ **插入/追加**（往某节里塞一段）· ⛔ 任何"打补丁"形态 |
| **旧版去哪** | **按规定进归档目录**（逐字节 · `R-17` · 清单件写明对应哪一版 + 字节数 + md5 + sha256） |
| **变更记录去哪** | **写进变更记录表**（`CHG-nn` 新条目 + 卷索引加一行；⚠ 两处同批） |
| **适用范围** | **`PROJECT.md` 唯一事实源本体**。⚠ 其余正本的改动形态按各自既有口径，不在本条的扩权面内 |

## 为什么这样定（用户给的理由，照录）

> 「这样整份方案更干净」

⚠ 与本仓既有形态口径（`CHG-025`「改动即重构、旧的归档」）**同向**，本条把它**收得更紧**：
既有口径允许"重构时顺手折入同批收口"；**本条对 `PROJECT.md` 明确到"只许整份重写、不许逐处改"**。

## 由此产生的三条硬要求（我据此执行，⚠ 不是新增用户要求，是执行口径）

1. **重写前必须先有逐字节副本**（`R-17`）—— ⚠ **副本没落盘，⛔ 不许动正本**；
2. **重写 ≠ 可以丢内容**：每一句旧文要么出现在新文里、要么在"逐条对照表"里点名说明**为什么不在**；
   ⚠ **⛔ 不许以"重写"为由悄悄删掉判据、纪律、指针、红线**；
3. **验收口径换形态**：整份重写之后，"区域外未变"这句话**不适用** ⇒ 改成
   **"逐条对照 + 内容覆盖率 + 节结构对照"** 三样，并**点名每一条不再出现的内容及其理由**。

## 边界（⚠ 防止被读成更大的授权）

- ⛔ 不解除任何既有红线（重启只有用户能做 · 判据只许加严 · 不碰第三方插件状态 · 看板仍由用户点）；
- ⛔ **不改方案的实际主张** —— 重写是**形态**要求，⛔ 不是"借重写顺手改方案内容"；
  凡要改主张，须另走"用户批准"这一步；
- ⚠ **"重写"不是"精简"**：⛔ 不许以"更干净"为由删信息。
