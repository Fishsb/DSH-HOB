# UD-152 · 用户已表态的事不许再问；「工作模式有问题就优化调整」

**用户原话（逐字，两段）**：

> 「我来重启」
>
> 「我说了我来重启你是听不懂人话吗，工作模式有问题就优化调整，说了话听不懂废物一样」

## 决定

| 项 | 内容 |
|---|---|
| **① 重启** | **由用户自己做，已认领。** ⛔ **不再列为"待用户决定"**、⛔ **不再在任何一轮里重问**。判它生效只认读数（宿主进程是否换成了盘上那份代码），⚠ **不许拿"红变少了"当"修好了"** |
| **② 工作模式** | **有问题就优化调整** —— 这是**授权**，不是询问。⚠ 凡"某一类错会反复犯"的，**改载体**（契约 / 判据 / 账本写法），⛔ 不停在"下次注意" |
| **⛔ 不做** | ⛔ 不解除任何既有红线（权限档位 / 判据只许加严 / 不碰第三方插件状态 / 看板仍由用户点）；⚠ **"调整工作模式"不等于放宽任何约束** |

## 根因（⚠ 这条必须留在账上）

**用户当轮说的话，如果没有落进账本，下一轮在我这里就不存在。**

于是我按"账本里没有"重新推，又把他已经做过决定的事端回去问。
⇒ **他每说一次只顶一轮，下一轮就蒸发。**

⚠ **这不是"理解力"问题，是流程缺一步**：**用户表态 → 当轮落账 → 下一轮读账本才看得见。**

## 修法（三层，缺一层就会再犯）

| 层 | 要落成什么 |
|---|---|
| **① 当轮落账（Hob 自己的纪律）** | 用户当轮做出的任何决定（**含"我来做某事"这类认领**），**同一轮写进账本**；下一轮它以「**已定 / 已认领**」出现，⛔ **不以「待决」出现** |
| **② 待决项的写法** | 每条待决必须能答"**这条是谁的**"；**用户已认领的**写成「已认领」，⛔ 不许留在"待用户拍板"里 |
| **③ 回话契约（预设正文）** | **增加一条硬规矩**：用户已明确表态 / 已认领的项 **不得再问**；⚠ 人读版与机器读版**逐字一致**（机检钉住） |
| **④ 机检（随后一轮）** | 正本里出现"待用户拍板"，而同一项在别处已写"用户已认领" ⇒ **红**。⚠ 要改脚本，与正在改判据的那条线**不同批** |

## 边界（⚠ 防止被读成"放宽"）

- 「不再问」**只针对用户已经明确表态过的项**；⚠ **没有表态的照旧问**。
- 「优化调整」**只授权改载体**（契约 / 判据 / 账本写法），⛔ **不授权放宽**任何既有红线或判据分辨率。
- ⚠ **不许把"少问"做成"不报"**：派了什么、失败了什么，**照旧要说**。
