### UD-107 · 2026-10-14 · 项目终态澄清：Hob = 总助理（只沟通 + 管账本 + 检索 + 派任务）；设计公理入方案 §1.3

- **决策内容**（用户口述，逐字保留）：
  1. **项目作用**：「**当前项目的作用就是像一个团队一样协助我来做开发**」；
  2. **Hob 的角色**：「hob 模式就是一个**总助理**负责和我沟通，**管理方案以及账本**，
     根据和我协商去完善方案以及账本，然后根据整理的方案项目方案和我的需求**去推进项目的落地**」；
  3. **能力面四条**：**只和我沟通** · **管方案与账本** · **检索网络信息** · **按账本编排任务派给其他会话落实**；
  4. **⚠ 排除项**：「**拉团队不要在 hob 自己的会话拉团队**」—— Hob **自己不组队、不拉专家**；
  5. **设计公理（为什么这么设计）**：「**为了后期跨实例或者跨系统投递任务，
     还有为了避免单独会话上下文注意力的问题，hob 模式只根据账本和我沟通然后指派任务，
     这样上下文能在一定程度上很大的压缩，保持一个主线注意力**」；
  6. 用户自陈：「**可能我说的不准确，不明确的可以和我沟通**」。
- **用户原话（逐字）**：见上六条（第 1 / 2 条与第 5 条已整段落进方案 §1.3）。
- **⚠ 本条同时更正 Hob 的一处误判（如实登记）**：
  Hob 曾据第 1 条里的「像一个团队一样」，**判定方案方向被写反、并提议放开团队工具** ⇒ **错误**。
  经第 4 条澄清：**团队 = 被 Hob 派出去的那些会话**；**Hob 自己拉团队恰是设计要排除的**
  ⇒ §4.3 / §4.5 / §6.1 三处既有条文**是对的**，⛔ **本条不构成对它们的改动授权**。
  **根因**：Hob **拿转述当原话**，未核用户原话即下方向性判断（该误判**未进任何提交**）。
- **影响**：落实为 **CHG-051** ——
  `§1` 新增 **§1.3 设计公理**（含用户原话逐字）· `§4.3` 给"不拉团队"**补理由**（条文一字未动）·
  「跨实例 / 跨系统」**全族 8 处**收口（§3 / §5 / §8 / §9）· `§11-13` 范围写明两件。
  ⛔ **不动代码 / 白名单 / 预设**（能力面经核**与终态四条完全相符**）。
  收尾 **11 条命令全 `EXIT=0`**；覆盖面 N / O / L / M / P 与改前一致。
