# CHG-068 · 在途任务书移出归档路径（落点/命名/迁移/判据四条自决）

## 一、决定了什么

| # | 项 | 决定 |
|---|---|---|
| **1** | **落点** | **`queue/<状态>/<YYYY-MM-DD-slug>/`** —— ⚠ **`queue/` 在账本区根**，与 `volumes/`、`archive/`、`runtime/` 平级 |
| **2** | **状态目录** | **只有两个**：`queue/doing/`（在跑）· `queue/todo/`（尚未开工）。⚠ **⛔ 不设 `done/`** |
| **3** | **完成时怎么走** | 交回件落齐、我验收之后 ⇒ **整个目录 `mv` 进 `archive/`**（⛔ 不是复制、⛔ 不留残件在 `queue/`） |
| **4** | **判据** | ⚠ **`archive/**` 下不许出现"看起来还在跑"的任务书**：归档目录里的 `TASK.md` **必须在其中写明"已收口"或"作废"** 且**指向它的验收件**；⚠ **`queue/` 下不许出现已完成件** |

## 二、为什么这样定（四条，都对应本项目实况）

1. **为什么不是"在 `archive/` 里加一个 `doing/` 子目录"** ——
   ⚠ `archive/` 的语义是"**改动前一份 / 已完成件的落脚处**"（`CHG-026`），并**已机器化**（`check:archive` 逐字节比对）。
   往里塞在途件会**污染它的语义**，还会让"哪些该逐字节核、哪些不该"变得含糊。
   ⇒ **分开两个根目录，比在一个目录里加例外干净。**

2. **为什么 ⛔ 不设 `done/`** ——
   设了 `done/` 就等于允许"已完成但没归档"这种中间态存在，而它**会一直存在下去**（没人有动力去搬）。
   ⇒ **完成 = 搬走**，⛔ 没有第三种状态。

3. **为什么只分 `doing` / `todo` 两档** ——
   ⚠ 档位越多，越会有人靠"放错目录"来表达模糊状态。两档的判别是**事实性的**（有没有在跑），不是判断性的。

4. **为什么判据要盯两半** ——
   只盯"归档里有没有在跑的" ⇒ 会漏掉"`queue/` 里堆满已完成件"；
   只盯"`queue/` 里有没有已完成件" ⇒ 会漏掉"归档里躺着一份还写着'待办'的任务书"。
   ⇒ **两半互相兜底**，与既有的"两边一致 ≠ 东西还在"（需成对判据）同一条思路。

## 三、迁移怎么做（⛔ 不在本单执行）

- **只迁"在途"的那几件**；已完成件**原地不动**（`archive/` 里已有的不动 —— 那是历史，⛔ 不改历史）；
- 迁之前**逐份留字节读数**（`wc -c` + `sha256`），迁完逐个核**逐字节一致**；
- 迁完在那几份任务书**开头加一行状态**（`状态：doing` / `todo`），⛔ 不改正文；
- ⚠ **历史件里那些"看起来还在跑"的**：⛔ 不搬（历史不动），改为**在归档清单件里点名**其真实状态。

## 四、影响面

1. `CONTEXT.md` 的账本区根成员描述要加 `queue/`（**一行**，⛔ 不许展开）；
2. `check:archive` 的扫描面**不含 `queue/`**（它是归档一致性判据）⇒ 新增一条**独立**判据盯 `queue/`，⚠ 属下一批；
3. ⚠ **本 CHG 只登记决定**，迁移与判据另起单；两条线**不同时落盘**（顺序约定，见 `CHG-067` 相关裁定）。
