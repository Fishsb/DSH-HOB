### CHG-031 · 2026-10-11 · 检查脚本按族拆分（薄调度入口 + 按族拆开的模块）
- **触发原因**：用户就"`check:gitignore` 是否拆分"拍板 —— **拆**（**UD-93**）。
  该脚本此前**一个文件承担全部判据**（入库与仓规 · 正本形态 · 源码静态面），
  且**脚本名与实际职责已明显偏离**（名字说"gitignore"，实际**大半在读正本**）；
  执行方**连续三轮**把它提上来，Hob 每次都因"须用户拍板"而未动。
- **用户原话（逐字）**：「**① 拆分那个检查脚本**」
- **审查结论**：同意。**定性为一次纯搬运** —— 判据**一条都不改**、**一条都不放宽**、**不顺手修 bug**。
- **调整内容（**现行结构**）**：
  1. **入口 = 薄调度**（`scripts/check-gitignore.mjs`，**名字不变**）：只做 CLI 直调 + 按族依次调用 + 汇总输出与退出码；
  2. **按"读什么"分族**（⛔ **不为对称硬切** —— 各族**数据源互不相干**，**名单见 `package.json` 与 §10.5**）：
     - **`check-repo-rules.mjs`**：**仓库规则族** —— MUST-TRACK / MUST-EXCLUDE · 骨架覆盖 · **脚本落点双向自检**
     - **`check-doc-shape.mjs`**：**正本形态族** —— A / B / J / C / D / D′ / E / I
     - **`check-code-face.mjs`**：**静态面族** —— K / F / G / H
  3. **那些模块属"纯库"** ⇒ 按既有纪律在**脚本落点自检的显式白名单里登记 + 写明理由**
     （该白名单**自身防腐烂**：幽灵条目 / 自相矛盾条目同样 FAIL）；
  4. **断言 K 的检查侧基准点同步指向搬家后的真实位置** ——
     ⚠ **不同步 ⇒ K 因"提取不到"而 FAIL**，**这正是它自带的保护**（它不会静默）；
  5. **同源字面量逐字未动**（`D_REF_RE` / `D_TASK_RE` 只换位置、不换字）；
  6. **`src/` 与 `scripts/` 仍是两棵互不依赖的树**（架构红线）—— 各模块只互相 import，**不跨树**。
- **现行硬规定（由本条升格）**：**入口名是契约** ——
  拆分类改动**不许改入口名**：它被**纪律登记表第 3 列**、方案、账本多处引用，
  **改名 ⇒ 断言 F（归属必须指向存在的检查）当场 FAIL**，直接死锁。
- **验收判据（现行，适用于一切"机械搬运"）**：**拆前拆后逐组输出逐行比对**。
  ⛔ **不许用"退出码 0"代替这一条** —— **搬丢一整组时很可能照样是 0**（该组的 ✗ 永远不出现）。
  配套四件：**先存基线（含不可变副本）** · **负向对拍（该咬的仍咬）** · **"改哑"对照** · **还原逐字节**。
- **⚠ 本条的实证案例**：第一次切片**直接崩**（`ZERO_WIDTH_RE is not defined`）——
  **按行号机械切分**会把夹在两块之间的**模块级声明"吞进"函数体**（**作用域悄悄变了**）；
  ⚠ **两个静态关口都放行**：`node --check` 全过（那是**运行时**错误、语法合法）、逐段首尾核对也对
  （切片边界没错，错的是**作用域归属**）⇒ **是基线 diff 当场抓住的**。**E-132**。
- **状态**：**已生效**（**逐行比对通过 · 负向对拍照旧咬人 · "改哑"对照被抓 · 收尾全绿**）
- **关联**：**UD-93** · CHG-028 · CHG-030 · E-132
