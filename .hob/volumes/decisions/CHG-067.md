# CHG-067 · 文档噪音治理：外部实践逐条对照后的采纳与不采纳

## 一、背景

用户提供了一份外部结论（另一 AI 检索汇总）：过程记录与现状混在一起 ⇒ 下一个会话把**过程性记录误读为当前事实**；
并给出三层结构、归档出阅读路径、清理绑进"完成"的定义、定期只读审计等做法。
本条是**逐条对照本项目**之后的取舍登记，⛔ 不是照抄。

## 二、采纳（四条，都是我们确实缺的）

| # | 采纳什么 | 为什么我们缺 |
|---|---|---|
| **1** | **"任务层"必须独立**：**在途计划**自成一层，⛔ 不许与"已完成"同处一目录 | ⚠ 本项目**在途任务的 TASK.md 全落在 `archive/<日期>-<名>/`** —— 与已完成件**住在同一个目录**。而"一份所有步骤都已打勾的计划，读起来是事实，本质是过时的意图" ⇒ 这正是我们**每一份归档 TASK.md 的形态** |
| **2** | **"半开放状态"短语单列严判**：`目前不用` · `暂时停用` · `等待合并` · `暂未开放` · `待重启` · `暂缓` —— **要么明确定为"永久不要"，要么连同引用一起清除** | ⚠ 这类比"过时"**更危险**：它**看起来像已经处理过了**。⚠ 现有词表虽有"暂时/暂未"，但**没有"必须二选一收口"这条判定** |
| **3** | **读者视角判据**，与现有的"动作敏感性"判据**并列** | 现有判据问"会不会因外部动作变假"（作者视角）；这条问"**删完之后，剩下的每一行，下一次会话能否字面理解为当前真实**"（读者视角）。⚠ 后者更严，且能抓住前者抓不到的"读起来像事实的意图" |
| **4** | **定期只读审计 + 把它写进"完成"的定义** | 三只报警器判的是**形式**；"与代码矛盾的陈述"只有**读**才能发现。⚠ 且"完成"必须包含"**没有把过程性记录留在权威文档里**"，否则清理永远是额外劳动 |

## 三、不采纳（三条，理由都是本项目实况不同）

| # | 不采纳什么 | 理由 |
|---|---|---|
| **1** | 引入 `doc-cleanup` / `context-curator` / `cursor-memory-curator` 等现成工具 | `UD-82`：**本项目不碰第三方插件的状态**；且审计面是**我们自己这套账本**（地图 + 分卷 + 判据靶点），通用工具不认识它 |
| **2** | 「文档只写**代码说不出口**的东西」 | ⚠ 本项目账本是**项目管理层**：需求、方案、决策、验收 —— **代码说不出来**。⇒ 改口径为「**只写当场量不出来的东西**」 |
| **3** | 「历史交给 Git」 | ⚠ 本账本区**长期大量未提交**（多处 ` M` 在途）⇒ Git 历史**不是**可靠的历史层。我们的 `sources/` + 清单件（逐字节 + md5/sha256）**比 Git 硬** |

## 四、用它量了一次我们自己的账本（⚠ 三处现存同类）

按第 3 条那条判据读 `CONTEXT.md`，至少三处"读起来像当前事实、其实是会立刻变假的判断/意图"：

1. **`§2.4` 表尾「本表在途项 = 无」** —— 一次派活就变假；这正是 `CHG-030` 明禁的形态，却仍在；
2. **`§2.4` 节标题「待派单 / 在途」** 与表尾「须用户裁的 = 第 49 项 + 总表那 17 条」 —— 同上；
3. **`§2.1b` 各格里的"仍未验 / 判不出"** —— 它们是**状态**，不是事实；⚠ 目前靠"两栏分家"缓解，但仍在状态页正文里。

⇒ **这些不是"我们没规矩"，是"规矩没有机器守"。** 三只报警器（另一轨）正是为这个。

## 五、影响面（落笔安排）

- 第 1 条（任务层独立）**需要定落点** ⇒ 另起一件，⚠ 不在本 CHG 里定；
- 第 2、3、4 条写进**规则卷**（`volumes/context/11-ledger-rules.md`，另一轨正在出候选）⇒ **等它回来后一并并入**，⛔ 不并发改同一份文件；
- 本条**只登记决定与取舍**，⛔ 不代为落笔。
