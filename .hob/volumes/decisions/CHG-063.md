# CHG-063 · 方案新增 §14「派发与回执契约」：把核心承诺从"只有实现"补成"有契约可对照"

- **状态**：已生效

## 一、为什么立这一条（⚠ 用户裁定）

用户原话：

> 看下这个HOB会话，一直有重复回执是什么情况，当前项目的工作模式还是有问题，从方案找问题梳理重构

随后在给的选项里选定：**「方案补一节「派发与回执」契约」**。

⚠ **背景（为什么不是"再修一轮代码"）**：
"派发 → 跑完 → 回执回到派单方"是**本项目的核心承诺**（§1 设计公理 · §4.2 闭环派活），
但方案里**只有"能投递什么"，没有"投递之后的账怎么算、怎么清、怎么读"**。
⇒ 后果是**每一轮修好的东西，下一轮会因为"没有条文可对照"重新长回来**：
`2026-10-19` 到 `2026-10-20` 之间，这条链上先后修过 P1 / P2 / W3 / W4 / W6 / W9，
而同期又新长出 **D3 那类通道混用**（内部回执被"不许给自己发消息"挡下）、
**量纲混装**（此刻 vs 累计并排）、**计数按读次累加**（22 → 3053）三处新缺陷。
⇒ ⚠ **判定：这是"缺少契约"的必然后果，不是"修得不认真"。**

## 二、改了什么

**新增方案正文一卷**：`volumes/plan/14-dispatch-and-receipt-contract.md`（9027 字节）。

| 块 | 内容 |
|---|---|
