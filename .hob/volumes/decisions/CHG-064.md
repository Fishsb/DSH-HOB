## 一、决定

**跨实例通信（M6a）不再是本项目的能力**，从"已实现 · 保留不扩建"改为**退场**：

1. **代码删除，⛔ 不是"留着不宣传"** —— 模块本体、入口登记、`provide`、投递路径里的跨实例分支、只为它存在的类型与常量、配置面三项（schema / 补丁文件 / 设置面板卡片）、判据族 `check:policy-cross` 全部拆除。
2. **不保留任何"将来可以捡回"的代码面勾子** —— 捡回的方式是读历史修订，⛔ 不是在当前树里留一块没人用的代码。
3. **旧安装兼容**：已装用户配置里残留的两个键按**容忍未知键**处理（不崩、不抛错退出），⛔ 不为此写显式迁移逻辑。

## 二、为什么这样定（不是偏好）

- **它不是"暂时不做"，是"不要"**：把它继续挂在"已实现 · 保留不扩建"下面，读者会认为它是一件随时可以打开的能力；而实际状态是**零消费方、缺省关、没有真实调用路径**。这两句话不能同时成立。
- **零消费方的代码不是资产，是负债**：它挂着一条"按发起会话判权限"的准入判定，是项目里唯一一处会在**跨进程**方向消费读档策略的地方；留着它，每次改动读档策略都得连带照顾它，而它并不提供任何用户可见的能力。
- **与读档红线方向相反**：它的准入面天然朝"跨出去"生长，而本项目当前的取向是**收紧**（新建只开放最低可读档）。少一个朝外生长的面，风险面就少一处。

## 三、边界（⛔ 不许被读成范围更大的取消）

- **跨系统通信（M6b）⛔ 不在本件内**：它本来就是**暂缓、无实现**，口径不变。⛔ 不许把两者合并成一句"跨实例/跨系统都不做了" —— 那会把一件"有实现被删"与一件"从未实现"搅成一件事。
- **M1 / M3 / M4 / M5 / C1 的既有行为与接口一格不动**；删 M6a 只删它自己。
- **可读权限三档、四个只读工具、写类工具的结构性不可达**：一格不动。
- **第三方插件 `dsh-interconnect` 的 4 个工具名保留在屏蔽名单里**：那是**deny 名单**（把宿主平面继承来的工具摘掉），删掉等于在"将来装了那个插件"的情形下**放宽** Hob 的工具面 —— 与三档不放宽的红线相反。⇒ **名字留着、注释写明"第三方，与本项目已退场的自研跨实例投递无关"**。

## 四、可以预见的代价（照实记，不许事后当成意外）

1. **判据覆盖净减少**：`check:orch` 的 `SS` 组整组删除（`-166` 行 / 约 `5` 条断言，`230 → 227` 条）。它专测已删模块的装载与诊断文案 ⇒ 模块不存在则无测对象。**选择删而非改成静默跳过**（本仓禁止"静默 skipped 当成功"）。
   ⚠ **由此留下一个真实的口子**：以后**"某模块压根没装载、服务静默缺席"这一类还能不能被人发现**，不再有专门断言守着。本件登记为**已知覆盖缺口**，⛔ 不当作已解决。
2. **族数下界下调**：`check:all` 的族数下界 `20 → 19`。这是一次**主动降低判据数量下界**的动作，理由是被删族确实不存在了；⛔ 不许把它当先例去下调别处。
3. **一次性不可逆**：删掉的是一段**曾在隔离实例上真跑通过**的东西。将来若又想要，代价是重建，不是翻开关。

## 五、未做 / 未验（⛔ 不许说成已上线）

- **运行实例还没跑上新代码**：删除类是"改了盘、但进程里那份代码还在"的典型 —— `npm run build` 只写 `lib/`，宿主进程仍在跑旧逻辑；⇒ **不重启则那段代码仍在内存里活着**。
- **重启只有用户能做**（红线），本件不代为决定。
- **正本正文尚未改完**：本件立了决定；`PROJECT.md` 概览、`volumes/plan/04` `05` `08` `09` `13` `14`、`REQUIREMENTS.md` 对应条目、`CONTEXT.md` 的模块表与收尾命令表**按 R-17 的顺序逐份改**（先逐字节落改前副本、再动正文）。
- ⚠ 因此**在那些正文改完之前，账本里仍会有"跨实例保留"的旧句**。它们不是漏改，是**尚未轮到**；判"这一版到底怎么算"以本件为准。
