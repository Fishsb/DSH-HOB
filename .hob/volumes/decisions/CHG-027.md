### CHG-027 · 2026-10-10 · 「待投递」中间态落盘：让"写了交接文件却没投递"不再静默
- **触发原因**：用户指令 —— **"偶尔会忘记派发任务、或没有派发任务"要排查成因并优化**。
- **用户原话（逐字）**：「这个偶尔会忘记派发任务或者没有派发任务的情况也需要排查一下是什么情况导致的看可不可以优化一下」
- **排查结论（根因，三段）**：
  1. **动作被拆成两步、中间无耦合** —— `write_hob`（写交接文件）与 `hob_dispatch`（投递）是**两个独立的工具调用**，**没有任何东西**要求"写了就必须投"；
  2. **🔴 漏掉第二步时，系统里没有任何记录** —— `watches` **只在投递成功之后**才登记（`src/modules/orchestrator.ts` 的 `dispatch`）⇒ **"写了但没投"这件事根本不存在** ⇒ 状态输出**无法把它与"无事可做"区分**；
     ⚠ **与已修过的缺陷同形**：`src/server/orch-state.ts` 的注释逐字记着"重载抹掉 watch"那次**现场读数相同**（「与"从来没派过"完全无法区分」）—— **那次是"记录被抹了"，这次是"记录从来没有"**；**同一个病：该记的事没记**。
  3. **回复形态掩盖它** —— 派活方按契约输出指令段 ⇒ **从用户视角看已交付** ⇒ 漏派**不报错、不显形**。
- **⚠ 该疏漏在修复前已发生两次**：第 9 轮 / 第 21 轮（**两次都是用户发现的**）。
- **审查结论**：同意，并**确立"加记录、不加口号"的处置方向** —— 本项目明规「**能机器核的不要靠人记**」（E-108③），而这条**已靠人记失败两次**。
- **调整内容（**现行口径**）**：
  1. **运行态结构新增 `handoffs`**（`src/server/orch-state.ts`）：`kind: 'task-file' | 'spawned-session'` · `ref` · `at` · `note?` · `wsRoot?`；**逐字段收窄**（纪律同 `asWatch`）；**读侧向后兼容**（旧文件无该字段 ⇒ **空数组**，不抛、不判坏）；**`writePending` 必须保留 `handoffs`**（覆盖掉就等于又变成"从来没写过"）；上限 `MAX_HANDOFFS = 50`（运行态、非审计日志）
  2. **记 / 清的落点**（⚠ **分层纪律**：`hob-write.ts` **刻意不 import** 运行态模块 ⇒ **落盘层不碰 orch-state，由工具层记账**）：
     - **记** `task-file` = 写交接文件成功（`src/modules/tools.ts` 的 `write_hob.execute`；`hob-write.ts` 只**多回一个可判定字段** `handoff?`）
     - **记** `spawned-session` = `hob_spawn` 成功（`src/modules/bus.ts`）
     - **清** = `hob_dispatch` / `hob_send` **投递成功**（`orchestrator.ts` / `bus.ts`）
  3. **匹配细则**：`spawned-session` 按**目标会话 id === ref**；`task-file` 按**投递发生在其 `at` 之后**（**不去猜"这条消息投的是哪个文件"**；**绝不按消息文本含路径匹配**）；**保守方向 = 宁可少清**（清错 = 把真漏派抹掉 = 本缺陷复现；多报一条只是多一句提示）
  4. **`hob_orch_status` 报出待投递**（新增一段）；⚠ **空态也要给读数**（`待投递：0 份`）—— **让"没有漏"也是可读的**（这正是本缺陷的病根：`0` 与"没记录"曾不可区分）；提示语点明「**若本轮打算人工转达可忽略；否则说明漏了投递**」
  5. **写入成功那一刻的提醒**（`hob-write.ts`）：写成功的 message 尾部**追加**「⚠ 这是交接文件：**尚未投递** —— 写完本轮回复前先 `hob_dispatch` / `hob_send`（或明确告知用户需手工转达）。」
     ⚠ **只是提示、不是闸门**（不改写入语义、不拒写、**新增而非替换**既有字段）；提示语**不含内部标识**（它会被复述给用户）
  6. **机检新增断言组 F**（`scripts/check-orch-state.mjs`）：写文件 ⇒ 出现记录 · 投递成功 ⇒ 记录消失 · **旧结构文件读得进且读成空数组**；
     ⚠ **"真跑函数"而非文本匹配** —— 本轮的缺陷形态（"`writePending` 忘了保留 `handoffs`"）在源码里**字样仍在**，正则照样 PASS；
     **三组负向对拍**全部 FAIL + exit 1，还原**逐字节一致**（`cmp` exit 0 + md5 相同）
- **⚠ 负向对拍的实际收获（已写进经验）**：对拍**当场抓到机检脚本自己的缺陷** —— 坏产物让脚本抛 `TypeError`、**只剩堆栈而无 FAIL 行**。⇒ **已修为防御式取值**。**教训：对拍的价值不只在验证产物，也在于验证检查器能否"失败得清楚"**
- **不做（边界，如实）**：⛔ **不做硬闸门**（"没投递就拒绝写文件" / "到点自动投递" / 给人工转达加显式清除入口）—— 均属**新增机制**，须用户拍板；本变更**只加记录与提示**
- **状态**：**已生效**（**记 / 读 / 清已真机验收** —— 当场实测通过）
