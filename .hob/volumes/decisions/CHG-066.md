# CHG-066 · 账本形状两项决定：口径卷独立 · 两本历史保持分家

## 一、决定了什么

| # | 决定 | 出处 |
|---|---|---|
| **1** | **写法口径整套移入独立卷**，`CONTEXT.md` 不再承载它；⚠ **`§4.1 收尾必跑命令表` 例外留在 `CONTEXT.md`**（判据靶点） | 用户授权 Hob 自决（「根治 + 边界清晰」） |
| **2** | **两本历史（`CHG` 技术变更 / `UD` 用户决策）保持分家，⛔ 不合并** | 同上 |

## 二、为什么这样定

**决定一**：现状把五种寿命不同的东西装在一份文件里（写法口径永久 · 地图稳定 · 状态按小时变 · 收尾表按月变 · 本批登记稳定），
读者无法判断某段是"此刻为真"还是"永远为真"。**这是本项目全部状态句过期的结构性成因。**

**决定二**，三条理由都指向"边界清晰"：
① **作者不同**（`CHG` 是 Hob 的技术决定；`UD` 是用户原话）；
② **权威不同**（`UD` 是历史出处、⛔ 不是现行需求；合成流水会让读者以为两者同权）；
③ **不可改性不同**（`UD` 已被写入工具拒写，`CHG` 仍可新增；合并要放弃这条机械保护）。

⇒ **合并会亲手模糊一个现在清晰的边界**，与用户要的"边界清晰"相反。

**顺带定一条口径（回应"时间线乱"这个真问题）**：
读者真正要的不是时间线，是"**哪条还算数**" —— 那由**方案本体**回答；
`CHG` / `UD` 只回答"**为什么**"。补充措施 = 每条决定写清**取代关系**（取代了谁 / 被谁取代 / 至今未取代）。

## 三、账本职责边界（一句话判据 + 逐本落点）

**判别法**：这句话会不会因为**这份文件之外的一个动作**（一次构建、一次部署、一次重跑）而变假？
会 ⇒ **状态**，只准进 `CONTEXT.md`；不会 ⇒ 才可能是**事实或规则**。

| 账本 | 一句话职责 | ⛔ 不许放 |
|---|---|---|
| `REQUIREMENTS.md` | 用户现在要实现什么、可观察结果是什么 | 技术手段 · 进度 · 变更史 |
| `PROJECT.md` | 系统现在怎么搭、边界在哪 | 会立刻失效的状态字 · 进度 · 变更史叙述 |
| `CONTEXT.md` | 现在做到哪一步、还欠什么 | 写法口径 · 红线 · 变更史 · 已完成批次叙述 |
| `volumes/decisions/` | 当时为什么这么定（技术） | 对"现在是什么样"的描述 |
| `volumes/user-decisions/` | 用户当时说了什么（原话） | 任何解读 · 任何"还算不算数"的判断 |
| 纪律卷 + 新规则卷 | 开工怎么守、账本怎么写 | 状态 · 进度 · 变更史 |

## 四、影响面 / 需要跟着改的地方
