# CHG-073 · 账本落点定案：**工作区根下的独立目录 `ledger/`**，每个被协助项目一份

## 一、决定了什么（用户拍板 + 我补技术口径）

| # | 项 | 决定 |
|---|---|---|
| **1** | **落点** | **工作区根下的独立目录 `ledger/`**（⛔ 不在 `.hob/` 内）—— 用户拍板 |
| **2** | **`.hob/` 与 `ledger/` 的职责** | **两件不同的东西，⛔ 不许混**（见 §二） |
| **3** | **其他被协助项目** | **同一套约定，各在自己工作区根下一份**（见 §三） |
| **4** | **迁移顺序** | 先盘点 → 先在另一个项目上验 → **本项目最后**（本批已两次因"搬东西"打断引用） |

## 二、`.hob/` 与 `ledger/` 为什么必须分开

| | `.hob/` | `ledger/` |
|---|---|---|
| 是什么 | **干活的方法**：骨架说明、模板、角色方法论、契约、经验库骨架 | **这个项目自己的记录**：需求、方案、状态、决策、归档 |
| 份数 | **同一套**，所有被协助项目拿到的是**同样的 39 件** | **每个项目各不相同** |
| 随包分发 | ✅ **是**（`skeleton-manifest` 逐件钉 `sha256`） | ⛔ **否** |
| 能否含内部编号 | ⛔ 不许（`D-6`：发布物里不许出现 `CHG`/`UD`/轮次号/本机路径） | ✅ 当然可以 —— 它就是记录 |

⇒ **合并会同时坏两边**：账本进 `.hob/` ⇒ 骨架清单从 39 件涨到几百件（每改一次账本都要重算清单）、
且账本里的编号与本机路径**会随包发给别人**。

## 三、其他项目怎么办（⚠ 这是用户追问的那一问）

**一套约定，N 个实例。**

- **约定**（来自插件）：**"每个被协助项目的账本，放在它自己工作区根下的 `ledger/`"** ——
  ⚠ 这条约定写进骨架的 `INIT.md`（**它随包走**），所以**新项目一建就有这条**；
- **实例**（属于各项目）：`ledger/` 里的**内容**属于那个项目自己，进它自己的版本库，与别人无关；
- ⚠ **账本目录本身⛔ 不进骨架清单**（它不是"要发出去的东西"，是"到了那边才生出来的东西"）。

**⇒ 一句话：骨架告诉每个项目"把记录放这儿"，但骨架本身不带任何一条别人的记录。**

## 四、唯一一个需要额外处理的项目：**本项目自己**

`dsh-hob` 的工作区**同时是插件源码仓**（会被 `npm pack`）。
⇒ **本项目的 `ledger/` 必须显式排除在发布包外**（`package.json` 的 `files` / `.npmignore`）。
⚠ 其他被协助项目**没有这个要求** —— 它们的 `ledger/` 就是普通项目文档，**应当进版本库**（这正是迁回来的目的）。

⚠ **这是 dsh-hob 的特例，⛔ 不许把它写成通用规则**，否则每个项目都会以为自己的账本要藏起来。

## 五、迁移的硬要求（本批实证）

1. **先盘点**：`~/.dsh/hob-ledgers/` 下现在有**哪几个项目**的账本，逐个给体积与文件数；
2. **先在一个"别的项目"上试**：迁完要验三件 —— **引用不停断 · `check:archive` 逐字节仍对 · 打包不含它**；
3. **本项目最后迁**；
4. **每一步都按既有纪律**：先落逐字节副本 + 清单件（`CHG-072`：作业书第一条就是它）；
   ⚠ 迁移前**全仓检索旧路径**、同批改判据面、搬完复跑（`CHG-068` 三步）；
5. ⚠ **`ledgerHome` / `ledgerRoot` 这类配置要跟着改**（它们现在指向工作区之外）。

## 六、不做的事

- ⛔ 不把账本放进 `.hob/`（哪怕做子目录）—— 骨架清单与打包排除两处都要重写，且**漏一处就把账本发出去**；
- ⛔ 不同时迁本项目与别的项目；
- ⛔ 不在迁移里顺手改账本内容（迁移只搬位置）。
