### 7. 配置体系

### 7.1 分层

| 层 | 位置 | 优先级 |
|---|---|---|
| bundle 层 | 本包的 `cordis.patch.yml` | 低 |
| **profile 层** | `<profile>/cordis.patch.yml` | **同 id 条目整体覆盖 bundle 层**（不是合并） |

### 7.2 配置项

| 字段 | 含义 | 状态 |
|---|---|---|
| `modules.*` | **模块开关**（**真管用**：决定模块是否加载） | ✅ 生效中（`bus` 缺省 **true**；`orch` 缺省 **false** —— 两方向误判代价不对称） |
| **`permission.level`** | **可读权限控制**：三档显示名 **账本权限**（缺省）/ **文档权限** / **完全权限**，配置值 `ledger` / `project` / `workspace` —— ⚠ **只改"读到哪里"**（三档一律无写、无命令、无组队） | ✅ 生效中（**2026-10-14 · CHG-057** 建立三档；**2026-10-17 · CHG-059 / UD-133** 改名，取值与字段名不变；⚠ **改完即生效、⛔ 不必重启**）；⚠ **新建 Hob 会话只开放最低档**（另两档呈现但不可选，待宿主持久清理能力具备后开放） |
| `spawn.agentPreset` / `spawn.provider` / `spawn.model` / `spawn.reasoningEffort` | **新建会话默认值**四字段（**只影响本插件建出的会话**） | ✅ 生效中（留空 = 交还宿主默认） |
| `ledgerHome` / `ledgerRoot` | 账本区落点（**工作区之外**；缺省按工作区名派生）。⚠ **二者住预设行的 config，不在插件设置 schema 里** —— 面板不呈现，随预设层落地 | ✅ 生效中 |
| **推进项目的工作方式**（`workMode.mode`） | **自动 / 单会话 / 多会话**三档，只决定**怎么拆活与派活** —— ⛔ 不改读范围、⛔ 不改写边界 | ✅ 生效中（⚠ **现行是全局设置**；目标形态是逐会话，见下） |

> ⚠ **配置面只保留"真管用"的字段。** 曾经存在的 `persona` / `showEntry` / `delivery` **已全部删除** ——
> 它们**没有任何真实消费者**。**界面展示一个背后没有功能的"空旋钮"，是本项目明确要避免的失败形态。**
> ⚠ **新增配置字段必须带 `.volatile()` 且必须有真实消费者。**

⚠ **`spawn` 的形状**：**父对象不标 volatile、各子字段各标**（宿主禁止 volatile 里再套 volatile）；
模块侧**一律不许直读 `config.spawn.x`**（那是 ref 对象，直读**恒 truthy 且不报错**），唯一入口是收口函数。机检钉住这条形状。

⚠ **`permission` 的形状（与 `spawn` 同形，2026-10-14 · CHG-057）**：**父对象不标 + 子字段 `level` 标 `.volatile()`**；
⚠ **为什么必须 volatile**：非 volatile 的配置**改完要重启**，而"换档位"是**用户的日常动作** ⇒
**它必须走值型**（改完即生效）；⚠ **工具清单逐 step 现算**，所以已开着的会话**下一步就按新档位走**。
⚠ **代价（如实记）**：四个读工具**在注册面恒存在**（档 1 下只**不在模型面**）——
这是"不重启即可换档"的**必然代价**，⛔ **不许在后续轮次把它改回需要重启的形态**。
⚠ **同一条读取纪律适用**：模块侧**不许直读 `config.permission.x`**（那是 ref 对象），走收口函数。

**⚠ 现行值的地位：过渡期权威，不是目标形态**

这两个轴（`permission.level` 与推进工作方式）**按全局设置生效** —— 改一次影响**所有** Hob 会话。
⚠ **目标形态是逐会话**（见 §4.3「目标形态：两轴属于每个会话自己的选择」）：
创建时弹窗**分别**选定读范围与推进工作方式、归属该会话并持久化。⇒ 就此而言：

- ⚠ **新建会话的读范围只开放最低档**：**三档是呈现面**，另两档**照常呈现但不可选**（灰显 + 标「暂未开放」），
  **待宿主持久清理能力具备后再开放**（条件是「创建失败后重载，该会话既不能执行、也不能按更宽档位读出工作区文件」这对读数）；
  推进方式三档**不受此限**。⚠ **三档机制本身存在**、既有会话按最低档 —— 这两条照旧。
- **现行**：这两个全局值**仍是唯一运行权威**（⛔ 不许说它已作废）；
- **迁移后**：全局值**只允许作为明确的一次性迁移输入**（例如"把既有会话统一收紧到最低读档"），
  ⛔ **不能长期继续作为运行权威** —— 那等于"有弹窗但没有守卫"的中间态。
- ⚠ **面板控件的现状（如实）**：那两个**全局**控件（`PermissionCard` / `WorkModeCard`）**已下线、不再渲染**，
  只留一句"移到新建弹窗"的只读提示；⚠ **但配置字段保留**（`permission.level` / `workMode.mode` 是旧会话迁移的取值来源）。
  ⛔ **不许仿造第二个逐会话选择控件** —— 选择只在**新建 Hob 会话的弹窗**里做（见 §5.1），
  ⛔ 不再新开一处入口去改同样的事（那会变成"两处各说各话"）。
  （未实施项与剩余工作见 `CONTEXT.md` §2）。
- ⚠ **其余真实开关不受影响**：模块开关、`spawn.*`、`ledgerHome` / `ledgerRoot` 照旧；
  **普通实施会话**也不受这两个轴影响。

⚠ **取名与取值分两层（2026-10-17 · CHG-059）**：**三档显示名**（账本权限 / 文档权限 / 完全权限）是**给人看的**；
**配置值**（`ledger` / `project` / `workspace`）是**内部标识**，⛔ **不进对话文本、不给用户看**。
⇒ 已有的用户设置存的是配置值 ⇒ **改名不影响任何已有选择**。
