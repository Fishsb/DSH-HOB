### 13. 对外交付（**开源商用标准** · 2026-10-18 · CHG-062）

> ⚠ **本卷回答一个问题**：**外部人拿到这个项目，能不能自己装上、配上、用明白、报得出问题。**
> ⚠ **它不重复其它卷** —— 其它卷讲"内部怎么造"；本卷讲"对外交付什么"。
> ⚠ **依据**：`UD-136`（用户裁定按开源商用标准规划）· `CHG-062`（落点）。
> ⚠ ⚠ **边界**：本卷**只立标准与清单**，⛔ 不改任何已验收的功能行为；⚠ **M6b 仍按 `UD-123` 挂起**。

### 13.1 六条对外标准（判据式）

| # | 标准 | 判据（外部人视角） |
|---|---|---|
| **D-1** | **可安装** | 从**空环境**照文档能装上；⛔ 不依赖本机路径、⛔ 不依赖内部账本 |
| **D-2** | **可升级 / 可卸载** | 升级**不改用户已有的设置**；卸载后**残留目录与文件可点名清除** |
| **D-3** | **可配置** | 每个对外可见的配置项：**有默认值 · 有一句后果 · 空值有明确语义** |
| **D-4** | **可诊断** | 出错时给**一句可读的原因**（⛔ 不是堆栈、⛔ 不是静默）；失败面**能按类分辨** |
| **D-5** | **可贡献** | 目录与模块边界**对外讲得清**；判据入口**能一条命令跑**；⛔ 不要求读懂内部账本 |
| **D-6** | **不泄漏内部** | 发布物与对外文档里**⛔ 不出现**：账本区路径 · 轮次号 · `CHG`/`UD`/`E-` 编号 · 开发者对话引用 · 本机绝对路径 |

⚠ ⚠ **D-6 不是"删掉我们的记录"** —— 内部账本**照旧保留**（那是工作记录）；**只是不往发布物里放**。

### 13.2 对外可见面（发布物清单）

**进入发布物**：插件本体（`src/**` 的产物）· 预设声明 · 骨架的可分发层（`README.md` · `INIT.md` · `templates/` · `roles/` · `drafts/` 的契约）·
**对外文档**（安装 / 配置 / 已知限制）。
**⛔ 不进发布物**：账本区（`PROJECT.md` / `CONTEXT.md` / `DECISIONS.md` / `volumes/**` / `archive/**`）·
经验库的**历史条目**（`.hob/experience/**`）· `backups/` · `runtime/` · 本机的 `node_modules` 与 `lib/`。

⚠ ⚠ **判据**：拿"发布物"里的每一件，问一句 **「外部人读到这个，会不会撞见一个他不该知道的名字 / 路径 / 编号」** ——
会 ⇒ 该件**不许进发布物**，或先做对外化。
⚠ **这一条是 `UD-129`（分发面逐字节审查）的推广**：从"会离开本项目的件"扩到"**全部对外可见面**"。

### 13.3 **必须照实写**的已知限制

| 限制 | 对外怎么写 |
|---|---|
| **跨实例投递** | ⛔ **不许把跨实例投递写成支持或可用** |
| **改完代码是否立即生效** | 按 `dsh-hmr` 实况写：**运行中的产物在下次重算时被替换**；⚠ **`package.json` 的变更不被检测**；⚠ **preset 那半边替换时不做兼容性检查** |
| **上游是预发布版** | 写清：**本插件对标的上游是 `next` 通道**（⛔ 不是 npm 的 `latest`）；⚠ **相邻版本可能删 API 且无弃用窗口** |
| **读的范围三档** | 写清三档的**显示名**与**「完全权限」的边界句**（见 §4.3 / §6.1）—— 这是对外最容易被误读的一条 |

⚠ ⚠ **本节的原则**：**已知限制宁可写多，不许写少**。⚠ 对外写"支持"而实际不支持，是**商用项目最贵的错误**。

### 13.4 需要用户拍的四件（⛔ Hob 不代答）

| # | 待定 | 为什么只能用户定 |
|---|---|---|
| **1** | **License 选哪个** | 法律与商业选择 |
| **2** | **版本号从哪一档起** | 与"是否对外发布"绑在一起 |
| **3** | **是否发到公共包仓** | 发出去就收不回 |
| **4** | **对外名称是否仍叫 `dsh-hob`** | 品牌与包名冲突风险 |

⚠ 四件未定之前：**对外文档只写"内部预览"**，⛔ 不许写"正式发布"。
