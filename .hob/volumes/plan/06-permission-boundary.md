### 6. 权限边界

### 6.1 对称模型

| 区域 | Hob（规划侧） | 实施侧（任意会话） |
|---|---|---|
| 代码 | ❌ 禁区（**不能改**） | ✅ 读写 |
| 工作区文件 | 👁 **按可读权限控制**（`permission.level`，缺省 = **账本权限**）：**账本权限** ⛔ 不可见 · **文档权限** 👁 只读 **`.md`** · **完全权限** 👁 只读**任意文件**（含代码与图片）+ 列文件 + 跨文件搜索 —— ⚠ **任何一档都不能写** | ✅ 读写 |
| `.md` 文档 | 👁 只读（**账本区内**恒可读；**工作区**里的 `.md` 从**文档权限**起可读） | ✅ 读写 |
| **网页正文** | 👁 只读（**不含**宿主的 `web_search` —— 它在注册面、被白名单滤掉） | ✅ 读写 |
| **看板 / 圆桌** | 👁 **只读查询** —— **不能建卡、移卡、开会** | ✅ 读写（含改动状态） |
| **投递指令** | ✅ **可** —— ⚠ **投递 ≠ 执行**；目标须是**活**会话，由人指定（不自动挑） | — |
| **建会话** | ✅ **可**（**强制带工作区归属**）—— ⚠ **建会话 ≠ 委派** | — |
| **闭环派活** | ✅ **可** —— ⚠ **回传 ≠ 验收**；刹车是一等公民 | — |
| **并行隔离推进**（§4.5） | 👁 **只读回收 + 汇总**；**自己不建卡、不合并** | ✅ 建卡 · 隔离执行 · 会话内合并 |
| **派活 / 委派（拉团队）** | ❌ **仍无** —— 会话总线给的是**点对点投递**，不是组队 | ✅ 有 |
| **账本区** | ✅ 读写 | 👁 只读 |
| **命令** | ❌ **无** | ✅ 有 |
| **向用户提问** | ✅ **可** —— ⚠ **但契约要求尽量不问** | ❌ **禁**（**由指令文本承担**；**不做硬机制**） |

⚠ **口径：界线在"投的是话，不是改动"** —— `hob_send` 只调 `agent.followup`（写一条消息进对方 inbox），
**不碰任何文件、不改任何共享状态**。
⚠ ⚠ **并行隔离推进不破这条线**：Hob 在这一路上**只读**看板记录（`taskboard_get` / `taskboard_comments`），
**不新增任何工具、也不扩白名单**；建卡与合并都由**被派的会话**做 —— 所以它**不是**「Hob 有了组队能力」。

⚠ **档位只改「读」的范围，不改「写」的边界**（**2026-10-14 · CHG-057**）：
三档之间的差别**只有"能读到哪里"** —— **任何一档都不存在** `write` / `edit` / `bash` / `pwsh`。
⚠ ⛔ **不许把"档位更高"读成"权限更宽"**：档位再高也**不动写边界**、**不给命令**、**不给组队**。
⚠ ⚠ **这条在改名后尤其要守住（2026-10-17 · CHG-059）**：**「完全权限」这个名字只描述"可读范围最宽"** ——
**完全权限 = 工作区里任何文件都可读，仍然不能写、不能执行命令、不能组队。**
⇒ 凡在界面或文档里写出这个名字，**紧邻必须有这句限定**（`R-26`：只给名字不给边界，读者会把"读得更多"读成"权限更大"）。

⚠ **新建会话只开放最低档**：新建 Hob 会话的可读范围**只可选「账本权限」**；
**三档是呈现面**，另两档**照常呈现但不可选**（灰显 + 标「暂未开放」），
**待宿主持久清理能力具备后再开放**（条件是「创建失败后重载，该会话既不能执行、也不能按更宽档位读出工作区文件」这对读数）。
⚠ 推进方式三档**不受此限**；⚠ 三档机制本身存在、既有会话按最低档，这些不变。

**★ 逐会话读取与执行纵深（目标形态）**

**读范围属于会话、不属于实例**：每个 Hob 会话的读档应来自**它自己的可信标识**（创建时选定并持久化），
⛔ 不再由"一处全局设置改所有会话"。**写、命令、组队在任何一档都是零** —— 这条**与档位无关，永远成立**。

⚠ **执行纵深必须真的纵到底**（三条不变量，缺一条就等于"只有 UI、没有守卫"）：
① **同一个策略读取器**同时服务**模型工具清单** · **执行前拦截** · **宿主作用域守卫** ·
**四个自注册读工具自身的执行** · 工作方式口径；
② **无可信身份 / 策略缺失或损坏 ⇒ 保守拒绝**，⛔ **绝不回落到旧全局宽档借权限**；
③ **低档点名、嵌套路径、无身份直接执行**这三种形态，都必须**由工具自身兜住** ——
⚠ 前轮的模拟探针已证明：低档正常调用会被外层挡住，**但直接执行仍能读到目录 / 正文 / 图片**
⇒ 这是**迁移时必须消掉的缺口**（它**不是**已证实的真实用户越权，但**不许留在那里**）。

⚠ **旧会话收紧的语义**：切换时旧 Hob 会话的读范围**统一降到最低档**，其**原有工作方式不变**；
⚠ 必须**明确告知用户**读能力会收紧。⚠ **这是获批需求，不是已运行行为**（差距见 `CONTEXT.md` §2）。

⚠ **"不能写"是怎么守住的（取证方式要写清，别当成绝对屏障）**：**三件性质不同的措施** ——
① **不声明**：提供写类工具的包**不在本预设的声明面**；
② **不注册**：声明面里没有 ⇒ 本作用域内**连定义都没有**（"名字落到注册面"这一步就不发生）；
③ **不白名单**：即便前两条被绕过，**模型面清单**里也没有它们（⚠ 名数以 `check:presets` 的判定为准）。
⚠ **宿主平面那几行 `disabled: true` 由机检盯住** —— 否则写类工具会**静默回到注册面**。
⚠ 另加**单调执行哨兵**（`ctx.tools.guard()`，**fail-closed**、**只紧不松**）：它**只罩读工具**的路径 / 类型规则。
⇒ 本表读作"**现有机制下不可达**"，**不读作"物理不可能"**（**R-26**）。

⚠ **"Hob 无命令" ≠ "插件不能读文件"**：插件代码本身跑在**宿主 Node 进程**里 ⇒ **它有 `fs` 能力**
（`write_hob` 能写账本、能核引用、能**渲染读数**，正是这个原因）。
**能否跑子进程是另一件事**（三档一致：**没有**）。本表"命令 ❌"说的是**Hob 这个角色拿不到命令工具**。

### 6.2 技术实现

- 插件**只注册自定义工具**，不注册宿主原生 `read` / `bash` / `write`
  ⚠ Hob 的**声明面**里有若干宿主工具行 —— **声明 ≠ 本插件注册**：「定义与注册分离」这条纪律未变。
- 路径校验用 `path.relative`（**不用 `startsWith`** —— 根 `/a/b` 会错误放行 `/a/b-evil`）
- **不跟随符号链接**（**读侧也一律拒**）—— 软链路径仍在区内、真实目标在区外

### 6.3 权限收敛的一个硬事实

**预设会话拿到的是"它自己声明的工具 + 宿主平面继承来的工具"。**
实测：即使预设只声明极少数工具，**宿主平面注册的全局工具仍会漏进来**。
`tools.restrict()` 只能掩码**继承来的全局工具**；**本作用域自己注册的（`own`）既不能点名、也摘不掉**。
⇒ **收敛仍要靠"允许清单"思维，不能靠"封禁名单"**：封禁名单**永远追不上**别人新装的插件。

**三层收敛机制（实测现状）**：① **装配期过滤**（决定**发给模型的清单**）·
② **执行前拦截**（决定**调用能否落地**）· ③ **历史 deny**（摘**继承来的全局工具**）。
⚠ **2026-10-14 增补第四件**：本插件**自己注册的读工具**另加一层 **单调执行哨兵**
（`ctx.tools.guard()`，**fail-closed**、只紧不松，罩它们的路径 / 类型规则）。

> ⚠ 各层各有边界：① 只改"看不见"，**不改能否拿得到**；② 是**收敛措施而非安全边界**（fail-open）；
> ③ 够不到 `own`；④ 方向相反（fail-closed）但**同在宿主进程内**，**仍不是安全边界**。
> ⇒ 要"硬边界"须另做设计，**本版不做**。

### 6.4 宿主平台硬事实（现行）

> **"平台/宿主现在就是这样"的约束 —— 现行有效**，不是历史记录。
> ⚠ ⚠ **完整清单、机制细节与实测读数都在经验库**（`.hob/EXPERIENCE.md`）；
> 更早的历史读数见 `archive/2026-10-09-ledger-history/FACTS-final.md`。
> **下面只留会直接影响设计的那几条**：

| 事实 | 影响 |
|---|---|
| **插件形态**（装在宿主 profile 内，非独立实例） | 架构与部署口径（§2） |
| **同实例会话通信是宿主原生能力**；三种投递语义见 §4.2 | 核心能力不从零造 |
| **宿主 preset 不支持 `extends`** | "基于某预设" = **照抄 + 加料** |
| **预设首轮后锁定** | 换模式 = **换会话**（§4.4） |
| **`lib/` 被 gitignore** ⇒ 源码与产物漂移**在 `git status` 里不可见** | **改完 `src` 必须 build**（**R-1 / R-2**） |
| **自建预设显示名不参与本地化** | 语言规则只能落在**模型输出**（§4.3） |
| **宿主平面注册的全局工具会漏进每个预设；`own` 摘不掉** | 收敛靠**允许清单**（§6.3） |
| **装配期过滤 = "看不见"，不是"拿不到"**（越权调用实测可成功） | ⚠ **不是安全边界**（§6.1） |
| **宿主看板自带隔离执行**：建卡可带 `isolation:"worktree"`，看板**到点自动点火**、自建执行会话、在独立 worktree 里干活 | **并行隔离推进复用该通道**，⛔ 不自建隔离（§4.5） |
| **`npm install` 会静默剪掉未声明的依赖** | 装依赖用 `--no-save` 并复跑 typecheck |
| **样式必须"字符串注入"而非 `.module.css`** | 插件路由只服务 `client.js` |
| **生效性按"半边"判断**；`--dump-config` 是离线读盘 | §5.3 |
| **PCL 启动器的 Windows 侧"启动 Harness"按钮已失效**（profile 名写死在二进制里） | 该路不通 |
| **本仓是纯本地仓、没有 `origin`** | archify 证据链口径（§10.6） |
