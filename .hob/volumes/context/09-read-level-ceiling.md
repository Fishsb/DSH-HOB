## 一、用户裁定（唯一来源）

`archive/2026-10-22-read-level-ceiling/USER-WORDS.md` —— 用户选「安全优先」：
**新建 Hob 会话的可读范围只开放最低档（账本权限）**；推进方式三档**不变**；
另两档等**宿主具备可靠的持久清理能力**后再开，条件是成对读数：
**创建失败后重载，该会话既不能执行、也不能按宽读档读出工作区文件。**

⚠ 理由（不是偏好）：宿主 `SessionPersistence` **没有 delete/remove**
（只有 create/flush/list/open/stat），`AgentHandle.dispose` 只撤活表、磁盘 JSONL 仍在
⇒ 创建失败时若策略隔离与宿主归档同时写失败，已落盘的宽档记录可能在重启后与磁盘会话**重新配对执行**。
报警不等于修好。

## 二、落点（一处声明，三处消费）

| 层 | 落点 | 行为 |
|---|---|---|
| **唯一声明点** | `src/shared/read-level-policy.ts` | `OPEN_READ_LEVELS = ['ledger']`；`isOpenReadLevel()`；拒绝原因 `readLevelNotOpenReason()`；用户可见说明 `CLOSED_READ_LEVEL_NOTE` |
| **签票** | `src/modules/session-create-channel.ts` 的 `issue()` | 枚举合法但**不在开放面** ⇒ `ok:false` + 可读原因（⛔ 不发票据） |
| **建会话** | 同文件 `createHobSession()` | 票据里带宽档 ⇒ **在创建之前**拒（零会话、零策略写入）；兜住"限制生效前签出的票" |
| **无界面路径** | `src/modules/bus.ts` 的 `hob_spawn` | Hob + 宽档 ⇒ `reason: 'hob-read-level-not-open'`，**`spawn()` 一次都不调**；**非 Hob 不受影响** |
| **下发枚举** | `session-create-channel.ts` 的 `action:'enums'` | **两份清单**：`levels: PERMISSION_LEVELS`（呈现面，三档）+ `openLevels: OPEN_READ_LEVELS`（开放面，只 1 档）+ `levelsNote`（原因说明）；`modes` 仍三档 |
| **界面** | `src/client/create-hob-dialog.tsx` | 按 `levels` 渲染**三项**、按 `openLevels` 把未开放的**置灰（`input.disabled`）+ 行内标「暂未开放」**；账本权限可选。⛔ 不自己过滤、不新增值；原因说明渲染在**同一 `fieldset` 内** |

⚠ ⚠ **置灰不是校验**：界面让两项灰着只是**减少误操作 + 让用户看见它们存在**；宽档一律由**服务端**拒。
⚠ 两个判据必须**同时**成立（缺一算没做完）：**界面三项呈现（后两项灰 + 标注）** 与 **服务端拒绝任何宽档请求**。
只有界面灰 ⇒ 绕过界面仍能建宽档；只有服务端拒 ⇒ 用户看不到另两档存在。
⚠ 合法枚举（`PERMISSION_LEVELS` 三档）**没变** —— 已建会话的解析与旧会话迁移仍用它；
收窄的只是"**新建时可选**"。

## 六、另两档怎么重开（条件写在用户裁定里）

宿主提供**可靠的持久删除或等价清理能力**，并给出成对读数（创建失败后重载：该会话既不能执行、
也不能按宽读档读出工作区文件）⇒ 达标后：
① 改 `OPEN_READ_LEVELS`（唯一常量，加回 `'project'`/`'workspace'`）——**界面不用改**：
   它本来就按 `openLevels` 决定哪些可选，三档也一直呈现着；
② 断言里那几条"后两项必须灰"的判断同步放开（D-18 / D-10 的"不可选"那半）；
③ `LEVEL_LABELS` 里的「完全权限」条目与四段边界句**一直在界面里**（纠正后没删），届时只需去掉置灰。
⛔ 不许在调用点各写一份白名单。
