### 0.7 红线与纪律

**红线**：不重启任何实例（**只有用户能重启**）· 不启 Windows GUI 进程 · 改前先备份 · 报错认账不美化 · **挂起项不修不改不删** · 不碰 `~/.dsh/**`（**本项目账本区除外**）· **机检零放宽** · 不许 `--amend` / rebase / 改历史 · 不推送远端 · ⛔ **不许用零宽 / 不可见字符** · ⛔ **仓库与交付物内不许用符号链接**（⚠ **临时目录的隔离实验副本例外**，见 §0.4）。

**账本纪律**：**格式进 git，内容不进**。**执行侧不写账本**（正本的**内容**归 Hob）。⚠ **`.hob/**` 在工作区** ⇒ Hob **无写权**，只能出指令让执行方落盘。

⚠ **★ 收到任何输入，第一个动作是对照方案（第 138 轮立 · 用户原话）**：
**判据** = **凡接到输入（用户的话 / 回传 / 提问，不分类别）⇒ 先读 PROJECT.md 与账本**，定清「**落在方案的哪一步 · 边界是什么 · 判据是什么**」⇒ **再决定下一步**。⛔ **不凭感觉**、⛔ **不拿"我记得的对话"当依据**。
⚠ **与既有两条的关系**：UD-96 / CHG-036 管**发出去的指令** · UD-97 / CHG-037 管**先做哪一件** · **本条管每一次收到的输入的第一个动作** ⇒ **三条叠加，⛔ 不是替代**。
⚠ **正文载体 = 预设契约**（两份逐字一致），机检 **⑤l** 钉住；⚠ 预设正文改动 **须重载 / 重启才生效**。

⚠ **★ 作业书与报告随轮入库 = 产生它的那一轮自己提交它（第 115 轮立）**：**判据** = **该轮结束时 `git -C <账本区> status --porcelain` 为空**。⛔ **不许**留给下一轮（**会自我延续**）。⚠ **报告正文 ⛔ 不许预写"报告自己那一笔"的提交号**。
⚠ ⚠ **Hob 独自改正本的轮无作业书** ⇒ 那一轮写定的东西**由下一轮的收口一笔提交**。
⚠ ⚠ **★ 落点回填的顺延（第 154 轮立 · `E-152`）**：**"只提交 + 收尾"类单**（⛔ **正本禁改**）⇒ **回填顺延到 Hob 下一轮**；⚠ 留 `—` 过轮界**不算违规**，但**下一轮必须补**。
⚠ ⚠ **★ 其"批终"例外（第 167 轮立）**：**"顺延给下一轮"以"还有下一轮"为前提** ⇒ **批终那轮的顺延项必须当场收口**。
⚠ ⚠ **★ 其结构性边界（第 168 轮实测 · 第 173 轮修订）**：**"当场收口"要写正本**；⚠ **若最后那单是"只提交 + 收尾"类，执行方无权改正本** ⇒ **缺口只能由 Hob 在批次内补一轮来收** —— ⚠ **而"补一轮"又要下一次派单** ⇒ ⚠ **"永久"二字在活项目里做不到**。
⇒ **判据** = **凡写"顺延给下一轮"，先问"下一轮还会来吗"**；⚠ **答"不确定"⇒ 写"待下一轮补"并给判据，⛔ 不写"永久"**。

⚠ **★ 写"永久 / 不再"须给凭据（第 173 轮立 · 经验库 `E-141` 第 ④ 条 · 骨架 §5.1 已登记）**：
**判据** = **凡写"永久 / 不再 / 到此终止"这类不可逆声明** ⇒ **必须写明"它由哪一步关掉"，或给出"那一步确实不会来"的凭据**；⚠ **落笔前先问"什么能让我这句话变假"** —— ⚠ **答得出来 ⇒ ⛔ 别写"永久"**。
⚠ ⚠ **本条是"不写自陈旧句"那条的同族**（**"永久"是那个坑最硬的形态**）· ⚠ **展开在经验库 `E-141`**，**两处并存且互相指认** ⇒ 符合**第 163 轮裁定**。

⚠ **★★ 填写 / 描述一处事实时，⛔ 不许替它辩护（第 184 轮实测 · 第 185 轮立 · 经验库 `E-154` 第 ⑦ 条 · 骨架 §5.1 已登记）**：
**判据** = **凡在正本里写下"某处可疑 / 某处看起来不对"的处置** ⇒ ⚠ **只写"据实说明 + 它凭什么"，⛔ 不许写"这样是合法的 / 这样没关系"**；
⚠ ⚠ **因为那句辩护会把一个错误论证成正常** —— ⚠ **比单纯填错更坏：它让下一个读者不再怀疑**。
⚠ **同族**：**`E-154`**（可查的指认须先核）· **`E-144`**（读数须能指认出处）。⚠ **判据** = **凡见"这样也可以"式的括号注，先当成一处可疑错，去实测**。

⚠ **★ 三处"可查的指认"都要先实测（第 176 / 177 / 179 / 182 轮立，逐次收紧）**：
① **落点号**：**凡往 §5.1 落点列填提交号** ⇒ ⚠ **先 `git log --name-status` 认"那一轮的产出落在哪一笔"**（⚠ 按**产出特征**认，⛔ 不按轮次先后猜）；
② **每一行的号各自独立实测** —— ⚠ **"两行同号"本身 ⛔ 不是错**（⚠ **实测有合法反例**：第 171 / 172 两行同填 `a3320c3` 且都对，**因第 171 轮的产出正是由第 172 轮那一笔提交的**；⚠ **"第 N+1 轮提交第 N 轮产出"是常态**）；
③ **"由某轮提交"那句也是归属** ⇒ ⚠ **同批实测**（⚠ **第 181 轮实测**：某行写"由第 178 轮提交"，而**第 178 轮提交数 0**；⚠ **第 184 轮实测**：另一行写"同笔提交"云云，**实为另一笔**）。
⚠ ⚠ **本档位下 Hob ⛔ 核不了**（读不到 `.git` 与 `.mjs`）⇒ ⚠ **凡要填号，一律在作业书里要求对方附实测原文**（**第 184 / 186 轮的做法**）。

② **后核**：**凡把表里若干行"移出"** ⇒ ⚠ **同批核"那些行的原文在别处读得到吗"**（⚠ **`CHG-043` 的对照表只是索引，不是槽位**）⇒ ⚠ **槽位不存在 ⇒ 那几行就是"无痕消失"**（**`E-151`** 反对的那种）。

⚠ **★ 描述别节 / 别表 / 别处状态时，先核它（第 170 / 171 / 182 轮立 · 第 184 轮扩展）**：

⚠ ⚠ **★ `N/M` 口径（`E-150`）**：`M` = **命令条数**、`N` = **通过的命令条数**；⛔ **不是 ✗ 断言行的条数**。

⚠ **★ 「同一事实的轮次归属」须逐处一致（`E-154` · 第 157 轮立 · 第 167 / 179 / 182 轮扩展）**：
**判据** = **凡写"某轮立 / 某轮建 / 某轮引入"** ⇒ **落笔前先在该轮提交里查一次**。
⚠ ⚠ **扩展一（第 167 轮）**：**同一条适用于一切"可查的指认"** —— **凡写"已记在 §X 第 N 行 / 某处已有 / 某表已列"** ⇒ ⚠ **落笔前 `grep` 一次**。

⚠ **★ 不写"下一步会做 X"这类自陈旧句（第 159 轮立 · 第 161 轮独立成条）**：
**判据** = **凡写"某处尚只在某地 / 下一批要落 / 下一步会做 X"** ⇒ ⚠ **要么写明它由哪一步关掉，要么改成 §2.4 表里的一行**。⛔ **不在 §5.3 这类"总结段"里写将来时**（那个位置**没有收口动作**，**必然**在下一次动作时变假）。
⚠ **两处并存是裁定为正确的**（**第 163 轮裁定**）：此处 = **纪律条**（管"该不该做"）；经验库那条 = **做法展开**（管"怎么做"）。⚠ **判据** = **两处须能互相指认**（⛔ 不是"必须删掉一处"）。

⚠ **★ 回归对拍（第 148 轮立）**：**凡本轮修好了某处，同批必须把那一处「注回去」，看新判据红不红**。⚠ **它与"注入一个自造违规"不是一回事**；⚠ **配套**：注入后**逐字节还原**（`cmp`）。

⚠ **★ 判据的判定行必须报"核了多少"（第 148 轮立）**：**判据** = **新判据的判定行带分族覆盖计数**；⚠ ⇒ **某族读数与其它族完全相同 ⇒ 先怀疑它没扫到**；⛔ **「命中 0」不得单独当"干净"的证据**。
⚠ ⚠ **配套（第 186 轮实测）**：**凡自己发现一处"数对不上"，⛔ 不许把它包装成"两个数各有所指"** —— **如实报 + 复核到能对齐**（该轮自查出"表头与分隔行被当成数据行"即此处置）。

⚠ **★ 「删引用」类改动须逐处复读自足性（第 147 轮立）**：**判据** = **删掉一个编号 / 引用后，逐处 `grep` 新写的指针在「本文件内」是否可解析**；不可解析 ⇒ **把规则本身写出来**（自足）。

⚠ **★ 新建件未按约定配齐 ⇒ 收尾当场红（第 150 轮立）**：⚠ **含 `sources/` 的归档目录必须带 `README.md` 清单件**（`check:archive` 的**唯一比对基准**，缺即 FAIL）。

⚠ **★ 「下一轮才建的目标」一律用形状描述（`E-148`）**：**凡写"将来要建 / 待派单 / 待落"的路径**，用 `archive/<日期>-<名>/…` 这类**形状描述**；⛔ **不写具体目录名**（会被引用判据 D 认成"指不到实体的引用"而**当场咬**）。⚠ **推广**：**凡"将来时"表述都适用**。

⚠ **★ 「机检绿」≠「问题修好了」（`E-151`）**；⚠ ⚠ **反向同理（第 179 轮实测）：机检红也可能是"靶点被搬走了"**。⚠ **凡"某处超限 / 某数超标"类的红修完，必须同时核"内容去哪了"** —— **搬运**（成链可回溯）还是**删除**（无痕消失）？⚠ ⛔ **抽样须标明是抽样**。

⚠ **★ 跨轮比机的读数，先看它依赖什么（第 152 轮立）**：⚠ **比"覆盖面那一族"更稳**。

⚠ **★ 立新纪律 ⇒ 同批登记三处（第 157 轮立 · `E-153`）**：**判据** = **正本 §0.7 · 经验库条目 · 骨架 `.hob/README.md` §5.1** —— **三处同批**，⛔ **不留"只在账本侧"的纪律**（否则**换个工作区开箱拿不到它** —— 这正是 **UD-103 / CHG-047** 的判据）。
⚠ ⚠ **配套（第 156 / 160 轮实测）**：**登记表第 3 列有两支写法**（`` `check:<名>` `` 带反引号 · **裸** `未机器化`）⇒ ⚠ **"照抄上一批的行"会翻车**；⚠ **且单元格里 ⛔ 不许写裸竖线**。⚠ **该坑已另立条目 `E-155`**（根因：**登记表单元格是个机械面**）。

**文档形态纪律**：**改动即重构、旧的归档**。⚠ **执行对象 = "会被读的每一份"**（**E-116**）。⚠ **改脚本 ⇒ 同步改"描述这个脚本"的文档**；⇒ **文档里不写死组数 / 条数**（**E-117**）。⚠ **正本改动必须整份重写**（**不许追加"订正"段** —— **断言 B 会判 FAIL**）。⚠ **一切写进正本的读数落笔前先核实**（**E-118**）。⚠ **每次改账本 = 一次整体重构（UD-99 / CHG-039）**：⛔ **不许堆历史数据、不许堆历史变更说明、不许留会立刻失效的状态字**。

⚠ **★ 方案落点审核（UD-101 / CHG-041）**：**① 先审落点** → **② 落到方案本体** → **③ 整份重构**（⛔ 不补丁式追加）。

⚠ **★ 预设必须自带职责边界 + 改动不只改自己（UD-103 / CHG-047）**：
① **预设落盘必须自带一块显式职责边界**（含"**靠什么守住并如实声明它是不是安全边界**"）；⚠ **新增 / 改动预设的批次 ⇒ 边界块与机检同批落**。
② **凡改动都须把「账本等相关部分」一并考虑** ⇒ **可复用层必须同批跟着走**（⚠ **判据** = 「换个工作区开箱，拿到的是新规矩还是旧规矩」）。⚠ ⚠ **本条判据已机器化**（第 148 轮）：**可分发层「开箱即错」族** —— ⚠ 但**记录层与说明书层是点名豁免的**。

⚠ **★ 派出去 ≠ 派过（第 112 轮立）**：**投递之后当场读一次 `hob_orch_status`，看「在等回传」是否为 1**；⚠ 判据三条：**① 作业书真的落盘了** · **② 「在等回传」有那一行** · **③ 那条 `pending` 在**。

⚠ **★ 回传与产出是两个通道（第 124 轮立）**：**回传** = "**它说它做了什么**"；**产出** = **盘上的字** ⇒ **回传异常时先核盘**，⛔ **别急着重派**（**重派会重复干活**）。

⚠ **★ 机检的覆盖面必须派生（第 121 / 122 轮立）**：⚠ ⚠ **派生面自己也会带洞** ⇒ **任何"收录判据"都要先问一句"谁被它排除在外"**。⚠ **配套**：判定行**分别报**"正文点名"与"盘上派生"两来源的贡献（⛔ 不报一个合计数）。

⚠ **例外**：只有当"**选错做法就会造成方案偏差**"时，才在作业书里写明做法。
⚠ **Hob 复核时看的是"主线有没有偏"，⛔ 不是"指令里的做法对不对"。**

### 二、实施方：⚠ ⚠ **发现与指令不符 ⇒ **立即停手** + 汇报**

⚠ ⚠ **停手门槛（随之抬高）**：⚠ ⚠ **只有"方案落点做不到 / 会偏离方案"才停手**；
⚠ **做法自由、取证自由、顺序自由** ⇒ ⛔ **不许把"指令写得不细"当成停手理由**。
⚠ ⚠ **做法自由 · 取证自由 · 顺序自由** ⇒ ⛔ **不许把"指令写得不细"当成停手理由**。
⚠ **理由（用户给的）**：⚠ **落实方没有全局视角** —— ⚠ ⚠ **它自己找路，可能让整个方案产生偏差**。
⚠ ⛔ **不许自己想办法 · ⛔ 不许绕路 · ⛔ 不许换做法 · ⛔ 不许打补丁**。

⚠ ⚠ **汇报须写清三问**：**哪里不符 · 你以为应该怎样 · 你建议怎么办**。

⚠ ⚠ **两档分界（⚠ 判据 = "**要不要换一个做法**"）**：

| 档 | 形态 | ⚠ 处置 |
|---|---|---|
| **甲** | ⚠ **做法 / 可行性不符** —— 指令说的做法**做不到** · **报错** · **实现逻辑走不通** · **盘上实情要求换做法** | ⚠ ⚠ **停手汇报** |
| **乙** | ⚠ **纯事实读数过期** —— 只是某个数 / 某份文件与记法不符，⚠ **而"怎么做"完全不变** | ⚠ **按实测办 + 登记**（⛔ 不停手） |

⚠ ⚠ **判不出是哪一档 ⇒ 按甲档办（停手）**。

### 三、Hob 收到汇报后：⚠ ⚠ **回方案核**（⛔ 不打补丁）

⚠ ⚠ **问题不是"让它接着干"，而是回到我说的那一层去找**：
1. ⚠ ⚠ **是方案有问题**（⚠ 落实方案 / 技术 / 逻辑哪一块不成立）⇒ ⚠ **重新审核并修改方案** ——
   ⚠ ⚠ **而"方案只有用户能批准变更、Hob 只提议"这条⛔ 不变** ⇒ ⚠ **提案交用户**；
2. ⚠ **是我把方案翻成指令时翻错了** ⇒ ⚠ **改指令，重派**；
3. ⚠ ⛔ **⛔ 不许"硬着头皮绕圈子、打补丁"解决问题**。
