## 一、欠账 ①：**端到端证据** —— 从"手写 fixture"升级到"真卡数据 + 已出货产物"

⚠ 而 2026-10-20 那场事故，恰恰是"**真帧里没有 `createdBy`、也没有 `executions`**"
把上一版判据**打空**的那一点 —— 当时的 fixture **看不出来**。

## 二、欠账 ②：**装配面钉死** —— 新族 `check:profile`

**判据四条（缺一条就等于漏一半）**：

| 段 | 判什么 | 为什么必须单列 |
|---|---|---|
| **A 声明面** | `dsh.profile.bundles` 里有本包 | 这就是事故那一行 |
| **B 依赖面** | `dependencies` 里也有（`link:` 也算） | ⚠ **实测事故形态正是"依赖在、bundles 丢了"** ⇒ 与 A 合成一条就说不清"哪一半丢了" |
| **C 解析面** | 从该 profile 能解析出本包，且**落在本 checkout 内** | 防"声明了、却解析到别处的另一份" |
| **D 可修面** | `--fix` 按原位补回，且**只动那一行** | 见下 |

**`--fix` 的安全闸**：补完先做**语义 diff**（把 `bundles` 里本包名剔掉后逐字比），
⚠ **不只动那一行就拒绝写盘**；写盘前 `copyFileSync` 备份。
⚠ 位置规则：插在 `dsh-taskboard` 之后（取自那份"还完好"的备份里的实际邻位），
找不到该邻位 ⇒ **追加末尾并说明**（⛔ 不猜）。

**实测四段**（临时 profile，不碰真件）：

```
造坏清单（bundles 28 项、无 dsh-hob）→ 只判 ⇒ FAIL，话说"插件不会被装配" ✓
                                     → --fix ⇒ 已补回（第 10 位，紧跟 dsh-taskboard）✓
                                     → 只判 ⇒ PASS ✓
前后比对：28 → 29 项，只多了 ['dsh-hob']，除 bundles 外逐键完全一致 ✓
```

**自检 5 条**（`--self-check`）：正向 / **钉事故形态** / "没法自动修"必须在**只判那一遍**就说 /
`--fix` 只动一行且修后转绿 / **`--all` 下非目标 profile 不许拖红退出码**。
**变异实测**：把 A 段改成恒绿 ⇒ **P-2 当场红**（⇒ 判据有牙，不是恒绿）。

⚠ **`--all` 的口径**（自检 P-5 逼出来的）：本机另有 `headless` / `system` 两个 profile，
它们**本来就不装**本插件 ⇒ 若算红，这条判据会**永远红**（"恒红的判据等于没有判据"）。
⇒ **退出码只由目标 profile（缺省 `web`）决定**，其余照实打印并标"⛔ 不计入退出码"。
⚠ 汇总句也改了：⛔ 不许再说"全部 profile 四条都成立"（那是假话）。

   （`UD-151`）。
