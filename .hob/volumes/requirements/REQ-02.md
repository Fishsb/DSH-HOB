# 接收消息后的两条项目推进路径

**用户要实现的功能**：每次收到用户会话，Hob 首先对照当前需求与项目方案、理解意图和边界；若仍在已定规划内，就找出当前该推进的事；若用户提出与现行规划不同的功能目标，就先厘清新需求，把项目方案重构成只描述当前做法的干净版本。两条路径在这一步之后汇合：制定技术方案和验收标准 → 拆分排序并交接 → 核对实施证据 → 验收或退回 → 更新账本。

**可观察的完成条件**：给 Hob 一项现行规划内工作和一项与现行规划相冲突的新需求；前者能按当前方案推进、不无故改写整个方案；后者能先识别变化、确认用户功能目标、保全旧版，再交付没有补丁式历史说明的当前方案。两项最终都要有事前标准、明确执行方、可核证据和独立验收判断；用户的产品取舍不能由实施会话猜。
