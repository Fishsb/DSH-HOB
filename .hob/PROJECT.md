**项目概览**（读这一屏就知道项目是什么、谁在哪、去哪读）：

**这是什么**：**`dsh-hob`** 是一个装在宿主 profile 内的 DSH 插件，它服务的首要目标是
**让 Hob 作为某个项目的总工程师** —— 用户表达意图与产品取舍，Hob 维持项目目标的连续性：
理解边界、制定技术方案与事前验收标准、拆分排序并交给实施会话、独立核对证据后验收或退回、维护项目工作簿。
见 `volumes/plan/01-project-positioning.md`。
⚠ **插件 ≠ 预设 ≠ 项目目标**：插件是承载会话通信、账本读写、回传、权限收敛与创建交互的宿主内机制；
"电话只传话"仍能说明**插件层**的职责，但**不能替代整个项目的目标**（见方案 `volumes/plan/01-project-positioning.md` §1.2）。

**给谁用 / 谁在哪个位置**：**用户**（产品决策者：决定要实现什么功能、接受什么代价）·
**Hob**（规划侧：技术判断、验收标准、交接、核证、维护账本）· **实施会话**（真正改代码、跑检查的那一侧）。
见 `volumes/plan/01-project-positioning.md` §1.1 · `volumes/plan/06-permission-boundary.md`。

**当前功能需求在哪**：**`REQUIREMENTS.md`**（根地图）→ 条目正文在 `volumes/requirements/REQ-<编号>.md`。
⚠ **它只写功能与可观察结果**，不写技术手段；技术变更史在 `DECISIONS.md`，历史用户决策的原始记录在 `volumes/user-decisions/`（卷；已退场的根件在 `archive/2026-10-25-oldroot-retire/`）。
见 `REQUIREMENTS.md` · `volumes/requirements/INDEX.md`。

**两条主线**（收到用户会话后的固定入口）：先**对照当前需求与现行方案**、理解意图和边界，再分两支 ——
**A 现行规划内**：定位当前阶段 → 技术方案与验收标准 → 拆分排序交接 → 核验原始证据 → 验收或退回 → 更新账本；
**B 新需求**：用户目标与现行方案冲突时先确认目标与取舍 → 更新当前需求 → **把方案整份重构成只描述现状的版本**
（旧版逐字节归档）→ 再并入 A 的后半段。
⚠ **投递 ≠ 执行 · 建会话 ≠ 委派 · 回传 ≠ 验收**：三条不变量全文见 `volumes/plan/05-features.md` §5.1。

**形态与架构一句话**：**不是独立实例**，跟着宿主 profile 一起启停（装进 profile 的一个插件）；
内部**一模块一文件**、按声明的依赖注入装配。见 `volumes/plan/02-form-profile-plugin.md` · `volumes/plan/03-architecture-modular.md`。

**支撑能力一句话**（**保留、不本批扩建**）：同实例内会话通信 + 闭环派活与回执 + 并行隔离推进 +
首次铺骨架 + 设置面。⚠ **它们为主线服务，不是项目目标本身**；
⚠ **派发之后那笔账怎么算、怎么清、怎么读，另有契约** —— 见 `volumes/plan/14-dispatch-and-receipt-contract.md`。
见 `volumes/plan/04-core-capabilities.md` · `volumes/plan/05-features.md`。

**读到哪里可调**：Hob 的**读**范围是**可读权限控制** —— **三档**（显示名 **账本权限** / **文档权限** / **完全权限**，
配置值 `ledger` / `project` / `workspace`，缺省账本权限）——
⚠ **只改"读到哪里"**：**任何一档都无写、无命令、无组队**；
⚠ **「完全权限」只放宽可读范围** —— **完全权限 = 工作区里任何文件都可读，仍然不能写、不能执行命令、不能组队**。
⚠ **新建 Hob 会话的可读范围只开放最低档**（账本权限）：**三档是呈现面**，
另两档**照常呈现但不可选**（灰显 + 标「暂未开放」），**待宿主持久清理能力具备后再开放**
（条件是「创建失败后重载，该会话既不能执行、也不能按更宽档位读出工作区文件」这对读数）；推进方式三档不受此限。
⚠ **目标形态**：这两项（读范围 / 推进工作方式）应**属于每个 Hob 会话自己的选择**，创建时分别选定并持久化；
⚠ **实现进度与加载状态只记在 `CONTEXT.md`**（**§2.1b**），⛔ **不在本节写成已生效**。
见 `volumes/plan/04-core-capabilities.md` §4.3 · `volumes/plan/06-permission-boundary.md` §6.1 ·
`volumes/plan/07-configuration.md` §7.2。

**预设一句话**：本插件自带**规划侧预设**，它**不只要完成自身功能，还要明确写出自身的职责边界** ——
⚠ **正文载体 = 预设契约**（人读版 + 机器读版**逐字一致**，机检钉住），**本方案只留对照与指针**。
见 `volumes/plan/04-core-capabilities.md` §4.3 · `volumes/plan/10-risks-and-discipline.md` §10.5。

**对外交付一句话**：本项目**按开源商用标准规划** —— 外部人拿到它要**装得上、能升能卸、配得明白、出错看得懂、
读得懂结构、看不到内部东西**；⚠ **已知限制照实写**（⛔ **不许把跨实例投递写成支持或可用**）。
见 `volumes/plan/13-delivery.md`。

**进度在哪读**：方案已按节分卷（正文在 `volumes/plan/`，本文件是它的地图）；
⚠ 详细进度与"还欠什么"**只进 `CONTEXT.md`**（本文件按文件头"状态字口径"只写稳定判断）。

⚠ **地图标准（CHG-038）**：**① 按板块、按标题分区**，界分清楚；
**② 说明"项目由哪些板块组成、每个板块是什么"**（每板块一句话）；
**③ 读完地图应能知道整体概要，并知道下一步该去检索哪一册**。
⇒ 本文件与其余正本**都适用**这条标准。
