## 1. 骨架 vs 运行数据

`.hob/` 的内容按**文件性质**二分：

| 类别 | 判定标准 | 进 git？ | 位置 |
|---|---|---|---|
| **骨架** | **格式契约 / 被机检脚本消费的规范源** —— 表头、列定义、编号规则、以及**入库脚本会读取的契约正文**。可复用、可分发；新建工作区时用它初始化 | ✅ **进** | `.hob/README.md`、`.hob/templates/`、`.hob/EXPERIENCE.md`、**`.hob/drafts/`**（见 §1.2）、**`.hob/roles/`**（见 §1.3） |
| **运行数据 / 方案** | **填充进格式的具体条目 / 本项目专有的过程产物** —— 第 N 条事实 / 第 N 条决策 / 本轮进度 / 改前备份 / **项目方案** | ❌ **不进**（且**不在本目录**，见顶部说明） | `PROJECT.md`（已迁入账本区）· 三本账本 · `.hob/archive/` · `.hob/backups/` · `.hob/CARRYOVER.md` · `.hob/STEP*-REPORT.md` ⇒ 四份正本在 `/home/lk/.dsh/hob-ledgers/dsh-hob/` **根目录**；**过程产物（`CARRYOVER.md` / `STEP*-REPORT.md` / 经验库碎片等 15 份）在该区 `archive/2026-10-10-ledger-root-housekeeping/`**（见 §1.6） |

**一句话**：**格式进 git，内容不进** —— 且内容**不在本目录**。

> **为什么这样切**：`.gitignore` **按路径匹配、读不到文件内容**，
> 所以「首行标记」在 git 上不可行；把运行数据下沉到子目录则要改目录结构定义。
> 本方案零迁移。

**⚠ 清单必须逐项列全，不许靠推断**（见 `EXPERIENCE.md` **E-70**）：
`.gitignore` 的 `!` 例外**少列一项** ⇒ 该文件**静默不入库**，git **不报任何错**。
⇒ 本表的「位置」栏就是 `.gitignore` 例外的**唯一权威清单**；
改一处必须同步另一处，并由 `npm run check:gitignore` 机检（见 §1.4）。

### 1.2 `drafts/` 为什么**进 git**（一次经复核的归类纠正）

`.hob/drafts/preset-contracts.md` 是**预设契约正文的人读版**（现状只有 `Hob` 一份），
也是 `scripts/check-preset-contracts.mjs`（**已入库**、挂在 `npm run check:presets`）
**无条件读取**的文件（该脚本里 `const DRAFT` 定义路径、`readFileSync(DRAFT, …)` 读取 —— ⚠ 引用用**符号锚**而非行号：行号会随脚本改动漂移，见 `EXPERIENCE.md` **E-91**）。

**决定性事实（实测）**：若把它排除，则**新 clone 跑不了已声明的命令** ——
```
$ git clone . /tmp/x && cd /tmp/x && node scripts/check-preset-contracts.mjs
Error: ENOENT: no such file or directory, open '.../.hob/drafts/preset-contracts.md'
EXIT=1
```
⇒ 一个**入库脚本**依赖一个**不入库文件**，是自相矛盾的状态。

**判定**：它满足「**被机检脚本消费的规范源**」⇒ **归骨架**。
它**不**满足本条原来的"可复用、可分发"措辞 —— 它是本项目专有的契约正文；
故「骨架」的判定标准写作"格式契约 **/** 被机检脚本消费的规范源"，
好让这条归类**有明文依据，而不是靠推断**。脚本头部注释亦称其为
"**用户过目、将来改动的地方**" ⇒ 是**源**，源必须进版本控制。

### 1.3 `roles/` 为什么**进 git**（角色簇）

`.hob/roles/` 存**角色簇与方法论**：`methods/` 下**随角色数增长的多份**
（各角色的领域方法论 + `quality-gates.md`；**份数以 `ls .hob/roles/methods/` 实测为准**）；人读契约在
`.hob/templates/ROLES.md`（角色）与 `.hob/templates/GATES.md`（门禁）。

**来源与许可**：改编自 [dsh-expert-mode](https://github.com/Asher-2000/dsh-expert-mode)
（**MIT**）的 `agent.cordis.yml` 内嵌 persona（17 段）与 `.expert-mode/methods/*.md`。
每份文件头部带来源注释。

**为什么归骨架**（对照上方标准）：

| 判据 | 事实 |
|---|---|
| **可复用、可分发** | ✅ 是**通用角色定义**（架构师/后端/QA/安全…），**不含本项目专有内容** |
| **被机检脚本消费** | ✅ 列入 `check:gitignore` 的 MUST-TRACK 清单，任一漂移即 FAIL |

⚠ **与 `drafts/`（§1.2）的判据区别**：`drafts/` 因"**被入库脚本读取**"才归骨架（本项目专有）；
`roles/` 是"**本身可分发**"（换项目直接复制可用）—— 两条判据**各自独立成立**。

⚠ **为什么不直接安装该插件**（两条取舍依据）：① **可移植性（UD-73③，用户原话）**：
外部插件**换环境就没有** ⇒ 它只能作**可选增强层**，且必须有**降级路径**；
而本层要的是**零外部依赖**的基础层。② **方法论已抽到手** ⇒ **不需要**它。
⚠ 另一条曾被引用的理由「撞本项目**硬边界**『不动 `~/.dsh/**`』」**不是用户决策**
（UD-76 已澄清：本项目**只管自己的账本**，不设跨项目/跨环境限制）⇒ **不作为依据**。

### 1.4 机检：`npm run check:gitignore`

`scripts/check-gitignore.mjs` 把「**排除漂移**」从**静默**变成**显式 FAIL**：
它按 §1 的两栏清单逐条断言 `git check-ignore` 的结果，**违反任一条 ⇒ exit 1**。
改 `.gitignore` 或改本表后**都应跑一次**。
（⚠ 它用 `git check-ignore`（**纯规则匹配**）做断言 ⇒ 能区分
"**被规则排除**"与"**不存在所以没出现**" —— 后者**不**算通过，见脚本内注释。）

⚠ **同一脚本还带文档形态机检多组**（**A / B / C / D / D′ / E / F / G / H / I**）
+ **脚本落点双向自检**（正方向：`package.json` 声明的 ⇒ 必须在 `MUST-TRACK`；
反方向：`scripts/*.mjs` ⇒ 必须被 `package.json` 的 `scripts` 调到）—— 别以为它只管排除。
⚠ **另加断言 J**（第 53 轮）：**正本里同一 `## ` 节标题不得重复**（只认行首；围栏内的标题不参与；只扫四份正本）
—— 判据函数 `findDuplicateSectionHeadings` 可对任意 `.md` 单跑：
`node scripts/check-gitignore.mjs --dup-headings <某份.md>`。
⚠ **组数与条数以实测为准**（`npm run check:gitignore` 的输出自报；⛔ 此处**不写死数字** ——
计数会随新增加断言而漂移，**E-117**：写死的数字会被下一次改动直接作废）。
⚠ A / B 两个清单的**基准不同**（A 需模板、B 只需正本）⇒ 各用各的常量，**不可合并**
（合并会在扩一条时连坐另一条，见 `EXPERIENCE.md` **E-110**）。
⚠ **D / D′** —— **正本里"具名"的路径引用必须真的存在**：
**D** 扫 `archive/<YYYY-MM-DD-slug>/…` 形态的具体路径（**与写侧 `src/server/hob-write.ts` 的
`ARCHIVE_DIR_RE` 同源** —— 归档目录名必须是 `YYYY-MM-DD-<slug>`）· **D′** 扫 `TASK-R<数字>…md`
作业书文件名（按 basename 在 archive 的各日期子目录下比对）。
⚠ **按设计不计**（这些**不是**具名引用，**不许**把它们判成"不存在的引用"）：
占位形态 `archive/<日期>-<名>/` · `archive/<YYYY-MM-DD-slug>/TASK.md` ·
**示意名 `TASK-Rnn.md`**（编号非数字）· 通配 `TASK-*.md` / `TASK-R*.md`。
⚠ 引用 0 处时**打印"无对象可查"**（**不判 FAIL，也不静默**）。见 `EXPERIENCE.md` **E-113**（判据来源）
与 **E-114**（**判据必须容忍"描述它自己的文本"**）。
⚠ **D 只认 `archive/<YYYY-MM-DD-slug>/…`**（与写侧同源）⇒ 若将来出现**合法的非日期归档目录**
（如 `archive/legacy/`），其下的引用会被**漏判**。这是**有意选择**：**宁可漏判非法命名，也不误报举例**。
⚠ **D 的计数随被引用文本变化**，**不是常量** ⇒
**引用该数字时必须带口径**（哪几份正本、各几处），否则下游会误读成"漏判"。
⚠ **派单时不得写死该计数**（⛔ 不写"预期 N 处"）⇒ 改**判据式**：**"D 必须 PASS 且无 missing；计数照实记录"**。
⚠ **正本里不得以"具名文件"形式书写反例** —— 反例请写成"**第 N 轮那份作业书**"这类**叙述**，
不要写成具体文件名。理由：**形状合法的元讨论，判据原理上无法排除**
（再收紧就等于取消该断言）⇒ **只能约束写法**才能保住断言 D′ 的全威力。
见 `EXPERIENCE.md` **E-114** 与正本 `CONTEXT.md` §0.7 的**两种形态**。

### 负向对拍：**通过判据不只是退出码**

> **负向对拍的通过判据 = 退出码非零（`exit ≠ 0`）** **且** **输出里有可读的断言行**。

⚠ **只判退出码不够** —— 实测踩过（`EXPERIENCE.md` **E-112**）：被检查对象的形状被改坏时，
**检查脚本自己先崩**（如对 `undefined` 裸访问 `.length`），同样 `exit 1`，
但输出里**一条可读的 ✗ 行都没有**（只剩一段堆栈）⇒
**分不清"抓到了违规"与"检查器崩了"**，看日志的人还得反推"它本来想查什么"。
⇒ 判据必须**两条都看**：先看**有没有失败**（退出码），再看**失败长什么样**（有没有指名的断言行）；
新增/修改断言后，除了正向跑，**还要拿"被检查对象的坏形状"喂一次**（否则那条路径永远跑不到）。

### 样本登记：**新增"引用类"断言必须自带"不该被咬"的样本**

> **新增 / 修改"引用类"断言时，必须同步给它加至少一个"不该被咬"的样本**（进**断言 E** 的样本数组）。

⚠ **为什么**：断言**只会验证它枚举到的形状** —— **枚举漏了，它就是静默失效**
（⚠ 与 **E-70 / E-73** 的"清单少列一项就静默出错"同形：**清单漏一项，机检不会报**）。
⚠ 出处（`EXPERIENCE.md` **E-114**）：D / D′ 上线一轮后，正本新增了
**描述它们边界的文本**（`archive/DATE-NAME/` 这类举例、`TASK-Rnn.md` 这类反例示意名），
宽口径正则把这些**当成引用** ⇒ **断言被描述自己的文本打挂**。
⇒ **纪律**：改 D / D′ 的判据时，**同步看断言 E 的样本够不够**；
新增任何"扫原文里的引用"的断言，**先给它配"不该被咬"的样本**再上线。

⚠ **本条对"渲染标记"类断言的落地（2026-10-11 第 49 轮实测补）**：
**围栏豁免 ≈ 那条"不该被咬"的样本** —— 断言 I 扫四份正本找未渲染标记，
而"讲这个标记怎么写"的正文**必然**要写出标记 ⚠ **所以渲染器与断言必须共用同一份
"跳过围栏"的实现**（`hob-render.ts` 的 `scanMarkers`），否则会出现
"文档里按 A 口径能安全写、机检按 B 口径报残留"的自相矛盾。
⚠ **实测边界（第 50 轮已修正）**：豁免覆盖**两种"形状可排除"的形态** ——
① **围栏代码块内**（块级）；② **行内代码段（code span）内**（行内，反引号串**长度须匹配**）。
⚠ **裸写的标记照旧被咬**（那是**真残留**）——豁免**不覆盖**它。
⚠ **第 49→50 轮的教训**：豁免最初**只有围栏**，于是"行内引用"照旧被咬，
**文档在正文里复述这个形态就被自己打挂**（**E-125** 实测：Hob 的 `CONTEXT.md` 那句）
⇒ 第 50 轮把**行内代码段**补进豁免（**调精度**，不是放宽），并给断言 I 补了自带样本。
（⛔ 这里**不**再放一行裸写当演示 —— 那会给自己埋一个活标记；
   要看"裸写会被吃掉"的实测读数，见 **E-125** 的 `scanMarkers` 三形态对照。）

### 跑检查的**标准姿势**：先建输出目录，再取退出码

> ⚠ **跑收尾命令前先 `mkdir -p` 输出目录**；**取完退出码确认日志已落盘**（如 `ls | wc -l` 等于命令条数）。

理由（`EXPERIENCE.md` **E-115**）：`npm run X > 某不存在的目录/x.log` ⇒ **重定向失败**，
shell 把**整条命令**报成失败 ⇒ `EXIT=1` 会被误当成**命令报错**（**假报障**）——
⚠ **被测命令其实一次都没跑**。
⇒ **报 FAIL 前先复核那条命令的原样输出**（失败时输出**往往是空的或只有 shell 报错**，
与"断言 FAIL"的 `✗` 行形态完全不同）；
**先问一句"这条命令真的跑起来了吗"**，再判它对不对。

### 清理类改动的验收**必须包含 `build`**：扫描器 PASS ≠ 文件能编译

> ⚠ **清理类改动（尤其动不可见字符 / 删字符）的验收必须包含 `build`**。

理由（`EXPERIENCE.md` **E-121**）：**删掉的字符可能是"承重"的** ——
实测：清掉 `src/modules/orchestrator.ts` 注释里的一个 U+200B 后，
`build` 与 `typecheck` **双双 EXIT=2**（`tsc` 上百条语法错误）。
根因：那个字符**恰好夹在 `*` 与 `/` 之间**，使得注释结束符**从未真正出现**；
删掉它 ⇒ 结束符成立 ⇒ **块注释提前闭合**，其后整段代码成了裸文本。
⇒ **"零宽字符扫描器报 0 处"只说明"没有不可见字符了"，证不了"文件还编译得过"** ——
**两条判据各自必要、都不可省**：**清理后必须重跑 `build`**（本轮即靠它当场把哑弹引爆、未让坏产物进入提交）。

### 读数可信：**读数必须能指认到"哪条命令的哪一行输出"**

> ⚠ **凡在提交信息 / 文档 / 回报里出现的读数，必须能指认到「哪一条命令的哪一行输出」**；
> **指认不出就写"未取"**。

理由（**第 42 轮实证**）：曾有一处**提交信息**写了**没测过**的 `BUILD-STAMP` 读数
（写 `dirty=false` + 一个 `built_at`，**实际是 `dirty=true`、且无该行**）——
⚠ **形态不是"过期"，是"根本没有"**；与 **`EXPERIENCE.md` E-117**（写死预期值）同族，**但更重**：
过期的值至少**曾经为真**，补出来的值**从头到尾没有对应的事实**。
⚠ **更值得记的一层**：**提交信息不是被检查的对象**（机检只扫正本与骨架，**不扫 git 提交信息**）
⇒ 它天然是**无人核对的区域** ⇒ **最不该出错的地方反而没有防线**。
⇒ **提交信息里的读数与正文读数同标准**（⛔ 别因为"它不会被机检"而放松）；
**写前先看一眼日志**（成本一条 `tail`，远低于事后认账）。

### 1.5 账本仓**也有自己的** `.gitignore`

⚠ **忽略规则有两处，不是一处** —— 本节记的是**上面那张表没覆盖**的那一处：

| 仓 | 规则文件 | 忽略什么 |
|---|---|---|
| **工作区仓**（本仓） | `.gitignore` | 见 §1 两栏清单（§1.4 机检逐条断言） |
| **账本仓**（`<账本区>/`） | **该仓根自己的 `.gitignore`** | **只忽略 `backups/`**（⚠ **规则条数以该仓 `.gitignore` 实测为准**） |

**依据**：§1 已把 `backups/` 归为**运行数据 · ❌ 不进 git**（理由：各轮**改前备份**、随工作区一次性消费、
无跨项目价值）。账本仓是同一批运行数据的新居所 ⇒ **同口径延续**（"半进库半不进"会
每轮 `git status` 都冒"N 删 + M 增"的噪音 —— 属 `EXPERIENCE.md` **E-108**（其正确做法③：*能机器核的不要靠人记*）那一类形态）。

⚠ **四份文档与 `archive/` 不进忽略** —— 它们是账本仓的**正本**，被排除就等于**静默消失**
（git 不报任何错，正是 **E-70 / E-73** 的失效模式）。
⚠ ⛔ **不许在该规则里写宽规则**（`*` / `**` 之类会**连带排掉四份文档与 `archive/`**）——
**已有机检盯住**：`npm run check:gitignore` 的**断言 C** 在账本仓里逐条实测
（四份文档 + `archive/` 必须**都不被忽略**；反向再验 `backups/` **必须被忽略**）——
判据用 **git 自己的答案**（`git check-ignore --no-index`），**不解析 `.gitignore` 文本**。
⚠ 账本区读不到时该断言**明确打印"未执行"**，**不静默 PASS**。

### 1.6 账本区根目录**只放"当前状态"**
