# `.hob/` —— **骨架目录**（账本已外置）

> **本目录只放骨架**（进 git）。**账本数据在工作区之外、按工作区名独立存放**：
>
> ```
> <ledgerHome>/<工作区名>/     ← 账本数据（**正本：项目方案 + 各本账本** + volumes/ + archive/ + backups/ + runtime/）
> ```
>
> **派生规则**：`<ledgerHome>/<工作区目录名>/`；`ledgerHome` 由**预设行的 config 显式配置**
> （⚠ **取值本项目专有、换机须重配** —— ⛔ 骨架**不写死**具体路径，见 **`.hob/INIT.md`**），
> 其下**每个工作区一个独立仓**（该目录**自己即仓根**）。
> ⚠ ⚠ **本节起全文的编号引用（`E-nn` / `CHG-nn` / `UD-nn`）一律是「本项目账本」的条目号**
> —— 它们是**本项目专属**、**开箱不带**（新工作区从零开始，⛔ 那些编号在那边不存在）。
> 读到即理解为**出处指针**，⛔ 不要把"引用不存在的编号"当成骨架的缺陷；
> 要据此判"骨架是否可分发"的，**只看规则句本身是否自足**。
>
> **依据**：重构方案 v4 的用户决策 **D3/D4** —— 每个工作区**独立的账本目录、物理隔离**，
> 且**在工作区之外**（隔离由**文件系统**保证，不靠契约约束）。
>
> **账本区里有什么**：`PROJECT.md`（项目方案 · 唯一事实源 —— **指「方案」这一档**）· `DECISIONS.md` · `USER-DECISIONS.md` ·
> `CONTEXT.md`，以及 `archive/` · `backups/` · `runtime/`。**账本区根上 = 正本 + `volumes/`（卷：一事一文件）+ `archive/` · `backups/` · `runtime/`**（见 §1.6）。
> ⚠ **成员与条数一律以账本根实测为准**（⛔ 不在此写死 —— 机检侧的清单同理，见 §1.4）。
> ⚠ **工作区里不再保留任何项目文档**。
> ⚠ **可写面**：`PROJECT.md` 已加入 `write_hob` 的可写清单；
> 但**方案只有用户能批准变更、Hob 只提议** —— 那是**程序纪律**，不是工具闸门。
>
> **仍在本目录**（骨架）：`README.md` · `INIT.md`（**新工作区初始化清单**，见 §1.8）· `EXPERIENCE.md` · `experience/` · `templates/` · `roles/` · `drafts/`。
>
> ⚠ **名称未改**：本目录仍叫 `.hob/`，但它**不再是账本**（只放骨架）。
> 改名会牵动**大量引用**（⚠ 属**漂移型计数，此处不写死**；要最新值以 `grep -r '\.hob/'` 实测为准）⇒ **不改名** —— 故在此处显式说明，避免误读。

> 本文件是 **骨架（进 git）**，不是运行数据。
> 它回答三件事：**这里的文件各自是什么 / 哪些进 git / 东西归档去了哪。**

## 1. 骨架 vs 运行数据

`.hob/` 的内容按**文件性质**二分：

| 类别 | 判定标准 | 进 git？ | 位置 |
|---|---|---|---|
| **骨架** | **格式契约 / 被机检脚本消费的规范源** —— 表头、列定义、编号规则、以及**入库脚本会读取的契约正文**。可复用、可分发；新建工作区时用它初始化 | ✅ **进** | `.hob/README.md`、**`.hob/INIT.md`**（**新工作区初始化清单** —— 见 §1.8）、`.hob/templates/`、`.hob/EXPERIENCE.md`、**`.hob/experience/`**（条目目录 —— ⚠ **出处见本项目账本，骨架不点名具体编号**，见 §1.7）、**`.hob/drafts/`**（见 §1.2）、**`.hob/roles/`**（见 §1.3） |
| **运行数据 / 方案** | **填充进格式的具体条目 / 本项目专有的过程产物** —— 第 N 条事实 / 第 N 条决策 / 本轮进度 / 改前备份 / **项目方案** | ❌ **不进**（且**不在本目录**，见顶部说明） | `PROJECT.md`（已迁入账本区）· 各本账本 · `.hob/archive/`（**历史位置 —— 该目录现于账本区**，见 §1.6）· `.hob/backups/` · `.hob/CARRYOVER.md` · `.hob/STEP*-REPORT.md`（⚠ 后两件亦为**历史位置**，现于账本区） ⇒ 各本正本在 **`<ledgerHome>/<工作区名>/` 根目录**（⚠ **具体路径是本项目实例，见 §3 归档表**）；**过程产物（`CARRYOVER.md` / `STEP*-REPORT.md` / 经验库碎片等 15 份）在该区 `archive/2026-10-10-ledger-root-housekeeping/`**（见 §1.6） |

**一句话**：**格式进 git，内容不进** —— 且内容**不在本目录**。

> **为什么这样切**：`.gitignore` **按路径匹配、读不到文件内容**，
> 所以「首行标记」在 git 上不可行；把运行数据下沉到子目录则要改目录结构定义。
> 本方案零迁移。

**⚠ 清单必须逐项列全，不许靠推断**（见 `EXPERIENCE.md` **E-70**）：
`.gitignore` 的 `!` 例外**少列一项** ⇒ 该文件**静默不入库**，git **不报任何错**。
⇒ 本表的「位置」栏就是 `.gitignore` 例外的**唯一权威清单**；
改一处必须同步另一处，并由 `npm run check:gitignore` 机检（见 §1.4）。

### 1.1 各类"运行数据"为什么进不了 git（逐类判定依据）

| 类 | 判定依据（对照上方「运行数据」标准） |
|---|---|
| 各本账本 | 「**本项目专有的过程产物**」—— **呈现当前状态**；历史移入 `archive/<日期>-ledger-history/`，不回填主体 |
| `.hob/archive/` | 「**本项目专有的过程产物**」—— 历轮证据/归档；⚠ **该目录名是历史位置**（现于账本区，见 §1.6）；去向由 §3 的**指针表**留在骨架区 |
| `.hob/backups/` | 「**本项目专有的过程产物**」—— 各轮**改前备份**，随工作区一次性消费，无跨项目价值 |
| `.hob/CARRYOVER.md` | 「**本项目专有的过程产物**」—— 旧项目**可搬资产登记**，供本项目的后续批次决策；不是可复用的格式契约。现位于账本区 `archive/2026-10-10-ledger-root-housekeeping/`（见 §1.6） |
| `.hob/STEP*-REPORT.md` | 「**本轮进度**」—— 各步/各轮报告，内容本项目专有。现位于账本区 `archive/2026-10-10-ledger-root-housekeeping/`（见 §1.6） |

### 1.2 `drafts/` 为什么**进 git**（一次经复核的归类纠正）

`.hob/drafts/preset-contracts.md` 是**预设契约正文的人读版**（当前即 `Hob` 那份 —— ⚠ **份数不写死**），
也是 `scripts/check-preset-contracts.mjs`（**已入库**、挂在 `npm run check:presets`）
**无条件读取**的文件（该脚本里 `const DRAFT` 定义路径、`readFileSync(DRAFT, …)` 读取 —— ⚠ 引用用**符号锚**而非行号：行号会随脚本改动漂移，见 `EXPERIENCE.md` **E-91**）。

**决定性事实（实测）**：若把它排除，则**新 clone 跑不了已声明的命令** ——
```
$ git clone . /tmp/x && cd /tmp/x && node scripts/check-preset-contracts.mjs
Error: ENOENT: no such file or directory, open '.../.hob/drafts/preset-contracts.md'
EXIT=1
```
⇒ 一个**入库脚本**依赖一个**不入库文件**，是自相矛盾的状态。

**判定**：它满足「**被机检脚本消费的规范源**」⇒ **归骨架**。
它**不**满足本条原来的"可复用、可分发"措辞 —— 它是本项目专有的契约正文；
故「骨架」的判定标准写作"格式契约 **/** 被机检脚本消费的规范源"，
好让这条归类**有明文依据，而不是靠推断**。脚本头部注释亦称其为
"**用户过目、将来改动的地方**" ⇒ 是**源**，源必须进版本控制。

### 1.3 `roles/` 为什么**进 git**（角色簇）

`.hob/roles/` 存**角色簇与方法论**：`methods/` 下**随角色数增长的多份**
（各角色的领域方法论 + `quality-gates.md`；**份数以 `ls .hob/roles/methods/` 实测为准**）；人读契约在
`.hob/templates/ROLES.md`（角色）与 `.hob/templates/GATES.md`（门禁）。

**来源与许可**：改编自 [dsh-expert-mode](https://github.com/Asher-2000/dsh-expert-mode)
（**MIT**）的 `agent.cordis.yml` 内嵌 persona（17 段）与 `.expert-mode/methods/*.md`。
每份文件头部带来源注释。

**为什么归骨架**（对照上方标准）：

| 判据 | 事实 |
|---|---|
| **可复用、可分发** | ✅ 是**通用角色定义**（架构师/后端/QA/安全…），**不含本项目专有内容** |
| **被机检脚本消费** | ✅ 列入 `check:gitignore` 的 MUST-TRACK 清单，任一漂移即 FAIL |

⚠ **与 `drafts/`（§1.2）的判据区别**：`drafts/` 因"**被入库脚本读取**"才归骨架（本项目专有）；
`roles/` 是"**本身可分发**"（换项目直接复制可用）—— 两条判据**各自独立成立**。

⚠ **为什么不直接安装该插件**（两条取舍依据）：① **可移植性（UD-73③，用户原话）**：
外部插件**换环境就没有** ⇒ 它只能作**可选增强层**，且必须有**降级路径**；
而本层要的是**零外部依赖**的基础层。② **方法论已抽到手** ⇒ **不需要**它。
⚠ 另一条曾被引用的理由「撞本项目**硬边界**『不动 `~/.dsh/**`』」**不是用户决策**
（UD-76 已澄清：本项目**只管自己的账本**，不设跨项目/跨环境限制）⇒ **不作为依据**。

### 1.5 账本仓**也有自己的** `.gitignore`

⚠ **忽略规则有两处，不是一处** —— 本节记的是**上面那张表没覆盖**的那一处：

| 仓 | 规则文件 | 忽略什么 |
|---|---|---|
| **工作区仓**（本仓） | `.gitignore` | 见 §1 两栏清单（§1.4 机检逐条断言） |
| **账本仓**（`<账本区>/`） | **该仓根自己的 `.gitignore`** | **只忽略 `backups/`**（⚠ **规则条数以该仓 `.gitignore` 实测为准**） |

**依据**：§1 已把 `backups/` 归为**运行数据 · ❌ 不进 git**（理由：各轮**改前备份**、随工作区一次性消费、
无跨项目价值）。账本仓是同一批运行数据的新居所 ⇒ **同口径延续**（"半进库半不进"会
每轮 `git status` 都冒"N 删 + M 增"的噪音 —— 属 `EXPERIENCE.md` **E-108**（其正确做法③：*能机器核的不要靠人记*）那一类形态）。

⚠ **正本与 `archive/` 不进忽略** —— 它们是账本仓的**正本**，被排除就等于**静默消失**
（git 不报任何错，正是 **E-70 / E-73** 的失效模式）。
⚠ ⛔ **不许在该规则里写宽规则**（`*` / `**` 之类会**连带排掉正本与 `archive/`**）——
**已有机检盯住**：`npm run check:gitignore` 的**断言 C** 在账本仓里逐条实测
（正本 + `archive/` + `volumes/` 必须**都不被忽略**；反向再验 `backups/` **必须被忽略**）——
判据用 **git 自己的答案**（`git check-ignore --no-index`），**不解析 `.gitignore` 文本**。
⚠ 账本区读不到时该断言**明确打印"未执行"**，**不静默 PASS**。

### 1.6 账本区根目录**只放"当前状态"**

> **账本区根上只放"当前状态"** —— 正本（`PROJECT.md` + 各本账本）+ `volumes/`（卷：一事一文件）+ `archive/` · `backups/` · `runtime/`。
> **任何过程产物（批次报告 / 阶段记录 / 快照）一律进 `archive/<日期>-<名>/`**，不进根目录。

**依据（用户原话，逐字）**：

> 「整个账本目录所有账本文件都应该是最新的状态，其他遗留的东西都应该归档到archive历史文档」

**为什么需要明文**：账本区曾一次性收口过（根目录 19 个 `.md` → 4 个）——
那次要**人工清一遍**，正因为此前**没有这条明文**（同 **E-108 / E-109**「靠人记 ⇒ 必然漂移」的形态）。
⇒ 从现在起它是**明文口径**：新报告**直接落** `archive/<日期>-<名>/`，根目录只留正本。

搬走的 15 份（含曾误置在此的**经验库碎片 `EXPERIENCE.md`**）见
**本项目账本区**的 `archive/2026-10-10-ledger-root-housekeeping/`（⚠ **完整路径见 §3 归档表 · 本项目专属、开箱不带**），
该目录带自己的 `README.md`（说明为什么搬 + 各是什么）。

### `EXPERIENCE.md` 是什么（**本项目的特殊骨架**）

它**不是**账本之一，是**跨项目的经验库**：从旧项目账本里**提炼**出来的已实测踩坑，
按主题归类，每条含**现象 / 根因 / 正确做法 / 出处**。

- **进 git**：它是**格式+知识契约**，不含本项目专有内容，可复用。
- **维护**：新坑进本册，编号 `E-nn` 续编**不重排**；**不许丢「根因」**（只写现象等于没写）。
- **未验证项进 §7**，不许混进正文当已知。

### 1.7 `.hob/experience/` —— 经验库的**条目目录**（**已建立**）

> **现行形态**（**UD-95 / CHG-032**）：`EXPERIENCE.md` 是**索引**（小、每轮必读），
> **一条经验 = 一个文件**，落 `.hob/experience/<编号数字>.md` —— **写一次固定**，要改就新写一条取代。

⚠ **文件名口径**：`<编号数字>.md`，**不补零**（`E-01` → `1.md` · `E-133` → `133.md`）。
依据：`check:experience.mjs` 的判据正则就是 `^(\d+)\.md$`。

**机制（第 78 轮立 · 第 81 轮随目录建立启用）**：

| 脚本 | 扫描面 |
|---|---|
| `check:experience` | **索引 + 条目目录**（两处都查）：编号唯一 / 连续 + `E-84` 起四要素 + **索引两向完整**。⚠ 目录**存在时 ⑤ 真跑**；目录**缺席**才打印「未执行、不代表通过」（迁移期口径，现已不走这一支） |
| `exp:next-id` | 取号面含条目目录（文件名 `^(\d+)\.md$` **+** 正文宽正则 `E-(\d+)`，⛔ 两个都收 —— 窄正则会**取号偏小 ⇒ 撞号**，本仓已两次踩坑） |

⚠ **两向完整**（现强制）：索引点名的条目**必须真的有文件** · 目录里每份文件
**必须被索引点名**。
⚠ **新增一条经验 = 新增一个 `.hob/experience/<n>.md` + 在 `EXPERIENCE.md` 对应主题分节加一行**（两处同批）。

### 1.8 `.hob/INIT.md` —— **新工作区初始化清单**（**新增件**）

> **是什么**：一页纸、**照着做就能开张** —— 步骤序 · 账本区怎么定（`<ledgerHome>/<工作区名>/`）·
> 四份正本从哪来 · 卷怎么建 · 编号从哪取 · 哪些是模板哪些要自己填 · **开箱自检判据**。
> **归属**：**骨架**（**可复用、可分发** —— 它讲的是**规矩**，且**路径一律占位**）。
> ⚠ 它填的缺口：此前 `.hob/README.md` §4 只有一句原则性描述，**没有可执行的初始化清单**
> ⇒ 哪些目录要建、卷要不要建，**全靠开箱者猜**（第 127 轮开箱实测报出的**第 3 类残留**）。

⚠ **新增一个骨架顶层文件 = 三处同批**（⚠ 缺一处即出问题，**别只改一处**）：

| # | 改哪 | 缺了会怎样（**实测**） |
|---|---|---|
| ① | **文件落盘** | —— |
| ② | `.gitignore` 的 `!` 例外（`.hob/*` 会排除顶层新件） | 该文件**静默不入库**，git **不报任何错**（**E-70**） |
| ③ | **本脚本** `scripts/check-repo-rules.mjs` 的 `mustTrack` 加一行 | ⚠ 若**同时**在 §1 骨架栏点名了它，则 `check:gitignore` 当场 **FAIL**（第 128 轮实测 `✗ README §1 骨架栏提到 .hob/INIT.md，但本脚本的 MUST-TRACK 清单里没有它 ⇒ 机检与约定已漂移`，**EXIT=1**） |

⚠ **这三个位置是「骨架 ↔ 机检的对接面」**：②③ 都由 `scripts/check-repo-rules.mjs` 判，

### 5.1 纪律登记表（**每条纪律声明"谁来查"**）

> ⚠ **为什么有这张表**（2026-10-10 第 45 轮 · 结构改造③）：纪律写在文档里、**靠立规矩的人记得遵守**

> **没机器管的显式标 `未机器化`** —— 把"忘了查"变成"**登记不上**"。
>
> ⚠ **「机检归属」只有两种合法值**：
> ① `` `check:<name>` `` —— 且该 name **必须真实存在于 `package.json` 的 `scripts`**；
> ② **`未机器化`** —— 显式声明**目前没有机器管**（⚠ **这不是失败，是如实登记**）。
> ⇒ **机检盯的是"归属是否真实存在"**（`check:gitignore` 的**断言 F**）；
> ⛔ **不许为让表好看而把"未机器化"改成某个检查名** —— **那正是本条要防的**。
> ⚠ **本表不数条数**（计数会漂移，不当判据 —— **E-117**）。
>
> ⚠ ⚠ **两处实操摩擦（第 108 轮实测补登 —— 都是"看着对、机器不认"的形态）**：
> - **第 3 列须逐字为 `` `check:<name>` ``（含反引号）或裸 `未机器化`** ——
>   断言 F 的取法是 `` /^`check:([A-Za-z0-9:._-]+)`$/ ``，**只认反引号包裹的那一种**；
>   ⚠ **写成裸 `check:xxx` 会被判「不是合法值」当场 FAIL**（实测：`✗ F 第 467 行的「机检归属」不是合法值：\`check:archive\``），
>   而 `未机器化` 恰恰**要裸写**（带反引号反而落进上面的正则分支）。
>   ⇒ 一句话：**`check:` 那一支要反引号，`未机器化` 那一支不要**。
> - **卷索引行的路径须反引号包裹** —— 断言 L 只认**表格「文件」列里 `` `…*.md` `` 那种形态**；
>   ⚠ 裸写（如 `volumes/decisions/CHG-040.md`）**L 点不到名** ⇒ 该行**不被计入**"索引点名"，
>   于是同一份文件会被判「卷里有、索引没点」（**两侧读数都失真**，且**不报"写法不对"**）。
>   ⇒ 卷索引里的 `文件` 列**一律反引号包裹**。
