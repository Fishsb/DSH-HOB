# `.hob/` —— 工作区账本（骨架说明 + 归档索引）

> 本文件是 **骨架（进 git）**，不是运行数据。
> 它回答三件事：**这里的文件各自是什么 / 哪些进 git / 东西归档去了哪。**

---

## 1. 骨架 vs 运行数据

`.hob/` 的内容按**文件性质**二分：

| 类别 | 判定标准 | 进 git？ | 位置 |
|---|---|---|---|
| **骨架** | **格式契约 / 被机检脚本消费的规范源** —— 表头、列定义、编号规则、以及**入库脚本会读取的契约正文**。可复用、可分发；新建工作区时用它初始化 | ✅ **进** | `.hob/README.md`、`.hob/templates/`、`.hob/EXPERIENCE.md`、**`.hob/drafts/`**（见 §1.2）、**`.hob/roles/`**（见 §1.3） |
| **运行数据** | **填充进格式的具体条目 / 本项目专有的过程产物** —— 第 N 条事实 / 第 N 条决策 / 本轮进度 / 改前备份 | ❌ **不进** | 四个账本（`FACTS.md` / `DECISIONS.md` / `USER-DECISIONS.md` / `CONTEXT.md`）、`.hob/archive/`、`.hob/backups/`、`.hob/CARRYOVER.md`、`.hob/STEP*-REPORT.md` |

**一句话**：**格式进 git，内容不进。**

> **为什么这样切**：`.gitignore` **按路径匹配、读不到文件内容**，
> 所以「首行标记」在 git 上不可行；把运行数据下沉到子目录则要改目录结构定义。
> 本方案零迁移。（沿用旧项目 CHG-006 的论证。）

**⚠ 清单必须逐项列全，不许靠推断**（2026-10-05 修订，见 `EXPERIENCE.md` **E-70**）：
`.gitignore` 的 `!` 例外**少列一项** ⇒ 该文件**静默不入库**，git **不报任何错**。
⇒ 本表的「位置」栏就是 `.gitignore` 例外的**唯一权威清单**；
改一处必须同步另一处，并由 `npm run check:gitignore` 机检（见 §1.4）。

### 1.1 四类"运行数据"为什么进不了 git（逐类判定依据）

| 类 | 判定依据（对照上方「运行数据」标准） |
|---|---|
| 四个账本 | 「**第 N 条事实 / 第 N 条决策**」—— 逐轮追加，内容本项目专有 |
| `.hob/archive/` | 「**本项目专有的过程产物**」—— 历轮证据/归档；去向由 §3 的**指针表**留在骨架区 |
| `.hob/backups/` | 「**本项目专有的过程产物**」—— 各轮**改前备份**，随工作区一次性消费，无跨项目价值 |
| `.hob/CARRYOVER.md` | 「**本项目专有的过程产物**」—— 旧项目**可搬资产登记**，供本项目的后续批次决策；不是可复用的格式契约 |
| `.hob/STEP*-REPORT.md` | 「**本轮进度**」—— 各步/各轮报告（§五 格式的交付物），内容本项目专有 |

### 1.2 `drafts/` 为什么**进 git**（一次经复核的归纠正）

`.hob/drafts/preset-contracts.md` 是**两个预设契约正文的人读版**，
也是 `scripts/check-preset-contracts.mjs`（**已入库**、挂在 `npm run check:presets`）
**无条件读取**的文件（`scripts/check-preset-contracts.mjs:32` 定义路径、`:71` 读取）。

**决定性事实（实测）**：若把它排除，则**新 clone 跑不了已声明的命令** ——
```
$ git clone . /tmp/x && cd /tmp/x && node scripts/check-preset-contracts.mjs
Error: ENOENT: no such file or directory, open '.../.hob/drafts/preset-contracts.md'
EXIT=1
```
⇒ 一个**入库脚本**依赖一个**不入库文件**，是自相矛盾的状态。

**判定**：它满足「**被机检脚本消费的规范源**」⇒ **归骨架**。
（⚠ 诚实边界：它**不**满足本条原来的"可复用、可分发"措辞 —— 它是本项目专有的契约正文。
因此本轮把「骨架」的判定标准**扩写**为"格式契约 **/** 被机检脚本消费的规范源"，
正是为了让这条归类有明文依据，而不是靠推断。脚本头部注释亦称其为
"**用户过目、将来改动的地方**" ⇒ 是**源**，源必须进版本控制。）

### 1.3 `roles/` 为什么**进 git**（2026-10-08 新增 · 角色簇）

`.hob/roles/` 存**角色簇与方法论**：`methods/` 下 18 份
（17 位角色的领域方法论 + `quality-gates.md`）；人读契约在
`.hob/templates/ROLES.md`（角色）与 `.hob/templates/GATES.md`（门禁）。

**来源与许可**：改编自 [dsh-expert-mode](https://github.com/Asher-2000/dsh-expert-mode)
（**MIT**）的 `agent.cordis.yml` 内嵌 persona（17 段）与 `.expert-mode/methods/*.md`。
每份文件头部带来源注释。

**为什么归骨架**（对照上方标准）：

| 判据 | 事实 |
|---|---|
| **可复用、可分发** | ✅ 是**通用角色定义**（架构师/后端/QA/安全…），**不含本项目专有内容** |
| **被机检脚本消费** | ✅ 列入 `check:gitignore` 的 MUST-TRACK 清单，任一漂移即 FAIL |

⚠ **与 `drafts/`（§1.2）的判据区别**：`drafts/` 因"**被入库脚本读取**"才归骨架（本项目专有）；
`roles/` 是"**本身可分发**"（换项目直接复制可用）—— 两条判据**各自独立成立**。

⚠ **为什么不直接安装该插件**（归档理由，防后来者重复调研）：它挂了一个
86,952 字节的 `router-bootstrap-v34.mjs`，实测会 `import vm`（动态代码执行）
并**写 `$DSH_HOME` 下的文件**（`:613` / `:629`）、**改写 YAML**（`:1118` / `:1271`）
—— 撞本项目硬边界「**不动 `~/.dsh/**`**」。故**只取方法论层**，不装插件。

### 1.4 机检：`npm run check:gitignore`

`scripts/check-gitignore.mjs` 把「**排除漂移**」从**静默**变成**显式 FAIL**：
它按 §1 的两栏清单逐条断言 `git check-ignore` 的结果，**违反任一条 ⇒ exit 1**。
改 `.gitignore` 或改本表后**都应跑一次**。
（⚠ 它用 `git check-ignore`（**纯规则匹配**）做断言 ⇒ 能区分
"**被规则排除**"与"**不存在所以没出现**" —— 后者**不**算通过，见脚本内注释。）

### `EXPERIENCE.md` 是什么（**本项目的特殊骨架**）

它**不是**四个账本之一，是**跨项目的经验库**：从旧项目账本（1652 行 / 217 条事实 /
11 条 CHG / 8 条 UD）里**提炼**出来的已实测踩坑，按主题归类，每条含
**现象 / 根因 / 正确做法 / 出处**。

- **进 git**：它是**格式+知识契约**，不含本项目专有内容，可复用。
- **本轮的来源**：旧 `dsh-hob` 项目（已归档，见 §3）。
- **维护**：新坑进本册，编号 `E-nn` 续编**不重排**；**不许丢「根因」**（只写现象等于没写）。
- **未验证项进 §7**，不许混进正文当已知。

## 4. 模板怎么用

`templates/` 下 4 份是**空骨架**，只含格式，不含任何本项目内容：

1. **新建账本**：以模板为蓝本创建运行数据文件，替换 `[日期]` / `[谁]` 等占位。
2. **格式参照**：需要确认「某类条目该有哪些列」时，以模板为准。

**改账本结构时，必须同步改模板**（否则漂移）。

---

## 5. 相关纪律

- **防漂移**：每轮开工先读 `CONTEXT.md`（其 `§0` 是摘要，**最新的 `§N` 优先于更早的**）。
- **归档** = 移入 `.hob/archive/<日期>-<名>/` **并在 §3 表登记一行**。
- **经验库**：动手前先扫 `.hob/EXPERIENCE.md` 对应主题；出问题先查有没有现成根因。
- **诚实边界**：没验的写「未验证」，不许把「我认为」写成「已验证」。
