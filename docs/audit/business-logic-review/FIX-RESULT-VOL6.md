## §85 A 方案 **第 4 轮** · 「判不出」拆成**五种语义**（⛔ 没有合并）

### 85.1 为什么不能共用一个词条

`判不出` 在面板里出现 20+ 次，但**它们是五件不同的事**：

| 键 | 语义 | 处置方向 |
|---|---|---|
| `stages.undecidable` | 通用「判不出」（**保留**，第 1 轮就在） | — |
| `stages.unknownStage` | 阶段号**不在封闭集** | **数据**坏了（要修账本） |
| `stages.unknownExec` | 执行态**不在封闭集** | **数据**坏了（要修账本） |
| `stages.unknownTime` | 时长**读不出**（`ms` 非数字） | **读数缺失**（不是数据坏） |
| `stages.missingValue` | 字段**值缺失**（这条记录没写该字段） | **记录不全**（补字段） |

⚠ 合并成一个键的后果：**界面上这三件事读起来一样**，而用户需要做的事完全不同。
  那正是 `R-4`（「判不出」与「空」必须字面不同）要禁止的形态 ——
  只不过这次要分的是**「判不出」内部**的几种。

### 85.2 本轮迁了什么

| 位置 | 改用 |
|---|---|
| `stageLabelOf()` 的兜底 | `unknownStage` |
| `execStateLabel()` 的兜底 | `unknownExec` |
| 时长格式化（`ms` 非数字） | `unknownTime` |
| 事实值 / 原始标题 / `lastReading` 等 **7 处** | `missingValue` |

词条总数：18 → **23**（+5：三个 `unknown*` + `missingValue`；`undecidable` 原有）。

### 85.3 ⚠ 动词短语也要跟键走

时长那处的原文是：

```
return `${prefix}判不出`        // prefix = '已跑：' 或 '已跑（最长）：'
```

⇒ 改成 `${prefix}${stageText('stages.unknownTime')}` —— **前缀不动，只换判不出**。
  ⚠ 如果整句都走词条，`已跑（最长）：` 那个**口径区分**会被埋进词条里，
    而它是「⛔ 不许省略」的那一条（省了就是拿一个口径冒充另一个口径）。
    ⇒ 口径与措辞**分开管**：口径留在代码里，措辞进词条。

## §86 A 方案 **第 5 轮** · 先**量清耦合**，再迁对的那一批

### 86.1 本轮最重要的事：把「表格文案」的成本量准了

| 口径 | 数 |
|---|---|

| **非注释行里** | **930** |
| 去重后（非注释） | **634** |
| ⚠ **真正的「逐字期望」**（`t.includes('…')` / `/…/.test`） | **51** |

⚠ 930 → 51 这个落差是关键：**绝大多数中文字面量是测试夹具与错误消息**，
  真正与面板渲染文案耦合的只有 **51 个**。

⇒ 结论：**表格文案可以迁**，但必须逐条核这 51 个，⛔ 不能机械批量替换。
  本轮就先迁**不在那 51 个里**的长段落。

### 86.2 本轮迁了什么

| 词条 | 原文 | 锚定情况 |
|---|---|---|
| `stages.healthNoCount` | 「（本次响应未带缺口计数）」 | 无锚定 ✅ |

  英文界面下留中文 = 那一段指引**对非中文用户完全不可用**。
  ⇒ 收益最高、风险最低（没有断言逐字匹配它们）。

### 86.3 ⚠ 顺带发现一个**死常量**

⚠ 这与 O-17 是同一形态。而 **G-16 抓不到它** ——
  G-16 只扫 `export function`，这个文件里是 `export const`。
  （G-16 的这个盲区在 §74.5 已记过，本轮**第二次**撞上。）

⇒ 按 O-17 的同一标准删除（连同它的访问器 `stageExecNow` 与词条 `stages.exec.now`）。

⚠ 没有删除它**只是因为它出现在文末**——它和别的常量一样零引用。
