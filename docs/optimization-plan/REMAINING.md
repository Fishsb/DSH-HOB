### 2. 🟡 缺陷债：还剩 68 条（这是最大的一块）

**是什么**：112 条历史缺陷里，代码确实改过的有 106 条。但要证明「它再犯时有人拦得住」，
需要每条都指向一条**指名它的断言**（判据里必须能查到这个名字）。

**现在的数**：112 = **93 条已绑定** + **7 条未绑定** + 3 条已排除 + 2 条按设计 + 1 条未修。
- 38 条里「强」38 条（断言自带反向验证）、「弱」55 条（有断言，反向验证在别处）。
- 68 条的状态标的是 `已修-未机器化` —— ⚠ **这不是「没修」**，是「没人会在它复发时开火」。

**为什么慢**：这 68 条要么当时的修复没留下断言，要么断言存在但**没写缺陷编号**。
逐条处理需要：读那条缺陷讲什么 → 找到/补上一条能重判它的断言 → 把编号写进断言标签。
⚠ **不能自动填**：本仓 2026-11-11 试过自动填证据位置，101 条里 **12 条指错（12%）**，
那次教训的结论是「看起来完整、实际不可核，比留空更糟」。

**棘轮机制**：已绑定数**只准涨**、未绑定数**只准降**。上限写死在
`scripts/check-audit-status.mjs` 的 `MACHINE_GAP_MAX`（现在是 **7**）。
⇒ 谁想偷偷塞一条新债进去，会当场红。

**进度在哪看**：`node scripts/check-audit-status.mjs` 输出里那句
「**已修必须有指名断言**：N 行 …… 强 X · 弱 Y」。

**文件**：`docs/audit/business-logic-review/STATUS.md`（逐条状态）、

### 3. ⛔ 精确等待时长（gate_wait）—— 需要改账本格式

**是什么**：文章里最关键的一条度量是「一个 PR **等人等了多久**」。
本仓现在能算「两次决定之间的间隔」，**算不出**「从进入待批到被决定」的时长。

**为什么没做**：账本里**没有「进入待批」这个时刻字段**。要算它，必须在每次进入待批时
写一个新字段 —— 那会改动**所有既有写入方**（写入协议变更），风险远大于收益。

**已有替代**：批次 4 的 `human-time.ts` 能算「介入次数 + 间隔中位/P95」，
它回答问题的一半（人被打断几次），不回答另一半（每次等了多久）。

**要不要做**：需要你定。做的话是一次写入协议变更，我会：先加字段（可选）→ 只在新数据上写
→ 老数据标「判不出」→ 判据只对新数据生效。风险可控但要一次专门的处理。

**文件**：`src/shared/human-time.ts`（现有读数）、`src/shared/pipeline.ts`（写入协议字段表）。

### 4. ⛔ 误报率 / 无效意见率 —— 需要你配合标注

**是什么**：文章用「作者怎么回应每条意见」来量 reviewer 的噪声
（修了 / 说它错了 / 说这是故意的 / 不在乎）。本仓**没有任何这样的计数**。

**为什么没做**：它需要**人工标注入口** —— 每条判据报红之后，要有人记录「这条是对的还是误报」。
没有标注就没有分母，写出来的数字都是假的。

**最小可行版**：不建全量标注，只在两个族上试点（`check:gitignore` 的读上限实测超限、
`check:audit-status` 的旧账），把「人看过并判定为不修」的登记成 `waived`（带理由）。
`waived ÷ (waived + 真修)` 就是那一族的误报代理指标。

**需要你做什么**：试点阶段，每次判据报红但你认为「这条不用改」，告诉我一声，我登记。
攒够 20 条左右就有一个能看的数了。

**文件**：（尚未创建）`scripts/waiver-ledger.json` 之类。

## 五、⚠ 今早发现的一件事：宿主升级导致两条判据变红（已修）

**现象**：2026-11-17 下午第一次跑全量判据时，`check:hob-create` 与 `check:stages-dom` 两个族变红。

**排查**：我在**改动之前的那个提交**（`e7e3e05`）上单独跑这两族 —— **同样红**。
⇒ 与本次优化无关，是**宿主（dsh）今天 13:32 升级**造成的。

**根因**（两条都是「判据拿了一个已经不存在的锚」）：
1. `check:stages-dom` 的 S-33h 靠 `key: "sidebar.right.pane.tab"` 与 `key: "…​.title"` 之间切片取值；
   新版宿主把 `.title` 这类相邻键**整批删掉** ⇒ 两次查找都返回 -1 ⇒ 切片为空 ⇒ 恒判「未声明」。
2. `check:hob-create` 的 CU-12b 在「对话包」里找槽声明；
   新版宿主把槽的**声明**整批搬进了 `dsh-cordis-client-runner` 的契约汇总文件，
   对话包里只剩 `renderSlot` 调用 ⇒ 旧正则恒假 ⇒ 报「宿主行为已变」（**其实没变，是锚搬了地方**）。

**处置**：两条都改成「先按新写法找，找不到再回落旧写法」，**判据强度没变**
（仍然要求那一段里出现 `useProjection: UseProjection` / `kind: single`）。
改完 `check:all` 50/50 全绿。

**你需要注意的**：本项目对标的是宿主的**预发布通道**，上游相邻版本**可能删 API 且不给弃用窗口**
（README §4 已写明）。⇒ **以后每次升级 dsh，先跑一次 `npm run verify`**，
红了先怀疑上游改了挂载点，而不是先怀疑本项目。
