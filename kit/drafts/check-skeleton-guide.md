# 骨架 ↔ 实例结构漂移检查（`check:skeleton`）

> 入口：`npm run check:skeleton`
> 实现：`scripts/check-hob-skeleton.mjs`

## 1. 它比较什么

**实例根**由共享账本解析器给出：`ledgerHome` + `workspaceName`。
**模板根**默认是 `kit/templates/`。

脚本不手抄根文档名单。它从模板首个一级标题里寻找“本文件名”，据此发现
`CONTEXT.md`、`DECISIONS.md`、`REQUIREMENTS.md`、`USER-DECISIONS.md` 一类的根上文档；
实例侧只配对同名且实际存在的文件。

每对文档检查两件事：

1. **标题**：去掉 Markdown 强调符与多余空白后，两边逐字一致。
2. **同名节内表头**：模板表所在标题路径若在实例里仍有表，则该模板表头必须仍存在。

实例多出来的项目专有表不提。模板里有、实例里整节已经移入卷且不再有表的，
不纳入表头比较。

## 2. 自证与退出码

脚本每次正常执行都会先跑三组夹具：

- 同构夹具 + 实例专有表 + 可选节未实例化 ⇒ 必须 `exit 0`；
- 只改实例标题 ⇒ 必须 `exit 1` 且点名「标题漂移」；
- 同名节里只改一列表头 ⇒ 必须 `exit 1` 且点名「表头漂移」。

退出码：

- `0`：已执行且通过；
- `1`：发现结构漂移；
- `2`：模板根、实例根或可比文档缺失，属于未执行；
- `3`：检查器自身异常或自证失效，结论不可信。

## 3. 明确不覆盖

- 不比较正文、条目数、行内容、编号集合或项目专有表；那些是运行数据。
- 不要求实例拥有模板里的全部节。缺节可能是正文已经移入卷。
- 模板表所在节在实例里连一张表都没有时，该表头不参与比较。
  因此本检查不能证明“模板声明的所有结构都已被实例采用”，只能证明
  **两边都还在使用表的那一刻，列定义没有漂移**。
- 实例没有同名根文档时只报「未实例化」，不判红；新工作区可能尚未初始化该文档。
- 不证明装机链路真的读得到工作区骨架；那是另一条读取路径。

## 4. 夹具与诊断

```text
node scripts/check-hob-skeleton.mjs --verbose
node scripts/check-hob-skeleton.mjs --template-root <目录> --instance-root <目录>
```

`--no-selftest` 仅供脚本内部夹具子进程使用，不用于日常收尾。
