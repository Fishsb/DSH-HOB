# 审查简报 · 共享纯函数（`src/shared/`）

> 按 [`_TEMPLATE.md`](./_TEMPLATE.md) 的四节写。⚠ 只写四节，**不加节**。

## 一、失败长什么样

这个目录是**判定本体**：服务端、客户端、判据族三方都调它。
⇒ 它的失败不是「算错一个数」，而是**同一件事在两处得到不同结论**。四种可观察形态（都实测过）：

1. **强弱判据分叉**：`stageFieldProblems` 用弱判据、闸门用强判据 ⇒ 同一个任务在面板说「可以」、在闸门说「不行」。
   R-17 的病灶；现在的落点是 `src/shared/stage-controls.ts:1420` 的 `case 'tasks': return units.flatMap(taskFullProblems)`。
2. **返回 `undefined` 被调用方的 `?? 0` 吃掉**：`revisionOf` 只认字符串（`src/shared/pipeline.ts:178-183`），
   传数字静默返回 `undefined` ⇒ 回执正则要求「第 0 版」⇒ **永远匹配不到**。
   ⚠ 修法不是改 `revisionOf`，是让调用方显式接受 `string | number`（见同文件 `receiptPatternOf`）。
3. **解析失败被当空集**：`parseUnitsToml` 抛错处若写成 `catch { return [] }`，
   「账本坏了」就变成「账本少几条」⇒ 下游门禁集体失明（O-33 的病灶就在这个边界上）。
4. **纯函数不纯**：本目录若 import `node:fs`，浏览器侧打包会连带把它带进去 ——
   由 `check:client`（`scripts/check-client-deps.mjs`）兜底；⛔ 别指望 `tsc` 拦得住。

## 二、该跳过的路径

| 路径 | 为什么跳过 |
|---|---|
| 各类 `*SelfTest()` | 它是给判据族当夹具用的，本身不是业务判定；审它等于审测试 |
| 纯类型声明与常量字面量本身 | 要审的是「谁读它」，不是字面量写得对不对 |
| `god` 函数内部的早退分支 | 早退不构成缺陷；要审的是「早退之后调用方据此做了什么」 |

## 三、建议上限

**小问题 ≤ 3 条**，其余合并成一条「这一类还有 N 处」。

⚠ 特别地：本目录的同族问题往往**一次牵动 3–5 个函数**（一个语义、多处实现）。
逐条报会把一个问题拆成五条噪音 ⇒ **合并成一条并列出全部落点**。

## 四、证据要求

- 必须同时给**两侧**的位置：定义处 + 至少一个调用处（只给定义处证明不了分叉）。
- 说「两处结论不同」时，要给出**让它们不同的输入**（哪个字段名、缺哪个字段）。
- 说「纯函数不纯」时，给出 import 行。
