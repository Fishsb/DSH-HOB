## 2. 目录内容一览

```
kit/                          ← **本目录只放工具材料；账本数据在各工作区自己的 `.hob/`**
├── README.md            ← 本文件（骨架 · 进 git）
├── INIT.md              ← **新工作区初始化清单**（骨架 · 进 git，见 §1.8）
├── EXPERIENCE.md        ← 经验库**索引**（骨架 · 进 git · 提炼自旧项目）
├── experience/          ← 经验库**条目目录**（骨架 · 进 git，见 §1.7；一条一个 `<编号数字>.md`）
├── templates/           ← 空模板（骨架 · 进 git；份数以 `ls kit/templates/` 实测为准）
│   ├── REQUIREMENTS.md  ← **当前需求根地图**（现行）
│   ├── CONTEXT.md  ├── USER-DECISIONS.md（历史）└── DECISIONS.md
│   ├── ROLES.md         ← 角色簇人读契约（§1.3）
│   ├── GATES.md         ← 阶段与门禁人读契约（§1.3）
│   ├── TASK.md          ← 指令模板（v4 · 交接协议；**在途件落点**见其页头）
│   ├── LEDGER-RULES.md  ← **账本规则卷母本**（三条规矩；铺骨架时只到这里，⛔ 不自动进账本区）
│   └── REPORT.md        ← 回报模板（v4 · 交接协议）
├── drafts/              ← 契约正文人读版（**骨架 · 进 git**；被 check:presets 读取，见 §1.2）
│   └── preset-contracts.md（另有 restructure-plan.md / nav-intake-draft.md / 架构总览 / check-gitignore-guide.md = **§1.4 机检各节的正文**，**第 196 轮**整节搬来）
└── roles/               ← 角色簇方法论（骨架 · 进 git，见 §1.3；份数以 `ls kit/roles/methods/` 实测为准）

<工作区>/.hob/                        ← **账本数据**（⚠ 具体路径本项目专有，见 §3）
├── REQUIREMENTS.md · PROJECT.md · DECISIONS.md · CONTEXT.md   ← **根上正本 = 全部"当前状态"**
├── USER-DECISIONS.md    ← ⛔ **历史档（只读）**：**已退场、不在根上**（在 `archive/` 下逐字节可读），**不再是写面**
├── volumes/             ← **卷：条目正文一事一文件**（⚠ 一卷一份索引；**卷按需建**，成员以 `ls volumes/` 实测为准）
│   ├── decisions/       ← 方案变更记录（`CHG-<编号>.md`）+ `INDEX.md`（卷索引）
│   ├── requirements/    ← **当前功能需求**（`REQ-<编号>.md`）+ `INDEX.md`（卷索引）
│   ├── user-decisions/  ← **历史**用户决策记录（`UD-<编号>.md`）+ `INDEX.md`（卷索引）
│   ├── plan/            ← 方案正文按节（`PROJECT.md` 的正文）+ `INDEX.md`（卷索引）
│   └── context/         ← 状态页正文按节（`CONTEXT.md` 撞读上限时移出）+ `INDEX.md`（卷索引）
├── archive/             ← 交接归档 + 历史（含 2026-10-10-ledger-root-housekeeping/，见 §1.6）
├── backups/             ← 改前备份
└── runtime/             ← 运行态（如 orch-watches.json）
```

> 上表由 `npm run check:gitignore` 机检（§1.4）——
> 标「进 git」的在库内、标「不进 git」的被 `.gitignore` 排除，任一漂移即 FAIL。

### 账本区各文件管什么（职责分离，避免两处漂移）

> **`PROJECT.md`（项目方案）与账本同级、同在账本区**。
> **方案是唯一事实源（SSOT）—— 指「方案」这一档**，各本账本记的是**围绕它的变更 / 决策 / 上下文**。
> ⚠ **「唯一事实源 / 唯一来源」这个词在本骨架里只指两档**（⚠ **用到它时必须点明是哪一档**）：
> ① **方案** = `PROJECT.md`（唯一事实源）· ② **教训** = 经验库 `.hob/EXPERIENCE.md` + `.hob/experience/`（唯一来源）。
> ⛔ **别把"状态"（`CONTEXT.md`）也叫唯一来源** —— 状态是**只写当前状态**的一份账本，不是任何东西的唯一来源。

| 文件 | 职责 | 编号 |
|---|---|---|
| `REQUIREMENTS.md` | **当前功能需求（唯一现行需求根）** —— 用户现在要实现什么功能与可观察结果。⚠ 只写功能，⛔ 不写技术手段 | `REQ-nn` |
| `PROJECT.md` | **项目方案（唯一事实源 —— 指「方案」这一档）** —— 现状 + 纪律。⚠ **只有用户能批准变更，Hob 只提议**（程序纪律） | 章节号（`§N`） |
| `DECISIONS.md` | **方案变更记录** —— 「影响项目方案本身」的变更 | `CHG-nn` |
| `USER-DECISIONS.md` | ⛔ **历史用户决策（只读）** —— 用户当时拍板的记录；**不是现行需求**，写入工具拒写（`retired-historical`） | `UD-nn` |
| `CONTEXT.md` | **当前上下文** —— `§0` 防漂移摘要（一屏）+ **文档面现状表** + **还欠的活**（等用户 / 未修的缺口 / 未验证三张表）+ **关键约束速查** + **开工检查单** + **本批登记**；**只写当前状态**，历史与原始读数落 `archive/` | `§N` |

> ⚠ 上表描述的是**格式契约** —— 账本是运行数据，按模板创建与维护。
