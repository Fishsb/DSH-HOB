## 1. 骨架 vs 运行数据

`kit/` 的内容按**文件性质**二分：

| 类别 | 判定标准 | 进 git？ | 位置 |
|---|---|---|---|
| **骨架** | **格式契约 / 被机检脚本消费的规范源** —— 表头、列定义、编号规则、以及**入库脚本会读取的契约正文**。可复用、可分发；新建工作区时用它初始化 | ✅ **进** | `kit/README.md`、**`kit/INIT.md`**（初始化清单 —— 见 §1.8）、`kit/templates/`、**`kit/drafts/`**（见 §1.2）、**`kit/roles/`**（见 §1.3） |
> ⚠ **2026-10-25（UD-161）**：`.hob/EXPERIENCE.md` 与 `.hob/experience/` **不再列在本栏** ——
> 账本恢复**自带 git 仓**（`.hob/.git`），项目仓**整目录忽略 `.hob/`** ⇒ 它们由账本仓自己跟踪。见 §1.7。

| **运行数据 / 方案** | **填充进格式的具体条目 / 本项目专有的过程产物** —— 第 N 条事实 / 第 N 条决策 / 本轮进度 / 改前备份 / **项目方案** | ❌ **不进**（且**不在本目录**，见顶部说明） | `PROJECT.md`（已迁入账本区）· 各本账本 · `.hob/archive/`（**历史位置 —— 该目录现于账本区**，见 §1.6）· `.hob/backups/` · `.hob/CARRYOVER.md` · `.hob/STEP*-REPORT.md`（⚠ 后两件亦为**历史位置**，现于账本区） ⇒ 各本正本在 **`<工作区>/.hob/` 根目录**（⚠ **具体路径是本项目实例，见 §3 归档表**）；**过程产物（`CARRYOVER.md` / `STEP*-REPORT.md` / 经验库碎片等 15 份）在该区 `archive/2026-10-10-ledger-root-housekeeping/`**（见 §1.6） |

**一句话**：**格式进 git，内容不进** —— 且内容**不在本目录**。

> **为什么这样切**：`.gitignore` **按路径匹配、读不到文件内容**，
> 所以「首行标记」在 git 上不可行；把运行数据下沉到子目录则要改目录结构定义。
> 本方案零迁移。

**⚠ 清单必须逐项列全，不许靠推断**（见 `EXPERIENCE.md` **E-70**）：
`.gitignore` 的 `!` 例外**少列一项** ⇒ 该文件**静默不入库**，git **不报任何错**。
⇒ 本表的「位置」栏就是 `.gitignore` 例外的**唯一权威清单**；
改一处必须同步另一处，并由 `npm run check:gitignore` 机检（见 §1.4）。

|---|---|

| `.hob/archive/` | 「**本项目专有的过程产物**」—— 历轮证据/归档；⚠ **该目录名是历史位置**（现于账本区，见 §1.6）；去向由 §3 的**指针表**留在骨架区 |
| `.hob/backups/` | 「**本项目专有的过程产物**」—— 各轮**改前备份**，随工作区一次性消费，无跨项目价值 |

### 1.2 `drafts/` 为什么**进 git**（一次经复核的归类纠正）

`kit/drafts/preset-contracts.md` 是**预设契约正文的人读版**（当前即 `Hob` 那份 —— ⚠ **份数不写死**），
也是 `scripts/check-preset-contracts.mjs`（**已入库**、挂在 `npm run check:presets`）
**无条件读取**的文件（该脚本里 `const DRAFT` 定义路径、`readFileSync(DRAFT, …)` 读取 —— ⚠ 引用用**符号锚**而非行号：行号会随脚本改动漂移，见 `EXPERIENCE.md` **E-91**）。

**决定性事实（实测）**：若把它排除，则**新 clone 跑不了已声明的命令** ——
```
$ git clone . /tmp/x && cd /tmp/x && node scripts/check-preset-contracts.mjs
Error: ENOENT: no such file or directory, open '.../kit/drafts/preset-contracts.md'
EXIT=1
```
⇒ 一个**入库脚本**依赖一个**不入库文件**，是自相矛盾的状态。

**判定**：它满足「**被机检脚本消费的规范源**」⇒ **归骨架**。
它**不**满足本条原来的"可复用、可分发"措辞 —— 它是本项目专有的契约正文；
故「骨架」的判定标准写作"格式契约 **/** 被机检脚本消费的规范源"，
好让这条归类**有明文依据，而不是靠推断**。脚本头部注释亦称其为
"**用户过目、将来改动的地方**" ⇒ 是**源**，源必须进版本控制。

### 1.3 `roles/` 为什么**进 git**（角色簇）

`kit/roles/` 存**角色簇与方法论**：`methods/` 下**随角色数增长的多份**
（各角色的领域方法论 + `quality-gates.md`；**份数以 `ls kit/roles/methods/` 实测为准**）；人读契约在
`kit/templates/ROLES.md`（角色）与 `kit/templates/GATES.md`（门禁）。

**来源与许可**：改编自 [dsh-expert-mode](https://github.com/Asher-2000/dsh-expert-mode)
（**MIT**）的 `agent.cordis.yml` 内嵌 persona（17 段）与 `.expert-mode/methods/*.md`。
每份文件头部带来源注释。

**为什么归骨架**（对照上方标准）：

| 判据 | 事实 |
|---|---|
| **可复用、可分发** | ✅ 是**通用角色定义**（架构师/后端/QA/安全…），**不含本项目专有内容** |
| **被机检脚本消费** | ✅ 列入 `check:gitignore` 的 MUST-TRACK 清单，任一漂移即 FAIL |

⚠ **与 `drafts/`（§1.2）的判据区别**：`drafts/` 因"**被入库脚本读取**"才归骨架（本项目专有）；
`roles/` 是"**本身可分发**"（换项目直接复制可用）—— 两条判据**各自独立成立**。

⚠ **为什么不直接安装该插件**（两条取舍依据）：① **可移植性（UD-73③，用户原话）**：
外部插件**换环境就没有** ⇒ 它只能作**可选增强层**，且必须有**降级路径**；
而本层要的是**零外部依赖**的基础层。② **方法论已抽到手** ⇒ **不需要**它。
⚠ 另一条曾被引用的理由「撞本项目**硬边界**『不动 `~/.dsh/**`』」**不是用户决策**
（UD-76 已澄清：本项目**只管自己的账本**，不设跨项目/跨环境限制）⇒ **不作为依据**。

### 1.5 账本仓**也有自己的** `.gitignore`

⚠ **忽略规则有两处，不是一处** —— 本节记的是**上面那张表没覆盖**的那一处：

| 仓 | 规则文件 | 忽略什么 |
|---|---|---|
| **工作区仓**（本仓） | `.gitignore` | 见 §1 两栏清单（§1.4 机检逐条断言） |
| **账本仓**（`<账本区>/`） | **该仓根自己的 `.gitignore`** | **只忽略 `backups/`**（⚠ **规则条数以该仓 `.gitignore` 实测为准**） |

**依据**：§1 已把 `backups/` 归为**运行数据 · ❌ 不进 git**（理由：各轮**改前备份**、随工作区一次性消费、
无跨项目价值）。账本仓是同一批运行数据的新居所 ⇒ **同口径延续**（"半进库半不进"会
每轮 `git status` 都冒"N 删 + M 增"的噪音 —— 属 `EXPERIENCE.md` **E-108**（其正确做法③：*能机器核的不要靠人记*）那一类形态）。

⚠ **正本与 `archive/` 不进忽略** —— 它们是账本仓的**正本**，被排除就等于**静默消失**
（git 不报任何错，正是 **E-70 / E-73** 的失效模式）。
⚠ ⛔ **不许在该规则里写宽规则**（`*` / `**` 之类会**连带排掉正本与 `archive/`**）——
**已有机检盯住**：`npm run check:gitignore` 的**断言 C** 在账本仓里逐条实测
（正本 + `archive/` + `volumes/` 必须**都不被忽略**；反向再验 `backups/` **必须被忽略**）——
判据用 **git 自己的答案**（`git check-ignore --no-index`），**不解析 `.gitignore` 文本**。
⚠ 账本区读不到时该断言**明确打印"未执行"**，**不静默 PASS**。

### 1.6 账本区根目录**只放"当前状态"**

> **账本区根上只放"当前状态"** —— 正本（`PROJECT.md` + 各本账本）+ `volumes/`（卷：一事一文件）+ `archive/` · `backups/` · `runtime/`。
> **任何过程产物（批次报告 / 阶段记录 / 快照）一律进 `archive/<日期>-<名>/`**，不进根目录。

**依据（用户原话，逐字）**：

> 「整个账本目录所有账本文件都应该是最新的状态，其他遗留的东西都应该归档到archive历史文档」

**为什么需要明文**：账本区曾一次性收口过（根目录 19 个 `.md` → 4 个）——
那次要**人工清一遍**，正因为此前**没有这条明文**（同 **E-108 / E-109**「靠人记 ⇒ 必然漂移」的形态）。
⇒ 从现在起它是**明文口径**：新报告**直接落** `archive/<日期>-<名>/`，根目录只留正本。

搬走的 15 份（含曾误置在此的**经验库碎片 `EXPERIENCE.md`**）见
**本项目账本区**的 `archive/2026-10-10-ledger-root-housekeeping/`（⚠ **完整路径见 §3 归档表 · 本项目专属、开箱不带**），
该目录带自己的 `README.md`（说明为什么搬 + 各是什么）。

- **未验证项进 §7**，不许混进正文当已知。
