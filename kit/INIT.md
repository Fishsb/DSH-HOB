## 2. 第 1 步 · 账本区怎么定

**现行规则**：`<ledgerHome>/<workspaceName>/ledger/`

- `ledgerHome` 由预设行配置；本机实例为 `/home/lk/.dsh/hob-ledgers`。
- `<workspaceName>` 来自项目根 `dsh-hob.workspace.json`，缺失时才回落到目录名。
- ⚠ 路径判不出时 **fail-closed**，⛔ 不猜。
- ⚠ **不许用符号链接**（读侧也一律拒）。

**自检**：

```bash
ls -d "<ledgerHome>/<workspaceName>/ledger/"   # 存在
git -C "<ledgerHome>/<workspaceName>" status --short # 账本仓状态可读
```

### 2.1 ⚠ ⚠ **工作区名从哪来** —— 建工作区时**第 0 件事**（⛔ 别等它出问题才补）

**规则**：工作区名**从工作区根上一份被 git 跟踪的配置文件读**，⛔ 不从目录名猜。

| 项 | 值 |
|---|---|
| 文件名 | **`dsh-hob.workspace.json`**（放**工作区根**，⛔ 不放 `.hob/` 里） |
| 内容 | `{ "workspaceName": "<工作区名>" }` |
| 谁读它 | **判据脚本**（`scripts/workspace-name.mjs`）+ **运行时**（`src/server/doc-read.ts` 的 `resolveLedgerRoot`）—— ⚠ **同一份文件、同一个字段** |
| 不带它时 | **落回"猜工作区目录名"**（= 老行为，⛔ 不报错） |

**为什么必须建它（⚠ 不建不会报错，只会"悄悄没有隔离优势"）**：

- **隔离执行**（看板卡开独立 worktree）里，**目录名 = 卡 id**、不是工作区名。
  ⇒ 靠目录名猜出来的账本区是 `<ledgerHome>/<卡 id>`（兼容档）或 `<卡 id 那层的>/.hob` ⇒ ⚠ **两者都不是本工作区的账本**
  ⇒ 账本面整族报「未执行 / 失败」⇒ **隔离卡永远拿不到全绿**。
- ⚠ **更要紧的一半**：**运行时**也按同一个名字读写账本区。
  判据与运行时若各按各的猜 ⇒ **判据报绿、运行时却把账本区认到别处**（读写到一个本不该存在的位置）。
- ⛔ **不建它目前不会红** —— 这正是它需要写进本清单的原因（"记了一笔"不会让任何东西变红）。

**怎么建**：

```bash
printf '{\n  "workspaceName": "%s"\n}\n' "<工作区名>" > dsh-hob.workspace.json
git add dsh-hob.workspace.json      # ⚠ 必须入库：它随分支走，隔离副本才认得出工作区名
```

**三条口径**：

1. ⚠ **`workspaceName` 必须是单段目录名**（不许带 `/`、`\`，不许是 `.` 或 `..`）——
   否则**按"写坏"处理**并落回猜目录名（⚠ 2026-10-25 起账本落点**不由名字决定**，这条只影响 `fail-closed` 判定）。
2. ⚠ **真的换工作区名时，必须同批改它**（并与账本区目录名一致）。
   ⛔ 不同步 ⇒ 会按配置去找**旧名**（该红就红，这是有意的，⛔ 别放宽判据）。
3. ⚠ **两侧口径只有一套**：`scripts/workspace-name.mjs` 与 `src/server/doc-read.ts` 的
   文件名常量 / 字段名常量**必须逐字相同**（`src/` 与 `scripts/` 互不 import，只能照抄）
   ⇒ 由 **`npm run check:gitignore` 的 `S` 组**机检（⛔ 不许改成两套）。

# ⚠ 上面是**新工作区**的期望清单（模板面⛔ 不缩小 ⇒ `USER-DECISIONS.md` 照建）；

⚠ **`PROJECT.md` 从模板起手**：只写当前方案；正文过长时按节拆到 `volumes/plan/`，根上保留地图与当前约束。

⚠ ⚠ **两条"根"的分工（开箱就得对，⛔ 别等以后再说）**：
**`REQUIREMENTS.md` = 现行需求根（唯一写面）**；**`USER-DECISIONS.md` = 历史档（只读）**。
⚠ 写入工具对 `USER-DECISIONS.md` 会回 `retired-historical` 拒写 —— 那是**设计**，不是坏了。
⚠ ⚠ **实况**：该份**在本项目已整份退场**（在账本区 `archive/` 下，⛔ 不在根上）；
**新工作区仍按上表建它**（模板面⛔ 不缩小）—— 两件事，别混。

### 3.2 卷怎么建 —— **按需建，一卷一份索引**

**卷 = 条目正文的落点**（**一事一文件**）。四类卷（**用不用由项目定**）：

| 卷 | 装什么 | 文件名形如 |
|---|---|---|
| `volumes/decisions/` | 方案变更记录 | `CHG-<编号>.md` + `INDEX.md` |
| `volumes/user-decisions/` | 用户决策记录 | `UD-<编号>.md` + `INDEX.md` |
| `volumes/plan/` | **`PROJECT.md` 的正文按节** | `<nn>-<slug>.md` + `INDEX.md` |
| `volumes/context/` | **`CONTEXT.md` 撞读上限时**的移出件 | `<nn>-<slug>.md` + `INDEX.md` |

- ⚠ **每一卷必须有 `INDEX.md`**，且**两向完整**（索引点名的文件必须存在；卷内每份必须被点名）。
- ⚠ **空卷根 / 空卷 ⇒ FAIL**（"扫 0 份报 ✓"就是假绿）。
- ⚠ **卷按需建**：一开始可以一卷都不建；**用到哪一卷就建哪一卷**（⛔ 别预先堆空目录）。
- ⚠ `runtime/` 是**自忽略**的运行态；`backups/` 是**改前备份**（**不进 git**）。

#### 3.2.1 ⚠ ⚠ **编年体陷阱** —— 开账本时就要防（**2026-10-14 实测教训**）

⚠ ⚠ **本节是"项目跑起来之后"才最容易踩的坑**，而它**在开账本时看一眼就能防住**。

**陷阱长什么样**：把 `CONTEXT.md` 当**流水账**写 —— **每轮追加一个带时间戳的章节**
（"（2026-10-12 21:4x）…"、"第 N 轮…"）⇒ 它**按定义就会无限增长**。

> ⚠ **实测代价**（⚠ 另一项目真机读数）：⚠ `CONTEXT.md` 涨到 **261806**、`DECISIONS.md` **261018**（⚠ 上限 65536）
> ⇒ ⚠ **主持人只能读到 25%、"半盲"主持了整个项目**；⚠ ⚠ **而它自己登记过"需轮转"两次，⚠ 一直没执行** ——
> **⚠ 因为"记了一笔"不会让任何东西变红**。⚠ **完整读数与来历见 `.hob/drafts/discipline-details.md`**。

**⇒ 开账本 / 每轮收尾时的两条硬口径**：

| # | 口径 | 判据（可当场跑） |
|---|---|---|
| **1** | **`CONTEXT.md` 只写"现在是什么样"，⛔ 不写编年流水** | 出现 `## …（<日期> …）` 或 `第 N 轮` 这类**时间戳章节标题** ⇒ **该段属于历史，应进 `volumes/context/` 或 `archive/`** |
| **2** | **加内容之前先算一次**（含卷） | 对**每一份会被读到的文件**：`wc -c` **< 上限**（上限值**从预设行读**，⛔ 不硬编码）。⚠ **"以后再说"＝一定会忘**——实测就是这么涨到 4 倍上限的 |

⚠ ⚠ **轮转 ≠ 删除**：整份**先逐字节归档**（`archive/<日期>-<名>/`，**R-17：先落地旧版、再写引用**），
⚠ **再**按主题切进 `volumes/context/`，⚠ 并**同批产出「移出行 → 槽位」逐行对照表**（否则读者找不到搬去哪了）。
⚠ ⛔ **原文一字不改** —— 那是**记录类文本**（改它就是伪造历史）。

⚠ **为什么把这条写进"初始化清单"**：因为**它必须在开账本时就知道**，
⚠ 而**事后补救的代价是"整个项目期间的主持人都在半盲工作"**（实测如此）。

#### 3.2.2 ⚠ ⚠ **会增长的表 / 文档** —— 建立的那一刻就要写明「到顶怎么办」（**2026-10-15 实测教训**）

⚠ ⚠ **本节与 §3.2.1 是两节，⛔ 不是同一件事的两种说法**（⚠ 边界见本节末）。

**陷阱长什么样**：一张表 / 一份文档，**它的行数或字节数随"又发生了一次同类事件"而单调增加** ——
⚠ 例：**每轮一行** · **每立一条纪律一行** · **每次归档一行** · **每踩一个坑一行** · **每条决策一行** · **每个旧版一份**。
⚠ 这类东西**本身不是错**（账本就是要记账）；⚠ **错在"只进不出、且没有到顶动作"** ——
⚠ 它与 §3.2.1 那个坑的**共同末端**是同一个：**住在一份必须一次读完的文件里（上限 64KB）⇒ 增长必然撞上限**。

> ⚠ **实测代价**（⚠ 本项目真机读数）：⚠ ⚠ **同一缺陷类出过三次**（⚠ 滚出的行**无槽位**）——
> **前两次修法都是"补回去 + 写成规矩"，两次都复发**；⚠ 根因 = ⚠ **那表只进不出，却住在一份每轮整份重写、必须一次读完的文件里**
> ⇒ ⚠ **"裁掉几行"随时可用而无人拦得住**（⚠ 实测：骨架侧最紧的一份余量一度只剩 **167 字节**）。
> ⚠ **完整三段与来历见 `.hob/drafts/discipline-details.md`**。

**⇒ 建表 / 写文档时的三条硬口径**：

| # | 口径 | 判据（可当场跑） |
|---|---|---|
| **1** | **先判它会不会增长**（⚠ 口径：**行数 / 字节数随同类事件单调增加**） | ⚠ 会 ⇒ **本轮就必须写明"到顶怎么办"**，⛔ 不许留"以后再说"（⚠ **"以后"不会自己来**；⚠ 本条要防的正是它） |
| **2** | **到顶动作按表的性质选**（⚠ ⛔ **不许同一句抄 N 遍**） | 见下表 —— ⚠ **每一项都必须写"谁执行"** |
| **3** | **能派生就别手抄** | 内容与 `git log` / 既有文件重复的表 ⇒ **改成一条命令 + 口径式读数**（⚠ 手抄的必然过期） |

⚠ ⚠ **可选动作与适用形状**（⚠ 照搬本项目已跑通的那些，⛔ 不是空想）：

| 动作 | 什么形状适用 | 谁执行 |
|---|---|---|
| **另起一册**（⚠ **写明旧册在哪、指针在哪**） | 纯追加、条目彼此独立 | `未机器化`（⚠ 靠人读指针） |
| **一轮 / 一条一个文件**（⚠ **本轮已在本项目落地**） | 同上，且单条较长 | `check:rounds`（⚠ 有收尾对账钉住"只增不减"） |

| **分区**（按类别 / 按日期分文件） | 一张表混了多种类别 | `check:archive` |

⚠ ⚠ **"整块搬走"也是到顶动作之一**（⚠ 硬判据：⚠ **搬走的块逐字节一致**`cmp` 无输出 · ⚠ **留指针** · ⚠ **⛔ 不是裁行**）；

#### 3.2.3 ⚠ ⚠ **写入侧的"可写面"是登记式的 —— 新增一个两层目录时怎么办**（⚠ **`UD-115` 的核心，⛔ 别当特例读**）

> ⚠ **与 §3.2.2 的分工（⛔ 不重复它的内容）**：§3.2.2 管**内容**（表 / 文档行数会涨 ⇒ 写明到顶动作）；
> 本小节管**写入侧的可写面**（⚠ **什么样的路径能写进去**）—— 两者是**同一件事的两个面**：
> ⚠ 前者管"装不下怎么办"，后者管"**根本写不进去怎么办**"。

⚠ ⚠ **要记住的一句话**：**写入侧的白名单是「登记式」的，⛔ 不是「按形状放开」的** ——
⚠ 卷下**一层**（`volumes/<卷>/<文件>.md`）本来就放行；⚠ 而**卷下的第二层**（`volumes/<卷>/<子目录>/<文件>.md`）
**⛔ 默认写不进去**，⚠ 必须**在清单里登记**才放行。

⚠ **新增这类目录时，动作是什么**：

| 步 | 做什么 |
|---|---|
| **1** | ⚠ **把它的相对路径**（⚠ 形状 = `<卷>/<子目录>`，例：`context/rounds`）**加进写入侧的登记清单**（**一行**，⛔ 不改任何正则） |
| **2** | ⚠ **谁强制你登记**：⚠ **有断言会扫账本区里实际存在的 `volumes/<卷>/<子目录>/`** ⇒ ⚠ **凡不在清单里的，当场 FAIL 并点名那条路径** |
| **3** | ⚠ **未登记的写会被拒**，⚠ **且拒绝消息里就写着"该怎么登记"**（⚠ 照本小节这段的指引） |

⚠ ⚠ **为什么必须"登记"而⛔ 不能"放开成 `volumes/**`"**：⚠ 那会把任意深度一并放进来 ⇒ ⚠ **边界白设**（⚠ 本清单是**窄**的那一档）。

⚠ ⚠ **「只把某一个目录写成特例、下次再裂一次」已被机械堵住**（⚠ `UD-115` 的核心）：
⚠ **第 2 步那个断言**会在**下一次新两层目录出现时当场 FAIL** ⇒ ⚠ **⛔ 不是靠"记得"，靠的是收尾会红**。

⚠ **命名规则**（⚠ 与卷 slug 同档）：⚠ 子目录的**每一层**都只允许**小写字母 / 数字 / 连字符**。

### 3.4 ⚠ 派实施活之前 · 先核目标会话的**预设列**

> **一句话**：**"在跑" ≠ "在干活"** —— 派实施活之前，先看目标会话的**预设**是谁。

| 要做的事 | 怎么做 |
|---|---|
| **看目标预设** | 派活工具列会话时**会给出预设列**（如 `预设=Hob` / `预设=standard`）—— **先看它，再派** |
| **判"能不能施工"** | ⚠ **规划侧/主持预设不能施工**：它只规划、没有 shell、白名单不含写文件工具 ⇒ 派实施活给它 = **永远没有产出** |
| **看编排状态** | 「在等回传」每行**显示目标预设**；若标了**规划侧预设·不能施工** ⇒ **别等**，换一个能施工的会话重派 |
| **建新席时** | 建会话时**显式点名实施预设**（如 `standard`）—— ⛔ 别指望"不填就走实施侧"：不填走的是**配置/出厂默认** |

⚠ **症状极具欺骗性**：编排状态显示「**已开跑**」、会话列表显示 `running`，
**但永远没有产出** —— 因为那个会话按**自己的规矩**（先规划、不动手）干活，**没违规、只是不施工**。
⇒ **判据**：**只看"在不在跑"会漏掉它**，必须看**预设列**。

⚠ **派活工具已自带预警**（第 129 轮起）：给一个**规划侧预设**的会话发消息时，
返回值里会带 `presetNotice`，说明**后果**（不能施工 / 看在跑永远没产出）与**下一步**（换会话 / 显式点名）。
⇒ **读到 `presetNotice` 就照它说的做**，⛔ 不要继续等那一轮的产出。
⚠ 它**只提示、不拦**（给规划侧会话发消息本身可能是合法的，比如问它状态）。
